まとめ

先週号で通奏低音だった「予告つきセキュリティの定例運用」が、今週は現実の大規模インシデントに変わった。8 月 4 日、Shai-Hulud 系のワームが keyv とその周辺 400 以上のパッケージを汚染し、しかもnpm の trusted publishing（GitHub Actions の OIDC 発行）を悪用して正規の provenance 付きで配布された点が転換点になった。これを受け GitHub/npm は「サプライチェーン攻撃の遮断」を掲げ、staged publishing・install script の既定無効化（npm v12）・Dependabot のクールダウンなど一連の防御を前面に出した。もう一つの主役、先週 preview だった Next.js 16.3 が 8 月 3 日に GA。Instant Navigations が stable 化し、dev メモリ最大 90% 減・next build の TypeScript 7 型チェック・SSR スループット +22% と、16.0 以来最大の更新になった。エコシステム側でも TanStack Table V9 が 2 年越しで正式化し、ライブラリ群も一斉に版を上げた。「安全運用が予告どおり届く」という先週の確定が、今週は攻撃の実害と、それに対する制度的な締め直しという形で一段深く現れた週だった。

今週の重要ポイント

npm/GitHub Actions のサプライチェーン攻撃が trusted publishing を突破 — keyv 系 400+ 汚染、GitHub は防御を制度化

先週号は Node.js の協調セキュリティリリースを「予告つき・まとめて着地」の runtime 版として据えたが、今週はそのセキュリティ潮流が攻撃側の実害として噴出した。8 月 4 日、Shai-Hulud 系のワームが週次ダウンロード約 1.27 億の keyv と関連パッケージを侵害し、数時間で 400 以上・月間 20 億インストール規模へ拡散した。最大の論点は手口で、攻撃者は維持者の GitHub アカウントを乗っ取って main へ直接 push し即座に新版を切ることで、npm の trusted publishing（長期トークンではなく GitHub Actions の OIDC で発行する経路）を通し、正規の provenance が付いたまま汚染版を配布した。CI/CD を信頼の起点に据えた仕組みそのものが逆用された格好だ。

GitHub/npm は「Disrupting supply chain attacks on npm and GitHub Actions」で、4〜7 月にかけて積み上げてきた防御を一気に前面化した。要は公開前に承認と 2FA を挟む staged publishing、高影響アカウントのメール変更・2FA リカバリ時の 72 時間読み取り専用化、actions/checkout が fork PR の untrusted コードを既定でブロック、そして npm v12 で install script と git/remote URL 依存を既定無効化、Dependabot に既定 3 日のクールダウン（セキュリティ修正は除外）を入れて、汚染版が検知前に伝播する速度を落とす。先週の「安全運用が予告どおり届く」という受け身の確定が、今週は信頼の前提（provenance/OIDC）が破られ得るという現実と、それを織り込んだ制度設計へと更新された。

Next.js 16.3 が GA — preview だった Instant Navigations が stable 化、dev メモリ90%減・TS7 型チェック・SSR +22%

先週 preview として取り上げた 16.3 が、8 月 3 日（月）に正式リリースされた。目玉の Instant Navigations（cacheComponents と partialPrefetching の 2 フラグで opt-in）が stable に到達し、ルート単位のローディングシェルを prefetch して SPA 並みの即時遷移を server-driven のまま実現する。検証系も揃い、遅い遷移を自動で洗い出す Instant Insights、シェルを一時停止して確認する Navigation Inspector、Playwright の instant() ヘルパが同梱される。これらの挙動は将来のメジャーで既定化される予定だ。

全アプリに効く改善も広い。Turbopack のディスクキャッシュとメモリ eviction を既定化して dev のメモリを最大 90% 削減（vercel.com で 21.5GB→2GB）、next build でも FS キャッシュが効いて CI で最大 5.5 倍速のケースを報告。next build の型チェックに先月出た TypeScript 7 を使えるようになり（typescript@^7 を入れるだけ）、App Router の描画層を web streams から ネイティブ Node.js streams へ置換して負荷時スループット +22%。実験扱いでは Turbopack 内で走る Rust 版 React Compiler（cold 34%・warm 46% 短縮）と、切断時に処理を保留して再接続で再試行する experimental.useOffline も入った。先週「preview で成熟中」と書いた機能群が、そのまま安定版として着地した。

TanStack Table V9 が正式版 — 2 年越しで tree-shakable 化、TanStack Store で状態管理を刷新

ライブラリの大玉も同じ 8 月 4 日に着地した。2 年以上の開発を経て TanStack Table V9 が GA。内部を tree-shakable なプラグイン（feature）アーキテクチャに組み替え、状態管理を TanStack Store ベースへ載せ替えた。row/column/cell/header の API を共有プロトタイプに移したことで、大規模テーブルで V8 よりメモリ使用量を大幅に削減し、細粒度リアクティビティと React Compiler 互換で不要な再描画を抑える。6 月のベータから積み上げてきた設計変更が固まった形で、フレームワーク別の adapter と移行ガイドが用意される。

状態管理は「atoms（TanStack Store）か controlled か」を選べる設計で、既存の controlled パターンを保ちつつ、必要なら Store の細粒度購読へ移れる。破壊的変更を含むメジャーのため、V8 からの移行はフレームワーク別ガイドの参照が前提になるが、下回りが Rust/ネイティブへ寄る一方で JS ライブラリ側は「共有プロトタイプ＋ストア」でメモリと再描画を締める、という今週の別の潮流を象徴する更新だ。

フレームワーク・ランタイム

Vue 3.6 は今週も RC のまま — 秋の GA 待ち、SolidStart 2.0 と Node 24.19 が周辺を固める

先週「RC のまま GA 待ち」とした Vue 3.6 は今週も動かず、7 月 22 日の rc.2 から先へは進んでいない。Vapor Mode は feature-complete だが RC 段階では unstable 扱いのままで、テンプレート型チェック（Volar 系）の TS7 対応が 7.1 待ちである構図も不変だ。一方で他の full-stack 系は版を上げた。SolidStart 2.0 が Solid v1 を土台に基盤を刷新し、Solid 系のフルスタック開発の足場を整えた。ランタイムでは Node 24.19 が stream.compose を安定化し、TLS/TCP 設定や fs.readFile() のカスタムバッファ、--experimental-import-text フラグを追加。先週の協調セキュリティリリース（26.5.1／24.18.1／22.23.2）に続く 24 系の通常更新で、runtime 側は「セキュリティは協調・機能は各系列で漸進」というリズムを保っている。

ビルド・サーバ層も更新 — Vite 8.2、Hono 4.13、Svelte 8 月号は SvelteKit 3 プレビューを継続

下回りのツールも足並みをそろえた。Vite 8.2 はトップレベルの input オプション、未対応ネイティブローダの警告、PostCSS 設定の型を追加。サーバ側では Hono 4.13 が最大 1.25 倍の性能向上に加え HTTP QUERY メソッド対応と 405（Method Not Allowed）ミドルウェアを載せた。先週 @next 入りを報じた SvelteKit 3 は、Svelte の 8 月号でプレビューが継続。zero-config なエラー props と refreshAll、新しい $app/* モジュールが積まれ、vite-plugin-svelte@7.2.0 や言語サーバの最適化、Svelte Inspector のコンテキストメニュー追加も入った。「速い基盤を stable の一歩手前まで詰める」動きが、Vite・Hono・SvelteKit の各層で並行して進んでいる。

エコシステム・ライブラリ

UI・状態管理ライブラリが一斉更新 — React Aria 1.20、Base UI 1.7、MobX 7.0、SWR 2.5

Next.js 16.3 GA に合わせるように、周辺ライブラリも版を上げた。React Aria 1.20 は PreviewTrigger（プレビュー付きポップオーバー）、インラインタグの TokenField、ネイティブのコンテキストメニュー、操作可能なテーブル行、そして Next.js 16 の RSC collection 対応を追加。Base UI 1.7 はバンドルを約 3% 削減しつつモバイル UX と ScrollArea.Thumb のオーバースクロール挙動を改善した。状態管理では MobX 7.0 がレガシー互換を切って ESM バンドルを縮小（mobx-react-lite／mobx-react の分離は維持）、SWR 2.5 が実験的な RSC データ preload とキャッシュ破棄・クエリ中断のための unload() API を入れた。React Hook Form 7.84（<Form /> の submit 改善）、React Three Fiber 9.7（reconciler を react-dom に整合）、Styled Components 6.5（型チェック高速化）も更新され、先週の shadcn の React Aria 一級サポートに続いてアクセシビリティ基盤の選択肢がさらに広がった。

  • This Week In React #293（React Aria 1.20 / Base UI 1.7 / MobX 7.0 / SWR 2.5 / RHF 7.84 / R3F 9.7）— thisweekinreact.com

AI エージェント向けの土台づくりが前進 — WebMCP、React の browser() API、GitHub の Stacked PRs

先週の ReactBench（エージェントの実装力を採点）に続き、今週は「AI にどう web を触らせるか」の基盤が具体化した。Chrome チームの WebMCP は、クライアント側のツールをブラウザ内 AI エージェントへ公開する実験的な React 抽象で、ページが自らエージェントに操作 API を差し出す方向を示す。React 本体側では、SSR を一時停止してブラウザ専用コンポーネントを扱う client-only な browser() API の PR が動いた。開発フローでも GitHub の Stacked PRs が public preview に入り、base の自動付け替え・部分マージ・gh-stack CLI 連携で、依存し合う PR を積み上げる運用がネイティブ対応になる。フレームワークやライブラリの更新と並んで、エージェントと協働する前提の道具立てが一段前に出た週でもあった。

来週の注目ポイント

サプライチェーン防御の実効性 — staged publishing の普及と、次の Shai-Hulud 波が来るか

今週の最大の宿題は攻撃側と防御側の追いかけっこだ。GitHub/npm が前面化した staged publishing・install script 既定無効化（npm v12）・Dependabot クールダウンが、trusted publishing/OIDC を逆用する手口をどこまで実際に鈍らせるかが焦点になる。維持者の opt-in がどの程度進むか、そしてkeyv 系に続く新たな汚染波が観測されるかを継続ウォッチしたい。先週 runtime へ広がった「予告つきセキュリティ」が、今週はエコシステムの制度設計そのものへ及んだ以上、来週はその運用が試される段になる。

  • Disrupting supply chain attacks on npm and GitHub Actions — The GitHub Blog

Vue 3.6 の GA と SvelteKit 3 プレビューの安定化 — 秋に束ねられた解禁の前段

SFC 系スタックの秋待ちは今週も続いた。Vue 3.6 が rc から stable（GA）へいつ進み、feature-complete でも unstable と位置づけられた Vapor Mode が本番推奨へ格上げされる条件が最初の焦点。あわせて SvelteKit 3 プレビューが設定統合・環境変数・shallow routing 統合をどこまで詰めるかも、次メジャー移行を占う材料になる。両者の型チェック解禁が TypeScript 7.1（10 月ごろ想定）のプログラマティック API に束ねられている構図は変わらず、この API の preview 更新が出れば全面移行計画が描ける。
