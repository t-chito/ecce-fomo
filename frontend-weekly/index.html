まとめ

先週号は「RC の波の 3 番目の卒業生は SvelteKit 3 か Vue 3.6 か」を宿題に残した。今週その 2 つはどちらも RC のまま足踏みし、代わりに波の外から本命が抜けた——React 19.3 が 9 月 9 日に GAし、約 1 年半 experimental だった View Transitions と Fragment Refs をついに stable にした。マイナー番号ながら「長く実験段階だった目玉をまとめて卒業させる」性格の号で、今週いちばん大きな出荷だ。もう一つの軸は出荷そのものの速度。Chrome が 9 月 8 日の Chrome 153 から2 週間リリースへ短縮し、プラットフォーム側の更新列車がギアを上げた。今週は「何が stable に上がるか」と「どれだけ速く回るか」——卒業と cadence の 2 語で読める。

今週の重要ポイント

React 19.3 が GA — 波の次の卒業生は「見張っていた列」の外から出た

先週「次の GA は SvelteKit 3 か Vue 3.6 か」と見立てたが、今週抜けたのはそのどちらでもなく React だった。React 19.3 が 9 月 9 日に stable リリースされ、目玉は 2 つ。2025 年 4 月から約 1 年半 experimental だった View Transitions（<ViewTransition> で enter / exit / update / share を宣言的にアニメーションさせる）と、<Fragment> に ref を付けて余計な div なしに複数子要素へ振る舞いを束ねる Fragment Refs が、そろって stable に上がった。マイナー番号だが「実験を長く続けた API をまとめて卒業させる」意味では、先週の pnpm 12・Vitest 5 に連なる波の一部として読める。破壊的変更は無く、全て追加的な更新だ。

Chrome が 2 週間リリースへ — 出荷の cadence がプラットフォーム側で上がった

フレームワークの GA を追う裏で、土台の Chrome が更新頻度そのものを変えた。9 月 8 日の Chrome 153 stable を皮切りに、beta / stable が従来の約 4 週間から 2 週間ごとへ短縮される（Desktop / Android / iOS 共通）。各バージョンの beta は stable の 3 週間前に出るので検証窓は確保され、Dev / Canary は変更なし、企業向け Extended Stable も 8 週間のまま据え置きだ。小さく頻繁に配ることで、むしろリリース後のデバッグが切り分けやすくなるという狙い。フロント側の含意は明確で、「Chrome N でしか出ない挙動」を追う周期が半分になり、beta 追従の重要度が一段上がる。

見張っていた 2 つは足踏み — SvelteKit 3・Vue 3.6 は今週も RC

先週「次の卒業生」に挙げた SvelteKit 3 と Vue 3.6 は、今週もそろって RC 段階にとどまった。SvelteKit 3 RC は 3.0.0-next.25 まで刻み、+server.js の QUERY メソッドハンドラ、成功／失敗時にアクションページへ遷移する改良版 form actions、serverless 向け applyReroute ヘルパなどを積んだが stable は未着。Vue 3.6 も alien-signals ベースのリアクティビティ刷新と Vapor Mode を feature-complete としつつ「秋 GA」の予告のまま据え置きだ。波は「一斉」ではなく1 つずつ、しかも見立てと違う順で割れていく——今週それを卒業させたのは React だった。

フレームワーク・ランタイム

React 19.3 の中身 — View Transitions は「Transition のときだけ」動く設計

View Transitions は常時アニメーションではないのが要点だ。動くのは startTransition / Suspense の reveal / useDeferredValue といった Transition 経由の更新に限られ、緊急更新は即座に反映してアニメーションを飛ばす。既定はクロスフェードで、CSS クラスや Web Animations API から差し替えられる。19.3 では遷移の「原因」で見せ方を変える addTransitionType も追加され、カルーセルの「次／前」で方向を出し分けるといった制御が宣言的に書ける。さらに react-dom の browser() が、SSR で特定コンポーネントだけ Suspense を使ってサーバー描画から外し、localStorage やタイムゾーンなどブラウザ専用 API を安全に使えるようにした。挙動面ではTransition が互いに独立して描画されるようになり、遅い遷移が無関係な遷移を止めなくなった。Trusted Types 対応や、Server Component から Provider ラッパー無しで context を描ける改善も入っている。

Svelte エコシステム

Svelte 5.57 と TanStack Table v9 — RC を待つ間も足回りは進む

SvelteKit 3 が RC で足踏みする一方、周辺は着実に動いた。Svelte 5.57.0 は SvelteMap に「読むか無ければ初期化する」パターン用の getOrInsert / getOrInsertComputed を追加し、createContext が存在確認用の has を返すようになり、<select> が defaultValue をサポートした。ツールチェーン側は先週触れた sv の mcp → ai-tools 置き換えに加え、task ベースの sv migrate に sveltekit-3 移行タスクが入り、新規プロジェクトは $lib ではなく Node の subpath imports を使う #lib が既定になった。エコシステムでは TanStack Table v9 が初の Svelte ネイティブアダプタを同梱し、runes に直接つながる形になった。RC 待ちの停滞感の裏で、5.x マイナーと周辺ライブラリが「3 系が来る前提」の地ならしを進めている。

ブラウザ・プラットフォーム

「宣言的 API」路線 — HTML-in-Canvas と Declarative Partial Updates

2 週間 cadence への移行と並んで、Chrome が押している方向は「重い処理を宣言的 API に肩代わりさせる」だ。HTML-in-Canvas は実 DOM 要素を WebGL / WebGPU の canvas に直接埋め込み、3D 表現の中身を検索・アクセシブル・翻訳可能・ブラウザ機能と噛み合う形で保てるようにする。Declarative Partial Updates は部分更新の定型を宣言的に扱わせ、複雑なレンダリングや性能チューニングを手続き的に書かずに済ませる狙い。cadence が速くなるほど、こうした「命令的コードを宣言に寄せる」プリミティブが早く手元に届くことになり、beta で挙動を先に確かめる価値も上がる。

来週の注目ポイント

Vue 3.6 の「秋 GA」は 9 月後半〜10 月が本番

今週 React が波を 1 つ卒業させたことで、視線は再び Vue 3.6 に戻る。「秋 GA」の予告が生きており、9 月後半から 10 月にかけてがいよいよ本番の窓だ。alien-signals ベースのリアクティビティ刷新と Vapor Mode がそのまま stable に載るのか、あるいは SvelteKit 3 が先に抜けるのか。「見立てと違う順で 1 つずつ割れる」という今週のパターンが続くのかどうかを来週も見ていきたい。

View Transitions の stable 化が各フレームワークにどう波及するか

React 19.3 で View Transitions と Fragment Refs が stable になったことで、次の焦点はフレームワーク側の取り込みだ。Next.js などが <ViewTransition> を前提にしたルーティング演出をどれだけ標準化するか、ルーター遷移との統合や addTransitionType の実運用パターンが早期に出てくるかを追う。あわせて Chrome の 2 週間 cadence が実際にどのくらい「機能が早く手元に来る」体感につながるか、最初の数サイクルの出方も見どころになる。
