まとめ

先週号は「一斉 RC の波」と「Next.js の予告つきセキュリティリリース」の 2 つを来週の宿題として残したが、今週はその両方が予告どおり着地した。Next.js は 8 月 25 日——予告した 26 日から 1 日前倒しで——critical 2 件の RCE を塞ぐ 16.3.3 / 15.5.24 を公開した。そして RC の波からは最初の GA が出た。pnpm 12.0 が 8 月 26 日に stable 化し、Rust 全面書き換えを正式版として送り出した。一方で Vitest 5・Vue 3.6・SvelteKit 3 はまだ RC のまま——波はまだ本格的には割れていない。低音では、フロントエンドを AI エージェントが作り変えるという Nolan Lawson の「隕石」論が広く読まれ、「DX より agent experience」という論調が水面下で広がった。予告の週の次は、予告が現実になる週だった。

今週の重要ポイント

Next.js 8/25 セキュリティリリースが着地 — critical RCE 2 件、予告から 1 日前倒し

先週号で「来週の注目」に挙げた Next.js のセキュリティリリースが、今週そのまま現実になった。当初は 8 月 26 日の予定だったが、上流依存にもう 1 件の critical 脆弱性が見つかったため 8 月 25 日へ前倒しされ、16.3.3（Active LTS）と 15.5.24（Maintenance LTS）が公開された。塞がれたのはいずれも unauthenticated RCE の critical 2 件だ。

1 つは AVIF 画像最適化の RCEで、sharp が使う libheif の脆弱性に起因する。攻撃者が用意した AVIF 画像を Next.js が最適化するだけで任意コード実行に至るため、パッチ版は上流の修正が行き渡るまで AVIF 最適化を無効化する対処を取った。もう 1 つは Windows ホスト限定の RCE（CVE-2026-75604）で、Pages Router と App Router を併用し Cache Components を使わない構成が対象。Windows ファイルシステム上で稼働する場合に成立し、既知の回避策は無い（Linux / macOS は非該当）。先週「予告つき運用が定着した」と書いた運びは、日付を 1 日縮めつつも約束どおりパッチとして届いた。該当構成のチームは即時アップグレードが必要だ。

pnpm 12.0 が GA — RC の波、最初の stable は Rust 書き換え版

先週「RC 入り」を報じた次期メジャー群のうち、最初に stable へ抜けたのは pnpm だった。pnpm 12.0 が 8 月 26 日に GAし、install エンジンの Rust 全面書き換えを正式版として送り出した。コマンド・フラグ・設定・lockfile 形式は pnpm 11 からそのまま持ち越され、既存の lockfile も --frozen-lockfile で動く。cycle の多いワークスペースでpeer 解決が 2〜3 倍速く、メモリは約 25% 減、lockfile も小さくなる。Linux では hardlink 優先で btrfs 上の materialization がほぼ半減する。

互換を保ちつつも破壊的変更は 4 点に絞られた。git 依存は SSH ではなく正規の HTTPS URL 経由で解決、pnpm-workspace.yaml の未知の設定は提案つきエラーになる、循環依存は peer 解決時に正規化され並び替えても byte-identical な lockfileを生む、engineStrict はサブツリー全体ではなく依存エッジを辿る。まだ latest は pnpm 11 を指し、導入は next-12 タグから——だが「速い基盤を stable 一歩手前まで詰める」動きは、今週ついに GA という結果を 1 つ出した。

波はまだ割れていない — Vitest 5・Vue 3.6・SvelteKit 3 は RC のまま足踏み

pnpm が先陣を切った一方で、RC の波の大半はまだ stable に届いていない。Vitest 5 は今週も RC を刻み続け、5.0.0-rc.3（8/28）・5.0.0-rc.4（8/31）と番号を進めたが、stable は未着（現行 stable は 4.1.11 のまま）。Vue 3.6 も rc.6 まで来て Vapor Mode を feature-complete としつつ GA は秋待ち、という先週の構図が続く。SvelteKit 3 も RC 段階で、Vite 8 + Rolldown（esbuild+Rollup を置き換える新バンドラ）を前提に「問題なければ近く stable」と告知するにとどまった。先週「一斉 RC」と呼んだ集団は、今週は pnpm 1 銘柄が GA へ抜け、残りは横並びで最終調整を続けている。

「フロントエンドに隕石が落ちている」— Nolan Lawson 論が広く読まれる

リリースの列とは別に、今週は 1 本のエッセイが論調を動かした。Nolan Lawson の 「フロントエンド web 開発にいま隕石が落ちている」（8/23）は、AI エージェントがフロントエンドの教育とキャリアを構造的に作り変えていると論じる。要点は 3 つ。(1) フロントのコードは backend より差し替えが利くため AI に任せる心理的障壁が低い、(2) エージェントの多くが React で学習しているため、Svelte / Solid の優れた DX よりも「agent experience」が効くようになり、特化フレームワークの魅力が相対的に下がりうる、(3) 標準化の焦点も、開発者に優しい API より Project Fugu 的な能力（capability）重視へ傾く——というものだ。著名なフロントエンド教育者が相次いで AI 側へ軸足を移している事実を挙げ、これが一時の流行ではなく職業地図そのものの変化だと位置づけた。RC の波やセキュリティ対応という「日々の道具立ての更新」の裏で、その道具を誰が・何のために書くのかという問い自体が揺れている。

セキュリティ

AVIF 最適化は当面オフ — 上流 libheif の修正待ちという構図

Next.js の 2 件のうち、影響が広いのは AVIF 最適化の RCE だ。根本原因は Next.js 自身ではなく sharp が内部で使う libheif にあり（GHSA-2xp9-vwfh-vxw4 / libheif 側 GHSA-g89c-p67h-r497）、攻撃者が用意した AVIF を最適化パイプラインに通すだけで成立する。上流の修正が配布網に行き渡るまで時間がかかるため、パッチ版はフレームワーク側で AVIF 最適化を止めるという一時対処を選んだ。画像最適化に AVIF を使っていたサイトは、当面 WebP などにフォールバックする挙動になる点を認識しておきたい。先週のサプライチェーン騒動に続き、今週も「自分のコードではなく依存の奥で穴が開く」という、モダンフロントエンドの構造的リスクが表面化した格好だ。

フレームワーク・ランタイム

Vite 8 + Rolldown が RC 群の共通土台に — バンドラ統一の実地投入が進む

今週の RC 群を横に見ると、Vite 8 の Rolldown 化が共通の下敷きになりつつあることが分かる。Vite 8 は従来の esbuild + Rollup の 2 本立てをやめ、Rust 製の Rolldown 単一バンドラへ統一する方向で、SvelteKit 3 RC はこれを前提に組まれている。先週「pnpm が Rust バイナリ」「Solid が Rust コンパイラ」と書いた流れは、ビルドチェーンの中核であるバンドラにも及んだ。フレームワーク各層が足並みをそろえて Rust ベースの基盤へ載り替える構図が、RC の波を通して一段はっきりしてきた。stable がそろえば、「Vite を使う限りバンドラは Rolldown」という前提が既定になる。

来週の注目ポイント

次の GA は Vitest 5 か — RC の波、2 番目の卒業生を待つ

pnpm 12 に続く 2 番目の stable がどれになるかが次の焦点だ。Vitest 5 は rc.4（8/31）まで来ており、当初予告の「RC 2〜3 週」を踏まえれば最も近い。SvelteKit 3（Vite 8 + Rolldown）と Vue 3.6（Vapor Mode / 秋 GA 予定）がそれに続くかを見たい。「一斉 RC」が実際に「一斉 GA」へ転じるのか、それとも pnpm のように 1 つずつ間隔を空けて抜けていくのか、波の割れ方そのものが来週以降の見どころになる。

Next.js パッチの浸透と AVIF 復帰 — 上流 libheif 修正の行方

セキュリティ側では、今週出た 16.3.3 / 15.5.24 の適用がどこまで浸透するか、そして無効化された AVIF 最適化がいつ復帰するかが続報になる。復帰は上流 libheif の修正が配布網に行き渡ることが前提なので、フレームワークの一時対処が「恒久対処」に切り替わるまでのラグを追いたい。Windows RCE には回避策が無いため、Windows ホストのチームがどれだけ早くパッチ適用を終えられるかも実務上の関心事だ。
