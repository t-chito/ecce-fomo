まとめ

先週号は「RC の波、次の GA はどれか」と「フロントに隕石＝AI エージェント」の 2 つを宿題に残した。今週はその両方に答えが出た。Vitest 5.0 が 9 月 3 日に GAし、pnpm 12 に続く波の 2 番目の卒業生となった——先週の「次は Vitest 5 か」という見立てがそのまま当たった格好だ。そして隕石論には Vercel が実物で応じた。Next.js チームはエージェント群「Maintainer Agent」で約 3 週間に 1,462 件の issue をクローズし、その一部は人手を介さない自動クローズへ移し始めたと明かした（9/4）。sv CLI も mcp アドオンを ai-tools に置き換え、開発ツールの土台に「エージェント前提」が静かに敷かれつつある。一方で SvelteKit 3・Vue 3.6 はまだ RC のまま。波は 1 つずつ、間隔を空けて割れていく。

今週の重要ポイント

Vitest 5.0 が GA — 予告どおり RC の波の 2 番目の卒業生に

先週「次の GA は Vitest 5 か」と書いた見立てが現実になった。Vitest 5.0 が 9 月 3 日に stable リリースされ、8 月 26 日の pnpm 12 に続いて RC の波から 2 番目に GA へ抜けた。目玉は Browser Mode の Trace View（操作・アサーション・DOM スナップショットを記録し、UI と HTML レポーターで一手ずつ再生できる）、引数ごとに戻り値を変える vi.when API、そして fake timers による Temporal API のモックだ。現実的なアプリでの実測は enterprise モノリス（1,280 モジュール）で −19%、deps 過多構成で −53% と、性能面の押し上げも大きい。破壊的変更は Vite ≥ 6.4.0 / Node.js ≥ 22.12.0 要求、未 await の非同期アサーションが失敗扱いに、clearMocks が既定で有効化、の 3 点が主軸。移行時はこの 3 つを先に潰しておきたい。

先週の「隕石」が実物に — Vercel、エージェント群で Next.js の issue 1,462 件をクローズ

先週広く読まれた「フロントに隕石＝AI エージェント」論に、今週は最大手の 1 社が実装で応えた。Next.js チームは 9 月 4 日、約 3 週間で 1,462 件の issue をクローズしバックログを 2,244 件（8/10 時点）から 1,000 件未満へ落とした経緯を公開した。中核は Vercel の OSS エージェント基盤 eve 上に組んだ closability エージェントで、sandbox 内で会話・関連 PR・コミット・リリースを調べ、報告バージョン／最新 stable／canary で再現を試み、自説に反する証拠まで探したうえで close 可否を confidence 付きで返す。判定内訳は「既に修正済み」37%・「重複」19%・「期待動作」16%。エージェントは sandbox の外では read-only で、issue 本文の指示はプロンプトインジェクション対策として無視する設計だ。当初は maintainer が全件をレビューして close していたが、今週score 80 以上を二段のエージェントで再確認し人手なしで自動クローズする運用（週 25 件から）を開始したことも明かした。隕石論が言う「フロントの仕事の作り変え」は、まず保守側の作業から目に見える形で始まっている。

波の残りは足踏み — SvelteKit 3・Vue 3.6 は RC のまま、sv CLI は mcp を ai-tools へ

Vitest が抜けた一方、SvelteKit 3 と Vue 3.6 は今週も RC 段階にとどまった。SvelteKit 3 RC は 3.0.0-next.24 まで進み、QUERY HTTP メソッドのハンドラや、成功／失敗時にアクションページへ遷移する改良版 form actionsを積んだが stable は未着。Vue 3.6 も Vapor Mode を feature-complete としつつ GA は「秋」の予告のまま据え置きだ。注目は周辺 CLI の動きで、sv は 1.0 プレビューで従来の mcp アドオンを、より広い ai-tools アドオンに置き換えた（クライアントごとにツールを選べる）。ここでも「エージェント前提」がツールチェーンの既定に滑り込んでいる。波は「一斉 GA」ではなく、pnpm → Vitest と1 つずつ間隔を空けて割れている。

テスト・ツール

Vitest 5 の設計思想 — 「速さ」と「厳格化」を同時に押す

Vitest 5 は機能追加だけでなく既定値の厳格化を同時に進めたのが特徴だ。vitest list はテストを実行せず静的解析でファイルを列挙する挙動に変わり、locator は既定で strict に、ARIA ツリーのスナップショットをエラーに併記するようになった。プロジェクト構成もルート設定を既定で継承する入れ子モデルへ整理され、ベンチマークは通常のテスト呼び出しに fixture として統合された。「未 await の非同期アサーションを失敗にする」「clearMocks を既定 on」といった変更は、これまで静かにすり抜けていた不正なテストを表に出す方向の調整で、性能の押し上げとセットで「速くて、ごまかしの効かない核」を狙っている。790 名超のコントリビューターへの謝辞が示すとおり、メジャー番号にふさわしい規模の更新になった。

フレームワーク・ランタイム

Turbopack、チャンク分割の実験的コントロールを追加 — ナビゲーション性能を手で詰める

Next.js は 9 月 3 日、Turbopack の JavaScript チャンク分割を調整する実験的機能を解説した。ページ間のナビゲーション性能を高め、ページをまたいだコード共有を効かせて初回読み込みを速める狙いで、これまで自動任せだったチャンク境界に開発者が介入できる余地を開いた。8 月の一斉セキュリティリリース（16.3.3 / 15.5.24）以降、Next.js の焦点は Turbopack と routing・caching の地道な最適化へ戻っている。先週追っていた「AVIF 最適化の復帰（上流 libheif 修正待ち）」については、今週の公式ブログでは特段の続報は出ていない——一時対処のまま静かに継続している状態だ。

来週の注目ポイント

波の 3 番目の卒業生は SvelteKit 3 か Vue 3.6 か

pnpm 12 → Vitest 5 と抜けてきた RC の波の次の GAがどれになるかが引き続きの焦点だ。SvelteKit 3 は next.24 まで RC を刻み、sv の task ベース移行（$lib → #lib の書き換えを含む）も整ってきた。Vue 3.6 は「秋 GA」の予告が生きており、9 月後半から 10 月にかけてがいよいよ本番だ。波が「1 つずつ」割れるパターンが続くのか、複数が近接して GA するのか、割れ方そのものを来週も見ていきたい。

「保守エージェント」は他ベンダーにも広がるか

Vercel が公開した Maintainer Agent（closability ほか、再現・検証・bisect・E2E・修正案作成を分担する複数エージェント群）は、OSS 基盤 eve の上に組まれている。人手なし自動クローズという踏み込みがissue 品質やコミュニティの反発にどう跳ね返るか、そして React・Vue・Svelte など他の大規模 OSS が同様の「保守側エージェント」を採り入れるかが次の見どころだ。先週の隕石論が言う変化は、まずコードを書く現場より、コードを保守・選別する現場で可視化されつつある。
