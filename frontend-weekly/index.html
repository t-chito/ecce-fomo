まとめ

先週号の「来週の注目ポイント」に挙げた 2 つが、そのまま今週の主役になった。Next.js 初の月次セキュリティリリースの中身が公開され、高 4・中 5 の 9 件が Server Actions の DoS・SSRF、Turbopack 単一ロケールでの Middleware バイパス、Image Optimization の SVG DoS など具体像を伴って明らかになったうえ、4 日後（7 月 25 日）には追いパッチ 16.2.12／15.5.22が続いた。もう一方の TS7 待ちだった SFC スタックでは、Vue 3.6 が RC 入りし Vapor Mode が feature-completeに到達、alien-signals によるリアクティビティ刷新も載って「3.0 以来最大」と評される節目を迎えた。ただし Vue のテンプレート型チェックは依然 TS7.1 待ちで、同じ TS7 の壁は Next.js 15.5 が「TypeScript 7 以上を明示的に弾く」一方 16.2 は対応を backportという形でフレームワーク内部にも表面化した。ブラウザでは Chrome 143 が anchor positioning の fallback スタイルと XSLT 非推奨開始を載せている。今週の通奏低音は「予告どおり届いた安全運用」と「速い新実装が RC まで来ても型基盤の解禁は 7.1 待ち」という二本の確定である。

今週の重要ポイント

Next.js 月次セキュリティリリースの中身が公開 — 9 件の内訳が判明、4 日後に追いパッチ

先週号で最大の焦点に挙げた「初回リリースの CVE 詳細と 9 件の内訳」に答えが出た。7 月 21 日に着地した 16.2.11／15.5.21 が塞いだ高 4・中 5 の脆弱性は、App Router の Server Actions における DoS、rewrites と Server Actions を突いた SSRF、Turbopack の単一ロケール構成での Middleware／Proxy バイパス、レスポンスボディに影響する キャッシュ混同（cache confusion）、Image Optimization API の SVG による DoS、内部 Server Function エンドポイントの露出、Edge ランタイムでの Server Action ペイロードの無制限受け入れ、といった内訳だった。攻撃者に手がかりを渡さない協調ディスクロージャの方針どおり、パッチ普及を待ってから具体像が開示された格好だ。

さらに読みどころは、初回で終わらせない運用が早くも回ったこと。7 月 25 日に 16.2.12／15.5.22 の追いパッチが出て、TypeScript 7 対応の backport やドキュメント修正を届けた。「決まった日にまとめて来る」制度が、初号の見栄えだけでなく直後の追随でも機能した点が、先週の「二号目まで宣言どおり回るか」という問いへの早い前振りになっている。緊急性の高い実悪用ケースには随時パッチという例外を残しつつ、平時は月次・予告付きで検証枠を組める前提が実データで裏づけられた一週間だった。

Vue 3.6 が RC 入り — Vapor Mode が feature-complete、alien-signals でリアクティビティを刷新

先週号で「TS7.1 を待つ SFC スタック」の代表に挙げた Vue が、その足止めとは別の軸で大きな節目を迎えた。7 月 18 日に Vue 3.6.0-rc.1 が公開され、数年来のロードマップだった Vapor Mode が feature-complete に到達した。Vapor Mode は Single-File Component 単位で opt-in する新しいコンパイル戦略で、<script setup> に vapor 属性を付けると仮想 DOM を介さずランタイムを大きく省き、js-framework-benchmark で Solid や Svelte 5 と同等の速度を示すとされる。既存 API のサブセットをほぼ同じ挙動でサポートし、部分導入から小規模アプリの全面採用まで想定する設計だ。

同時に @vue/reactivity を alien-signals ベースで全面書き換えし、push-pull の遅延評価で computed の性能を上げつつ メモリ使用量を約 14% 削減する。こちらはコンポーネントコードを触らずに効く基盤刷新で、Vapor を使わないアプリにも恩恵が及ぶ。RC 段階のため Vapor Mode 自体はまだ unstable 扱いだが、「3.0 以来最大の Vue リリース」と評される内容が GA 目前まで来た。先週の「ネイティブ実装・脱仮想 DOM の速さ競争」という文脈に、React・Svelte に続いて Vue が本命の一手で並んだ形になる。

Chrome 143 — anchor positioning の fallback スタイル、そして XSLT 非推奨の開始

先週号の Chrome 142（View Transitions の仕様追随、scroll-marker 擬似クラス）に続き、Chrome 143 の Release notes が出そろった。CSS では、アンカー配置要素がどの position-try-fallbacks を採用したかに応じて子孫を出し分けられる @container anchored(fallback) が入り、テザーやアニメーションを配置結果に連動させやすくなる。加えて background-position-x/y の辺基準ロングハンドで背景画像を端からの相対位置で指定でき、OpenType グリフ置換に使う言語を上書きする font-language-override も追加された。

基盤側では 2 つの締めが目を引く。FedCM は IdP が構造化 JSON を返せるようになる一方、プライバシー強化として .well-known/web-identity に direct endpoints 形式を必須化し、client_metadata 経由のクロスサイトな identity 相関を防ぐ。そして セキュリティ上の懸念と利用減から XSLT v1.0 の非推奨が始まった。ほかにも WebTransport のプロトコルネゴシエーション、Isolated Web Apps 向け Smart Card API、ICU 77（Unicode 16）への更新など、標準 API の拡張と旧機能の整理が同居する。先週に続き「既定を締めつつ標準を増やす」方向性が続いている。

型チェックとエコシステム

TS7 の壁がフレームワーク内部に露出 — Next.js 15.5 は「7 以上を拒否」、16.2 は対応 backport

先週号で「コンパイラの速さは本物だが、SFC 中心スタックの型チェックは 7.1 待ち」と読んだ構図が、今週は Next.js の中に具体化した。追いパッチで 16.2.12 は TypeScript 7 対応を backport して取り込む一方、15.5.22 は「TypeScript 7.0 以上を、実行可能なエラーメッセージ付きで拒否する」挙動を明示的に入れた。同じフレームワークの現行系列でも、TS7 を迎え入れる版とまだ受け付けない版が並走している、というのが 7.1 前夜の実態を端的に表している。

そしてこの壁は、今週 RC に達した Vue にもそのまま残る。Vapor Mode と reactivity 刷新でランタイムは一段速くなったが、Vue のテンプレート型チェック（Volar 系）が依存する旧プログラマティック API は TS7.0 では保留されたままで、TS7.1（10 月ごろ想定）を待つ点は先週から変わらない。速い新実装が RC・GA へ進む動きと、その型基盤の全面解禁が 7.1 に括られている構図が、フレームワークとメタフレームワークの双方で今週いっそう鮮明になった。当面は「tsc は TS7・型情報付き ESLint は TS6 併用」という折衷を続ける現場が多い。

フレームワーク・ランタイム

React 19.2.8 パッチ — Compiler は正式版として定着

React も 7 月 21 日に 19.2.8（あわせて 19.1.9／19.0.8）をリリースした。<Activity> や useEffectEvent、Performance Tracks などを載せた 19.2 系のメンテナンスパッチで、破壊的変更のない安定運用寄りの更新にあたる。トピックとしては、以前は experimental だった React Compiler がもはや実験的ではなく正式（stable）として扱われる段階に入っている点が背景にある。useMemo／useCallback を手で撒く最適化から、ビルド時に自動最適化する前提へと現場の作法が移りつつある。

ランタイム側では Deno 2.7 が Temporal API、Windows ARM 対応、npm overrides を載せて Node.js・Bun との競争を続けている。フレームワークのメジャー更新（Vue 3.6 RC）とパッチ運用（React 19.2.8）、ランタイムの機能追加が並走し、エコシステム全体としては「大玉の RC と、その周りの着実なメンテナンス」が同居する一週間だった。

ビルドツール・エコシステム

Turbopack の永続キャッシュ運用と、Astro のパッチ整備

先週の「速くなった基盤を実プロジェクト規模で安定運用へ持ち込む」局面は、ビルドツール側でも続く。Next.js 16.3（@preview）の Turbopack は、turbopackFileSystemCacheForBuild で next build にも永続ディスクキャッシュを効かせられるようになり、CI で .next を実行間で引き継げば再ビルドの計算を再利用できる。長時間の dev セッションでのメモリ使用も大きく下がる方向で、Vercel 自社サイトでの hardening を経ての段階的な提供だ（安定版ラインは 16.2 のまま）。「速さの前にキャッシュ運用を決める」という設計判断が実務の論点として定着しつつある。

ビルドチェーンの上流では、Astro が 7.1.x のパッチ（7 月 27 日時点で 7.1.4）を重ねて Vite 8／Rolldown 世代の安定化を進めている。TypeScript のネイティブコンパイラ、Astro の .astro コンパイラ、Vite の Rolldown、そして今週 RC に達した Vue の Vapor と、フロントの基盤が軒並みネイティブ／脱仮想 DOM へ載せ替わる流れの中で、各層が「メジャーで飛躍し、パッチで実運用へ均す」サイクルに入っている。

来週の注目ポイント

Vue 3.6 の GA と、Vapor Mode の unstable 解除の見通し

今週 RC に達した Vue 3.6 が rc から stable（GA）へいつ進むか、そして feature-complete でも「unstable」と位置づけられた Vapor Mode が本番推奨に格上げされる条件が最初の焦点。alien-signals リアクティビティは既存アプリにも効くため、GA 後の移行ガイドや実測ベンチ、Nuxt 側の追随ステータスが出てくれば、採用計画を立てる材料になる。

  • Releases · vuejs/core — GitHub

Next.js 月次セキュリティの「二号目」と、15.5 系の TS7 対応判断

初号が予告どおり着地し追いパッチも回った以上、次は 8 月に予定される二号目が同じ日程規律で出るかが継続ウォッチ。あわせて、16.2 が backport した TypeScript 7 対応を 15.5 系も受け入れる方向へ転じるのか、それとも「拒否」を維持するのかは、旧 LTS を使い続けるチームの移行計画に直結する。CVE 番号の追加公開があれば自社アプリの露出評価にも反映したい。

  • Next.js Blog — nextjs.org

TypeScript 7.1 のプログラマティック API — SFC テンプレート型チェック解禁の前提

Vue・Svelte・Astro・MDX のテンプレート型チェックを TS7 上で動かす鍵となる プログラマティック API は 7.1（10 月ごろ想定）待ち。来週の短期で GA する話ではないが、ロードマップやプレビュー、@typescript/typescript6 併用がいつまで必要かの見通しが出れば、Vue 3.6 GA と足並みをそろえた型基盤の全面移行計画を描ける。ネイティブ化の恩恵を「型チェック全面」へ広げられる時期の手がかりとして追う。
