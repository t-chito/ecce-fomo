Claude Code

Claude API に2023年以来初の正式バージョンが入る

10/21、Anthropic が API バージョン 2026-10-21 を公開した。Claude API は進化を続けてきたが、正式なバージョン発行は 2023 年以来初だという。今後はより頻繁にバージョンを出し、新モデルが要求する前に破壊的変更へ備えられるようにする。2023-06-01 は非推奨にはならない。

このバージョンでは、Messages API から temperature・top_p・top_k が外れ、アシスタントターンの documents とユーザーターンの citations が 400 を返すようになる。SDK と ant CLI も新メジャーが出て既定が 2026-10-21 になった。Claude Code からは 2.1.307 で入った /claude-api api-version でコードを移行できる。

  • @ClaudeDevs: SDK と ant CLI の新メジャーが既定 2026-10-21・/claude-api skill と移行ガイド

gzip 圧縮とクラウド先行起動で応答が速くなる

Claude Code が毎ターン送る会話を gzip 圧縮するようになり、モデルへ届くまでが速くなった。応答が始まるまでの待ちが縮んでいる。あわせてクラウドセッションは、入力を始めた時点で起動を先に走らせるので、送信してから立ち上がりを待つ時間が減る。派手な機能ではないが、毎回の体感に効く地味な改善だ。

Code Review が Team・Enterprise で一般提供に

10/15、Claude の Code Review が Team・Enterprise プランで一般提供になった。管理者が Claude Code の設定でリポジトリを選んで有効化すると、開発者側の設定なしで新規 PR ごとにレビューが走る。リポジトリ単位で Quick・Standard・Deep の深さを選べ、プレビュー時より約 3 倍速く、重要なバグをより多く拾うという。Enterprise は 1/15 までに最低 $10,000 のクレジットを請求できる。

背景には、Anthropic 自身が Claude Code のコードの約 9 割を Claude に書かせ、6〜9 月でマージ PR を倍以上に増やしつつ revert 率を 40% 以上下げた経験がある。どうレビューを変えたかはブログにまとまっている。開発者の bcherny は「Code Review なしの生産性は想像できない。全 PR で走り、出る前にほぼ全部のバグを捕まえる」と書いた。

出典（4）
  • @ClaudeDevs: Code Review が Team・Enterprise で GA（Quick/Standard/Deep をリポジトリ単位で選択）
  • @ClaudeDevs: 管理者が設定でリポジトリを選ぶと開発者の設定なしで全 PR にレビュー
  • @ClaudeDevs: Claude が Claude Code のコードの約 90% を記述・PR 倍増で revert 40%+ 減のレビュー手法
  • @bcherny: Code Review が全 PR で走り、出る前にほぼ全バグを捕まえる

続報週次リリースはサンドボックスと API 移行を整える

この週は 2.1.301〜2.1.308 が出た。2.1.302 では Read ツールが 128MB 超の画像を拒否してメモリ逼迫での crash を防ぎ、アイドル圧縮の on/off が /config から切れるようになった。fork サブエージェントも既定で有効になった。2.1.304 で /auto-mode-setup（環境を走査して Auto Mode に学習させる案内）が入った。

2.1.305 では sandbox.allowNestedUserNamespaces が加わり、Linux のサンドボックス内で Chromium や rootless podman がユーザー名前空間を作れる（その分ファイル保護は回避され得るので承知のうえで使う）。2.1.306 はクラウドセッションで claude -p が「Not logged in」になる不具合と、MCP 多用時に API エラーが「prompt is too long」に化ける不具合を直した。

Claude Duet が先回りするエージェントとして登場

Claude Duet が「先回りして動く」エージェントを打ち出す

10/21、Anthropic が Claude Duet のリサーチプレビューを開いた。Claude が能動的なエージェントとして動く新しいアプリで、注意が要ることを向こうから持ってきて、頼んだタスクをこなし、席を外しても作業を続け、代わりに動く前には確認を取る。Opus 5.5 を軸に設計され、何が急ぎで何を後回しにでき、いつ確認すべきかを判断する。アカウントのメモリ・スキル・連携アプリを引き継ぐので設定はほぼ要らない。

提供は米国の Pro・Max プランで、待機リスト経由の早期プレビュー。緊急度の見誤りはまだあり得るとしている。安全面では、パスワードを直接見ることはなく、機微な情報の共有を防ぐ分類器を新たに置き、重要な判断は人に残す設計だという。

各社が AI でコードの脆弱性を探し始める

Anthropic が OSS と自社コードを継続スキャンする

10/19、Anthropic が OSS Scanner を出した。重要な OSS プロジェクトに、最も強いモデルによる無料の定期脆弱性スキャンを提供する。各指摘には実証（PoC）が付き、可能なら修正も添える。最初の 1 週間で 77 件の critical と 803 件の high をメンテナへ報告し、curl の修正も含まれた。

10/21 には Claude Security がコードの変化に追従するようになった。リポジトリを一度つなぐと深い初回スキャンの後、変更が入るたび再スキャンして指摘を現状に合わせる。Claude がコードから書く脅威モデルも付き、修正が入れば finding を fixed にし、再発すれば開き直す。Enterprise でパブリックベータ、対象組織に月 $25,000 のクレジットが付く。

OpenAI が PHP の重大な脆弱性を発見しスキルを配る

10/21、OpenAI が、自社モデルが研究者とともに PHP の重大なセキュリティ欠陥を見つけたと公表した。PHP は推計で全ウェブサイトの約 70% を動かす。2 か月かけてメンテナ・研究者の連合を率いて進めた、"Patch the Planet" 構想の成果だという。発表後、PHP の緊急対応に追われた開発者も多かった。

自分のサイトが影響を受けるか確かめられるよう、OpenAI は Codex 用のスキルを用意した。リポジトリを指す形で Codex に渡すと、確認手順を案内する。モデルが脆弱性を見つけ、その対処まで同じエージェントの手順に落とす流れだ。

出典（2）
  • @OpenAI: モデルが PHP（全サイトの約 70% を駆動）の重大な欠陥を発見（Patch the Planet）
  • @OpenAI: 影響の有無を確かめる Codex スキルを配布（リポジトリを Codex に渡す）

Codex が開発環境の操作性を詰める

Codex が CLI とアプリの細かい使い勝手を改善

OpenAI の Codex が開発環境まわりを細かく整えた。アプリ側は、Composer に次のプロンプト候補を出す予測機能と、Tab でそれを編集可能な下書きとして受け取る操作が入った。CLI 0.163.0 では /config の検索と即時編集、/keymap のリーダーキー（既定 Ctrl+X）、ターン途中のフォローアップと読み取り専用ツールの並列実行が加わった。

Notion のエージェントが長時間稼働へ

Notion のエージェントが 24 時間連続で動けるように

10/19、Notion AI が大きく更新された。Notion Agents は自分専用のコンピューターとブラウザを持ち、稼働時間が従来の 5 分から 24 時間以上に伸びた。実行前に安全確認を挟む「Review for me」モードが入り、個人の ChatGPT プランを Notion 内で使うこともできる。Web・モバイルの読み込みは最大 50% 速くなった。

モデル選びは新しいルーター Auto が担う。タスクごとに品質・速度・コストの釣り合う型を選び、行き詰まれば方針を変える。フロンティア級の品質を 90% 安く出すという。BYOK・MCP の改善・新しいクレジット制も加わった。
