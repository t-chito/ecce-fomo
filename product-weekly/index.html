まとめ

先週の「穴を塞ぐハードニング」に対して、今週の Claude Code は「任せる」を既定に切り替える週だった。8/14 から Pro・Max・Team で auto モードが標準の権限モードになり、しかも権限分類器のトークンは利用上限に数えない——「人間が危険コマンドを見抜けるのは 14%（50回も繰り返すと 5% 台）、分類器は 89%」という自社検証を根拠に、承認ダイアログを外して長時間タスクを回す方向へ舵を切った。あわせてセッション同士がメッセージを送り合える（SendMessage）機能が 2.1.224 で入り、今週いちばん拡散した投稿（750万インプレ・6万いいね）になった。プロダクト外周では Grok 4.6 が「フロンティアの半額」で登場し即日 Devin・Cursor・Notion に載る、モデル差し替え合戦が続く。CodeRabbit は 143M ドルのシリーズ C（評価額 15億ドル）を発表して「AI コードレビュー」から「Agentic Change Management」へ看板を掛け替えた。そしてコミュニティでは、他社モデルを Claude Code のハーネスで動かして Anthropic に BAN された話が波紋を呼び、ハーネスの囲い込みという論点が浮上した週でもあった。

Claude Code

8/14 から auto モードが既定に——「人間の承認より安全」を数字で押し切る

今週の主役は明確だ。8 月 14 日から、Claude Code の既定の権限モードが auto モードになる（Pro・Max・Team、既に defaultMode を設定済みなら変更前に確認が入る）。auto モードは各ツール呼び出しを別の分類器で審査する方式で、Anthropic は「テストで危険なコマンドの 89% を捕捉、手動承認は 14% だった」と主張。さらに 1,053 人の有料テスターに、明らかに危険なコマンド（テキストのみ・実際には実行しない）を混ぜた検証では、テスターが気づいたのは 13.6%、50 回もプロンプトを浴びると 約 5% まで落ちた——「承認ボタンの連打は安全装置として機能しない」というのがメッセージだ。

運用上の摩擦も同時に削った。分類器が各ツール呼び出しで消費する少量のトークンは、Pro・Max・Team の利用上限に数えない（Enterprise・API は auto モード既定化に合わせて追随）。管理者は managed settings で defaultMode を固定、あるいは auto モードごと無効化でき、ユーザーは従来どおり Shift+Tab で切り替えられる。中の人の温度感も高く、Boris Cherny（@bcherny）は「チームは何ヶ月も auto モードだけを使ってきた。もう承認プロンプトには戻れない」と投稿。安全性の裏づけとして、彼は「モデル訓練＋入力プローブ＋意図を確認する分類器、を積み重ねると、未知の攻撃に対する間接プロンプトインジェクションを実質ゼロにできた」とも書いた。先週までの権限・サンドボックスのハードニングに続く「任せる前提の地ならし」が、いよいよ既定値の変更として着地する。

セッションが互いにメッセージを送り合う（SendMessage）——今週いちばん拡散した機能

2.1.224 で入った クロスセッション・メッセージング（SendMessage）は、今週最大の話題になった。別セッションに文脈を渡し直したいとき、これまでは自分で説明をやり直す必要があったが、これからは「あのセッションに伝えておいて」と Claude に頼める。送られるのは要約だけ（履歴やファイルは渡さない）で、受け取った側はタスクの途中でそれを拾う。双方向で、別セッションに質問を投げて回答を今のセッションで受け取ることもでき、Claude が自発的に「今の変更が別セッションの作業に影響する」と判断してメッセージを送ることもある。@ClaudeDevs の告知は 約 750 万インプレッション・6 万いいねに達し、今週の x で群を抜いた反応を集めた。

基盤として、ListAgents でマシンをまたいだセッションを発見できるようになり（macOS/Linux）、2.1.225 では 他マシン上の Remote Control セッションに名前で会話を開始できるようになった。2.1.228 ではクロスセッションのメッセージが折りたたみでなくインライン表示になり、受信箱なしで会話が始まってしまう不具合も修正。複数エージェントを並走させて協調させる、という運用が「実験」から「標準の使い方」に一歩近づいた。

  • @ClaudeDevs — セッション同士がメッセージを送り合える（要約のみを渡す）
  • @ClaudeDevs — 双方向・Claude 側からの自発的メッセージ
  • Claude Code Releases（2.1.224 SendMessage／2.1.228 インライン表示）

2.1.224〜231——self-hosted runner、Edit の厳密置換、そして「同期スキル」の締め直し

リリースは 2.1.224 から 2.1.231 まで一週間で 8 本。目玉は 2.1.224 の self-hosted runner（claude self-hosted-runner）で、自前のマシンやコンテナを Claude Code セッションの実行先にできる（Team・Enterprise）。プライベートで統制の効いた実行環境を、クラウドではなく手元に置きたい組織向けの一手だ。あわせて Edit ツールが厳密な文字列一致でのみ置換する方式になり、部分文字列を巻き込む意図しない編集を防ぐようになった（2.1.224／225）。

先週の権限ハードニングの流れは、今週は「claude.ai と同期するスキル」の締め直しに及んだ。2.1.228 は、同期スキルがローカルのコマンドを乗っ取る（shadow する）のをやめ、シェル実行をブロックし、メタデータをサニタイズする——ローカルのコマンドを優先させ、外部同期の設定に足元をすくわれないようにした。2.1.229 は 32 変更の大型で、Remote Control の --continue、self-hosted runner のフック対応、長考中の SSE キープアライブ、プラグインマーケットプレイスの command ソースなどが入った。週末の 2.1.231 では、Slack のような事前登録 OAuth クライアントを使う MCP サーバーでサインインが失敗するリダイレクト URI 不一致を修正している。

エージェント運用基盤の Managed Agents にも 4 つ更新が入った。セッションに予算を設定して上限で一時停止（budget_reached）、接続リポジトリの .claude/skills/ からスキルを自動ロード、推論リージョンを US／global で固定（inference_geo）、そして働くエージェントにadvisor（強いモデル）を 1 行で付与してセカンドオピニオンを取れるようにした。

  • @ClaudeCodeLog — 2.1.228（同期スキルの締め直し）
  • @ClaudeDevs — Managed Agents に 4 つの更新（予算・スキル・inference_geo・advisor）

Grok 4.6：「フロンティアの半額」で各プロダクトに一斉搭載

出た当日に Devin・Cursor・Notion——モデル差し替え合戦の最新ラウンド

xAI が Grok 4.6 を公開した。同価格で Grok 4.5 から大きく改善したとうたい、価格は 入力 $2／出力 $6（100万トークン）——「他のフロンティアモデルの半額」を前面に出した。注目は展開の速さで、発表当日に Grok Build・Cursor・Grok Bot・API で利用可能になり、Cursor と Grok Build では初週 2 倍の利用枠が付いた。

そして数時間のうちに、コーディングプロダクト側が続々と取り込んだ。Devin は「Grok 4.6 が使えるようになった。Grok 4.5 から大きく改善し、GPT-5.6 Sol を上回り、Opus 5 と Fable 5 に次ぐ」と告知。Notion も同日「Grok 4.6 が Notion で使えるようになった」と発表した。基盤モデルの新版が出るたびに、各プロダクトが最速で載せ替えてベンチ順位とコストを語る——先週の Devin×Grok（の前世代）に続く、この構図が今週も回った。プロダクトを選ぶ側にとっては「どのエージェントがどのモデルを、いつ、いくらで使えるか」が実利用の分かれ目になりつつある。

CodeRabbit：143M ドル調達で「レビュー」から「変更管理」へ

シリーズ C（評価額 15億ドル）と Agentic Change Management への看板掛け替え

先週「指摘より説明可能性」で立ち位置を語った CodeRabbit が、今週は資金で裏づけた。1.43 億ドルのシリーズ C を評価額 15 億ドルで調達（Atomico と Smash Capital が共同リード、BMW i Ventures や Datadog など新規、CRV・Scale Venture Partners などが継続）。掲げるのは「ソフトウェア変更の control layer（統制レイヤ）」で、AI コードレビューから「Agentic Change Management」へ事業を拡張すると宣言。「AI がコードを大量生産した結果、いまやボトルネックは信頼だ」という認識のもと、影響範囲の把握と出荷後のセキュリティ維持まで踏み込むという。

技術面の小ネタも、専業らしい方向だった。Baseten と組んで NVIDIA Nemotron 3.5 Lightning を CodeRabbit のルーティング判断でファインチューンし、3 時間・100 ドル未満で「従来の GPT クラスより精度 約 4% 向上」を得たと報告。汎用コーディングエージェントがレビューまで飲み込む中で、専業側は「レビュー」という単機能ではなく変更フロー全体の統制へと逃げ場を広げにきた、という構図が資金の裏づけとともに鮮明になった。

コミュニティ：ハーネスの囲い込みという論点

「他社モデルを Claude Code のハーネスで動かしたら BAN された」

プロダクトの使い勝手をめぐって、今週は「ハーネス（実行の枠組み）とモデルの結びつき」が議論になった。きっかけは、Tibo のセットアップを真似て OpenAI のモデルを Claude Code のハーネスで動かしたら Anthropic に BAN された、という報告。当の Tibo も「Anthropic には勤めていないので助けられないが、他社モデルを自分たちのハーネスで使っただけで BAN するのはおかしくないか。同じ状況の人いる？」と反応し、oikon48 らを通じて日本語圏でも共有された。

ツール（ハーネス）とモデルが別々に選べるように見えて、実際には利用規約でひも付いている——コーディングエージェントを選ぶとき、機能やモデル性能だけでなく「どのモデルを載せてよいか」という規約面まで見る必要がある、という実務的な気づきを突きつけた一件だ。auto モードの既定化や self-hosted runner のように「任せる・自前で回す」方向が進むほど、こうした運用境界の話題は増えていきそうだ。
