まとめ

今週の Claude Code は「机から離れても止まらない」方向に一気に寄せた週だった。先月ユーザーが「最初に直してほしい」と挙げた Remote Control の信頼性を作り込み、ついにスマホから直接セッションを開始できるようになった——接続が切れても勝手に再接続し、電話と CLI がモデルや作業状態まで同期する。もう一つの目玉は SendFeedback：何かが失敗したとき、Claude が自分でバグ報告を下書きしてくれる。リリースは 2.1.238〜247 と過密で、複雑タスク向けの専用エージェント起動ツール、/usage の Loops 内訳、組織承認モデルを並べる modelPicker、/permissions の Auto モードタブ、そして computer use・browser・Skills・Files API の一般提供まで積み上がった。周辺では Codex がエージェントをダッシュボードに束ねて @メンションで繋ぎ、Devin が Web アプリを全面刷新、CodeRabbit が変更の"影響半径"を可視化、Claude 本体は Cowork に組み込みブラウザと統合メモリを載せた。

Claude Code

スマホから Claude Code を起動する——Remote Control を作り込んで「机を離れても回る」へ

今週いちばんの動きは Remote Control の信頼性強化だ。Anthropic は「先月あなたたちが最初に直してほしいと挙げたのが Remote Controlだったので、信頼性に本気で取り組んだ」と切り出し、目に見える改善を並べた。最大の追加はスマホからのセッション開始——claude remote-control を動かしているマシンが Code タブの上部にデバイスカードとして並び、タップしてディレクトリを選ぶだけでそのマシン上でセッションが立ち上がる。告知スレッドは約 1 万いいね・150 万インプレと、今週の x で最も強い反応を集めた。

「動くけど不安定で使えない」を潰す地道な作り込みが揃ったのが肝だ。接続が切れても自動で復帰し（ノートを一瞬閉じたり Wi-Fi を切り替えても勝手に再接続）、電話とマシンの状態が同期する——ラップトップでセッションを再開すれば電話もライブ表示のまま、Claude Code が終了すれば数秒で電話側もオフライン表示に変わる。モデルと effort レベルも電話・CLI 間で揃い、iOS では重いセッションが速く開く。スラッシュコマンドも電話から効くようになり、/clear で電話ビューをリセット、/compact で圧縮マーカー表示、/diff がネイティブの差分ビューを開く。「長時間タスクを投げて、あとはスマホから様子を見て指示を足す」という運用が、実用に耐える段階に入った。

  • @ClaudeDevs — Remote Control の信頼性を強化（スレッド）
  • @ClaudeDevs — スマホから直接セッションを開始できる
  • @ClaudeDevs — 電話と CLI がモデル・effort・スラッシュコマンドまで同期

Claude が自分でバグ報告を書く——SendFeedback（2.1.247）

2.1.247 で入った SendFeedback は、使い勝手に効く小さな一手だ。何かが失敗したとき・Claude が自分のミスに気づいたとき・「うまくいかなかった」と伝えたときに、Claude がフィードバック報告そのものを下書きする。ユーザーはそれをレビュー・修正して承認し、送信できる（/feedback から確認、feedbackDrafts 設定でオフにも）。

この変更を実装した中の人 @trq212 は「これは自分の変更で、出せて嬉しい。今までは /feedback を叩いて自分で報告を書かないといけなかったが、これからは『フィードバックを下書きして』と言うだけでいい。報告は改善と問題把握にとても役立つのでありがたい」と投稿した。エージェントに任せる範囲が「コードを書く」だけでなく「不具合を言語化して開発元に返す」ところまで広がった格好で、日々の摩擦を一段減らす。

  • @ClaudeDevs — Claude Code が失敗時にフィードバックを下書き
  • @trq212 — 実装者による解説（「下書きして、と言うだけ」）
  • Claude Code Releases（2.1.247：SendFeedback ツール）

2.1.238〜247——専用エージェント起動ツール、/usage の Loops 内訳、modelPicker、Auto モードタブ

リリースは一週間で 2.1.238 から 247 まで、基盤側の効く更新が並んだ。2.1.246 では複雑なマルチステップ作業のために専用エージェントを立ち上げるツールが加わり、隔離されたサブエージェント・ワークフローが組めるようになった。あわせて /permissions に Auto モードのタブが入り、auto モードの分類ルールを一覧・編集できる。2.1.243 では /usage に Loops の内訳（ループ単位の実行回数・総トークン・実行あたりトークン・最終実行）が付き、おしゃべりな／暴走した /loop タスクを一目で見つけられるようになった。同版の modelPicker は /model を組織承認済みの順序付き・ラベル付きリストに整える設定だ。

足回りの修正も厚い。2.1.245 で glibc 2.44 を積む Linux（Arch・CachyOS・Fedora Rawhide）での起動時クラッシュを解消。2.1.247 では新コマンド /claude-api cost-optimize が、支出をプロファイルしてキャッシュ・バッチ・トークン衛生・モデル選択といったコスト削減の勘所を提示する。サブエージェントまわりも、初回呼び出しモデルが 404 で落ちていたのをセッションのフォールバック連鎖で救うよう直った。「賢くする」より「壊れず・軽く・見通しよく回す」側の投資が、今週はまとめて表に出た。

  • @ClaudeCodeLog — 2.1.246：専用エージェント起動ツールと Auto モードタブ
  • @ClaudeCodeLog — 2.1.243：/usage の Loops 内訳と modelPicker

computer use・browser・Skills・Files API が一般提供に——エージェントを組む土台が固まった

プラットフォーム側では、computer use、browser tool、Skills API、Files API が Claude Platform で一般提供（GA）になった。API を持たないアプリ相手でも、より少ない往復で作業を自動化でき、バージョン管理された Skills と再利用可能な部品の上に Claude Managed Agents を組める。

効率も上がった。新しい computer_toolset_20260801 では、Claude が1 往復に 1 アクションではなく、クリック・入力・キー・スクリーンショットを 1 ターンで複数実行する。早期アクセスの顧客ではタスクあたりの往復が 20〜40% 削減され、タスクが速く・安く終わったという。browser_toolset_20260801 は、レイアウトがずれると壊れる「ピクセル狙い」ではなく、ページ構造（要素参照＋座標）を Claude に渡すことで自動化を安定させる。エージェントを「デモ」から「日々回る仕組み」へ寄せるための、地味だが本質的な GA だ。

  • @ClaudeDevs — computer use・browser・Skills・Files API が GA
  • @ClaudeDevs — 1 ターンで複数アクション、往復 20〜40% 減
  • @ClaudeDevs — browser_toolset は要素参照でレイアウト変化に強い

Codex：エージェントをダッシュボードに束ね、@メンションで繋ぐ

agents ダッシュボード、タスク同士の @メンション、全マシン横断の接続

OpenAI の Codex CLI も、今週は「多数のエージェント／タスクをどう束ねるか」に踏み込んだ。0.149.0 で agents ダッシュボード（タスクの検索・開始・リネーム・停止）、codex queue（ローカル／リモートのセッションへのメッセージング）、codex doctor（ネットワーク・プロキシ・更新の診断）が入った。続く 0.150.0 では、他のタスクを読む・作る・メッセージするための @メンション、レスポンス／コードブロック／引用を選んで拾える /copy ピッカー、タスクの自動タイトル付け（/rename が名前を提案）が加わった。

OpenAI の @ajambrosino は「Codex を全部のコンピュータにまたがって接続できる（settings → connections）」と告知。Claude Code の Remote Control が「スマホから 1 台を操る」方向なら、Codex は「複数タスク・複数マシンを 1 画面から束ねる」方向で、エージェントを"群れ"として運用するための土台を並べてきた。似た課題に別のアプローチで各社が同時に手を伸ばしているのが今週の見どころだ。

  • @Codex_Changelog — 0.150.0：@メンションでタスク間連携、/copy ピッカー
  • @Codex_Changelog — 0.149.0：agents ダッシュボード、codex queue、codex doctor
  • @ajambrosino — Codex を全マシン横断で接続

Devin：Web アプリを全面刷新

読み込み 80% 減・レンダラを作り直し、⌘K で何でも操作

Cognition の Devin は、今週は中身より「毎日触る画面の速さと操作性」に投資した。Web アプリを全面刷新し、読み込みのもたつきを 80% 削減、サイドバーをカスタマイズ可能にし、⌘K で検索・開始・ピン留め・アプリ内移動までキーボードから完結させた。チャットのレンダラは一から作り直し、長いチャットが 55% 速く開き、INP は 36% 改善したという。

ネストしたサブエージェントの管理（子セッションが自前の VM を持ち、さらに孫を起こせる）をサイドバーから扱える点や、セッションのグルーピング・フィルタリングも入った。派手な新モデルの週ではないぶん、「大量のエージェント・セッションを日常的にさばく道具としての完成度」を各社が競い始めていることが、Devin の刷新にもよく表れている。

  • @cognition — Devin Web アプリ刷新（読み込み 80% 減、⌘K）
  • @cognition — レンダラ再構築で長いチャットが 55% 速く、INP -36%

CodeRabbit：変更の"影響半径"を可視化する

Security Blast Radius——diff に映らない下流の影響まで辿る

先週「5 日で 3 プロダクト」を打った CodeRabbit は、今週その中身を掘り下げた。目玉は Security Blast Radius。「PR が触るものの多くは diff に現れない」という問題意識から、変更の到達範囲（依存しているもの・影響を受ける消費側・カバーするテスト・周辺のリポジトリ文脈）を丸ごとマッピングし、承認前に下流への影響を調べられるようにする。7 分の解説動画つきで使い方を示した。

Blast Radius は Security Agent に同梱され、Change Stack から使える。あわせて CodeRabbit が Cursor のプラグインとして提供開始され、Cursor Agent に変更レビューを依頼したり、同梱の CodeRabbit サブエージェントにレビューを委譲したりできるようになった。汎用エージェントがレビューまで飲み込む流れに対し、専業らしく「変更が実際にどこまで波及するか」という一段深い情報で差別化しにいく構えだ。

  • @coderabbitai — Security Blast Radius の解説（7 分）
  • @coderabbitai — Blast Radius が依存・消費側・テストを地図化
  • @coderabbitai — CodeRabbit が Cursor プラグインに

Claude 本体：Cowork に組み込みブラウザ、記憶をチャットと統合

Cowork がサイドパネルでブラウザを開く／チャットと Cowork で記憶が一本化

コーディングエージェントの外周として追っている Claude Cowork にも、実務で効く更新が来た。ひとつは組み込みブラウザ：タスクがサイトを含むと、Cowork のサイドパネルにブラウザが開き、Claude が自分でナビゲート・フォーム入力して仕事を仕上げる。インストール不要で、自分のブラウザやログインとは分離される。今後 1 週間で有料プラン全体に展開。自分のブラウザで動かしたい人向けには Claude in Chrome が全有料プランで GA になった。

もうひとつはメモリの統合。チャットと Cowork で記憶が一本化され、Cowork にタスクを渡すと、Claude がこれまでのチャットで得た文脈（進めているプロジェクト、上司の好み、先の四半期の顧客）から始める。記憶は設定でトピックの一覧として読み・編集・削除でき、会話中に自動更新される（「これを覚えて」で明示保存も可能）。中の人 @bcherny は「小さな改善だが、メモリがよりシンプルで強力になった」と添えた。1 つのメモリを複数の作業面で共有する設計は、エージェントに任せる運用の"文脈の持ち越し"を楽にする方向だ。

  • @claudeai — Cowork に組み込みブラウザ
  • @claudeai — チャットと Cowork で記憶を統合
  • @bcherny — 「メモリがよりシンプルで強力に」

コミュニティ：セッション途中でモデルを変えるな

プロンプトキャッシュが壊れる——地味だが効く実務の注意

使い方の勘所として今週共有されたのは、個人エンジニア oikon48 の一言だった。「セッション中にモデルをガチャガチャ変えるな、プロンプトキャッシュが壊れる」——意外とやってしまいがちな落とし穴で、モデルを切り替えるたびに積み上げたキャッシュが無効化され、コストと待ち時間が跳ねる。今週の Claude Code 側の更新（/model を組織承認リストに整える modelPicker、/usage の Loops 内訳で暴走ループを可視化）は、まさにこうした「知らずに無駄を垂れ流す」箇所を減らす方向で噛み合っている。

関連して、Notion はスキルをローカルのエージェントへ持ち出す機能を出した。Notion をスキルの source of truth にしておき、Claude Code・Codex・Cursor・Gemini・Grok へ SKILL.md（＋承認済みファイル）をダウンロードして、どのツールでも同じ手順書で作業できる。「どのエージェントを使うか」がツール単位で分断されがちな中、スキルという単位で運用知を持ち運ぶ動きが静かに広がっている。

  • @oikon48 — モデルを途中で変えるとプロンプトキャッシュが壊れる
  • @NotionHQ — スキルを Claude Code / Codex / Cursor / Gemini / Grok へ持ち出す
