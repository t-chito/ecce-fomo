まとめ

先週は Fable 5.1 のキャッシュ読み 75% 減が主役だったが、今週の Claude Code は「値下げしたキャッシュを、実際に効かせ切る」ための地味で徹底的な修正週だった。2.1.265／2.1.267 で OAuth トークン更新・MCP 再接続・セッション途中のツール追加・/model 切替・セッション再開——プロンプトキャッシュが取りこぼす経路を一斉に塞いだ。先週入った切替フックが"検知"なら、今週は"漏れ止め"だ。あわせて全プロバイダ横断で努力度に上限をかける maxEffortLevel が入り、コストの締め方がもう一段増えた。周辺では、エージェントを隔離された作業場で走らせる流れが続き、Codex が実験的な worktree 分離を、OpenHands が Docker サンドボックス込みの 1.0 で応えた。派手な新機能より、"長く安全に回し続ける足回り"を各社が固め直した一週間。

Claude Code

プロンプトキャッシュの取りこぼしを一斉に封鎖——2.1.265／2.1.267 の"漏れ止め"ラッシュ

先週は Fable 5.1 のキャッシュ読み値下げと PreModelSwitch / PostModelSwitch フックで「キャッシュを壊さない」話が始まったが、今週はその続きを本気で詰めた。2.1.267（9/9）と 2.1.265（9/8）で、プロンプトキャッシュが無駄にミスする経路がまとめて潰されている——OAuth トークンの更新時、MCP サーバの再接続やツールの再描画、ToolSearch を使わないセッションでの途中ツール追加、/model でのモデル切替、セッション再開時のインラインツール／ツール説明の書き換え。いずれも「同じ文脈を舐め直しているのに、キャッシュ前提が微妙にズレて課金上のヒットを失う」典型パターンだ。

効きどころは明快で、Fable 5.1 のキャッシュ読み $0.25/Mtok を"割引価格のまま実際に使い切れるか"は、こうした取りこぼしをどれだけ塞げるかで決まる。先週の値下げ告知が理論値なら、今週の一連の修正はその理論値に実測を近づける作業。エージェントを長時間・複数ツールで回すほど効いてくる、地味だが本質的な週だった。

`maxEffortLevel` で努力度に天井——Bedrock／Vertex／Foundry 横断のコスト上限

2.1.267 の目玉機能は maxEffortLevel 設定だ。全プロバイダ（Bedrock・Vertex・Foundry）を横断して、エージェントが使える effort（思考の努力度）に上限をかける。同版では --system-prompt-snapshot off でリクエストごとにシステムプロンプトを描き直す挙動も選べるようになった。先週の /usage の支出上限バーが「使った額を見て止める」なら、maxEffortLevel は「そもそも重い思考に振れる上限を先に決める」——コストを事後の可視化と事前の制約の両側から握れるようになってきた。

加えて 2.1.261（9/4）では、コンテキスト浪費を洗い出す /skill-doctor（使われていないスキルとその context コストを表示）と、組織ポリシーの読み込み失敗を /status・claude doctor に出す「Organization policy」診断行が入った。2.1.265 の bashOutputMaxChars / taskOutputMaxChars（インラインで受け取る出力量を最大 128K 文字まで引き上げ）や、--plugin-dir にプラグイン群のフォルダを丸ごと指せる対応も、"長く回すエージェント"の取り回しを一段楽にする更新だ。

  • Claude Code Changelog（2.1.267：maxEffortLevel、2.1.261：/skill-doctor・組織ポリシー診断）

2.1.265→266 のゲートウェイ回帰と即日ホットフィックス——"締める"更新の裏で出た破壊的挙動

締める方向の更新が続くと、認証まわりの回帰も出る。2.1.265 で入った変更が、CLAUDE_CODE_USE_GATEWAY 環境変数を、API キーや apiKeyHelper・独自認証ヘッダと併用していても Cloud ゲートウェイ経由のサインインを強制してしまう不具合を生み、2.1.266（同 9/8）で即日修正された。修正後は、この変数を単体で置いても再び無視される（＝従来の認証経路を壊さない）挙動に戻っている。

企業デプロイでプロキシやゲートウェイ設定を握っている環境ほど刺さる回帰で、同日中にパッチが出た点も含めて「リリースの回転が速いぶん、認証や環境変数の互換性は毎版チェックが要る」という運用上の教訓がそのまま出た一件。2.1.x を追随している人は、飛ばさずに 266 まで上げておくのが無難だ。

  • Claude Code Changelog（2.1.266：CLAUDE_CODE_USE_GATEWAY 回帰の修正）

Codex：エージェントを"隔離された作業場"で走らせる

実験的 worktree 分離と、作業を止めずに質問に答えられる inline Q&A

OpenAI の Codex CLI は 0.154.0（9/9）で実験的な worktree サポートを入れた。新規セッションやフォークしたセッションに隔離されたチェックアウト（作業ディレクトリ）を割り当てられるようになり、複数のエージェント作業が同じリポジトリを踏み合わずに並走できる。あわせて、Codex が作業を続けたまま、途中の質問にインラインで答えても下書きが消えない挙動や、Vim モードの Replace（undo・ドットリピート対応）、Windows でのバックグラウンドサーバ共有も加わった。

先週の Vim 検索・undo/redo やプラグイン市場が「編集体験の作り込み」なら、今週は「エージェントを走らせる場所を分ける」方向。先週 Cursor が self-hosted machines で"実行基盤を自社に置く"を、今週 Codex が"作業ツリーを分ける"を——粒度は違えど、複数エージェントを安全に同時運用するための隔離という同じ課題に各社が寄っている。なお 0.153.x〜0.154.0 では GPT-6-Astra がモデルピッカーと Amazon Bedrock カタログに載り、既定モデルの選び方も整理された。

  • Codex Changelog（0.154.0：worktree 分離・inline Q&A、0.153.x：GPT-6-Astra）

OpenHands 1.0：自分のマシンで回せるエージェントが"production-ready"に

Docker サンドボックス・セキュリティポリシー込みの 1.0、SWE-bench Verified 約 68%

オープンソースの自律コーディングエージェント OpenHands が 1.0 に到達し、今週コミュニティで話題になった。本番運用向けの Docker サンドボックス、組み込みのセキュリティポリシー、リソース上限、プラグイン機構を備え、SWE-bench Verified を自律で約 68% 解く（Claude Opus 4.6 バックエンドで 68.4%）。有償の商用エージェントと"同じ土俵"のスコアを、自分のインフラ・自分の鍵のまま回せることが注目点だ。

刺さる文脈は明確で、Claude Code の --restricted・組織管理 MCP、Cursor の self-hosted machines、Codex の worktree 分離と、この夏の各プロダクトは揃って「エージェントに与える権限と、動かす場所を絞る」方向に来ていた。OpenHands 1.0 は、その"隔離・自己ホスト"の要求にオープンソース側からproduction-ready で応えた格好。コードや秘密情報を外に出せない組織にとって、商用 SaaS の代替として現実味を帯びる選択肢になってきた。

Devin：マルチ PR・マルチセッションの取り回しを整える

セッション archive で子 PR も自動クローズ、複数 PR のドロップダウン、キュー投入の生存

Cognition の Devin は 9/9 の更新で、派手な新機能より複数セッション・複数 PR を捌く UIを厚くした。セッションを archive すると、一緒に archive された子セッションの開いている PR も自動でクローズされ、複数 PR を持つセッションはサイドバーにPR ごとのドロップダウンが出る。Changes / PR タブのファイルパスはクリックで組み込みエディタの diff に飛べるようになり、キューに入れたメッセージがセッションのアイドル・再開をまたいで生き残るようになった。

先週の cleanup scan（デッドコード検出）や /scan の自動化が「エージェントの仕事を型に落とす」なら、今週はその仕事が生む大量の PR とセッションを、人間がどう見て回すかの整備。エージェントが一度に複数のタスク／PR を走らせる前提が当たり前になり、"束ねて管理する"側の作り込みが追いついてきた週と言える。
