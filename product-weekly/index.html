まとめ

今週の主役は Claude Opus 5 の投入（7/24）と、それが「プロダクトの中身」を一斉に入れ替えた動きだ。Claude Code は既定モデルが Opus 5（1M・high effort 既定）に切り替わり、同日のうちに Devin・Notion・CodeRabbit といった各コーディングプロダクトが差し替えを済ませた——モデルの発表より、プロダクトが足並みを揃えて乗せ替えた速さのほうが今週らしい。Claude Code 側は 2.1.219 で nested subagent（既定で深さ3）・厳格な allowlist・DirectoryAdded フックなどを積み、Anthropic の中の人は「新モデル向けに Claude Code のシステムプロンプトを約80%削った」知見まで公開した。プロトコル面では MCP が launch 以来最大の更新でステートレス化し、serverless/edge に置けるようになった。Codex 陣営も音声（GPT-Live）でのエージェント操作、CLI 0.146.0 のプラグイン・マーケットプレイス、Codex Security CLI の OSS 化と並走。Grok Build もプラグイン経済を広げ、Devin は初の"フロンティア級"OSS モデル Kimi K3 を載せた。

Claude Code

既定モデルが Opus 5 に——high effort 既定、Fast モード、/claude-api migrate

7/24、Claude Opus 5 が Claude Code とプラットフォームに投入され、Opus クラスの既定モデルが Opus 5（1M コンテキスト）に切り替わった。Claude Code では 既定で high effort で走り、難しい問題では上げ、速く安く回したいときは下げる、という調整が前提になっている。約2.5倍速の Fast モードも用意され、既存ワークロードの移行は Claude Code 内で /claude-api migrate（組み込み claude-api skill がモデル文字列を更新し、Opus 5 向けのプロンプト改善も提案）で済む。単に /model claude-opus-5 で切り替えることもできる。

プロダクト目線で効くのは、中の人の実感の共有だ。Anthropic の Boris Cherny は「Opus 5 はコーディング・データ分析・設計・ナレッジワークに強いが、それ以上に嬉しいのはこれまでで最も prompt injection に強いモデルだという点」と述べ、エージェントに長く任せるうえでの安全余裕を強調した。Thomas（trq212）は「Claude 5 ファミリーを綺麗に締めくくる一台。素晴らしい daily driver で、計画・ブレスト・最難のバグ潰しは Fable と組ませるのが良い」と、Opus 5＋Fable の役割分担を勧めている。

  • @ClaudeDevs — /claude-api migrate で既存ワークロードを移行
  • @bcherny — 最も prompt injection に強いモデル
  • @trq212 — Opus 5 は daily driver、Fable と組ませる

2.1.219／2.1.220——nested subagent（深さ3）、厳格 allowlist、DirectoryAdded フック

この一週間の CLI は 2.1.219 と 2.1.220 の 2 本。目玉の 2.1.219 は 27 の変更を含み、Opus 5 を既定に切り替えたうえで土台を広げた。(1) subagent が入れ子でさらに subagent を起動できるようになり、既定で深さ3まで。あわせて stream-json 出力で nested subagent がフォワードされる。(2) sandbox.network.strictAllowlist を追加し、allowlist に無いホストへのアクセスを確認プロンプトなしで拒否できる。(3) セッション途中でディレクトリを登録するための DirectoryAdded フックを新設。(4) ワークフローのサイズを動的に決める workflowSizeGuideline 設定を追加。fast モードからは Opus 4.7 が外れ、/fast は Opus 5 と Opus 4.8 に適用されるようになった。

翌日の 2.1.220 は 1 変更のみで、クラッシュ低減と応答の安定性向上に絞ったバグ修正リリース。派手な機能追加より、Opus 5 を既定にした直後の足元固めに寄せた一週間だった。

  • @ClaudeCodeLog — 2.1.219（Opus 5 既定・27 変更）
  • @ClaudeCodeLog — 2.1.219（strictAllowlist ほか）

「システムプロンプトを約80%削った」——新モデル向けの書き方の知見

Opus 5 世代に合わせ、Anthropic の Thomas（trq212）が「新しいモデル向けに Claude Code のシステムプロンプトを約80%削った。そこから、システムプロンプト・スキル・CLAUDE.md をどう書くかについて学んだことを共有する」と投稿し、今週の x で最大級の反響を集めた。モデルが賢くなるほど、細かく手取り足取り指示するより余計な足場を外したほうが良く動く——という方向で、指示文の"減らし方"が実務の関心事になっている。

Claude Code を長く使う側にとっては、CLAUDE.md やスキルを「盛る」よりも、新モデルに合わせて削ぎ落とす見直しが効く、という手触りの共有だ。プロダクトの新機能を追う一方で、同じプロダクトを新エンジン向けにどうチューニングするかに注目が移った。

  • @trq212 — Claude Code のシステムプロンプトを約80%削った

Opus 5、コーディングプロダクトに一斉展開

Devin・Notion・CodeRabbit が同日で差し替え

今週特徴的だったのは、Opus 5 が各プロダクトに発表当日ほぼ同時に載ったことだ。Cognition は「Claude Opus 5 が Devin で利用可能。FrontierCode 1.1 で Opus 5 は Fable 級の性能に半額で迫る」と告知。Notion は「今日の新モデル：Claude Opus 5 が Notion に入った」と即日対応を示し、ハードなタスク（複数ツールをまたぐ作業など）には最も undo 率の低い Opus モデルを、と使い分けを案内した。

コードレビューの CodeRabbit は自社ベンチで Opus 5 を計測し、「これまで測った中で最も的確で実行可能なコメントを書いた（自社ベースライン 35.2% に対し 39.3%）。一方で既知バグの検出は 61.1%→55.2% とやや落ちた」と、精度は上がったが取りこぼしは増えた、という具体的なトレードオフを公開した。モデルの是非というより、各プロダクトが「自分たちのベンチと使い方で測って即日採否を決める」体制になっている——という点がプロダクト視点での注目だ。

  • @cognition — Opus 5 が Devin で利用可能
  • @NotionHQ — Claude Opus 5 が Notion に
  • @coderabbitai — 自社レビューベンチでの Opus 5 計測

MCP がステートレスに——launch 以来最大のプロトコル更新

serverless／edge に置けるリモート MCP サーバへ

7/28、MCP の新版「MCP 2026-07-28」が公開され、launch 以来最大の更新として プロトコルがステートレス化した。これまでリモート MCP サーバの運用はセッション状態の管理が必要で、動かせる場所が制約されていた。ステートレスになったことで、serverless やエッジのインフラにデプロイしたり、任意のロードバランサーの背後で水平スケールさせたりできる。エージェントに繋ぐ外部ツールを"軽くどこでも"立てられる方向で、MCP サーバを配る側のプロダクト運用が一段楽になる。

あわせて拡張の正式な道として Extensions が用意された。例として (1) サンドボックス化した iframe 内でサーバ側描画の UI を出す「MCP Apps」、(2) 長時間・非同期の処理を扱う「Tasks」、(3) 「Enterprise Managed Auth」。認証まわりのハードニングと、正式な deprecation ポリシーの導入も含まれる。プロトコルとして"作り込んで長く使う"段階に入った格好だ。

  • @ClaudeDevs — MCP 2026-07-28 はステートレスに
  • @ClaudeDevs — serverless／edge にデプロイ可能
  • @ClaudeDevs — Extensions（MCP Apps／Tasks／Managed Auth）
  • @ClaudeDevs — 認証ハードニングと deprecation ポリシー

Codex 陣営：音声操作とプラグイン・マーケットプレイス

音声で複数エージェントを差配、CLI 0.146.0、Security CLI を OSS 化

OpenAI の Codex も並走した。まずデスクトップの ChatGPT Voice が GPT-Live で強化され、音声だけで PC を操作し、ChatGPT Work や Codex で走る複数エージェントを差配できるようになった（iOS からペアの遠隔アクセス経由でも可）。Codex アプリ 26.715 では macOS の最前面ウィンドウを文脈に取り込む screen context や複数フォルダ・プロジェクトが入り、CLI は 0.146.0 で named session・ピン留めスレッド・サイド会話、プラグイン manifest／workspace publishing／新しい marketplace、ページング付きの thread forking を追加。「1つのエージェント」から「複数を束ねて共有・再利用する」方向へ踏み込んでいる。

セキュリティ面では、OpenAI が Codex Security CLI を OSS 化した（npm i @openai/codex-security）。リポジトリのスキャン、実行をまたいだ検出結果の追跡、修正の検証、CI/CD へのセキュリティチェック追加ができる。先週の Anthropic「Claude Security」プラグインに続き、コーディングエージェントに脆弱性検出を組み込む動きが各社で並んだ——ただし OpenAI 側は最初から OSS として出した点が対照的だ。

  • @OpenAI — ChatGPT Voice で複数エージェントを操作
  • @Codex_Changelog — Codex app 26.715
  • @Codex_Changelog — Codex CLI 0.146.0（プラグイン marketplace ほか）
  • @OpenAI — Codex Security CLI を OSS 化

Grok Build のプラグイン経済と、Devin に載った初の"フロンティア級"OSS モデル

エージェントに"手足"を足す動きも続いた。xAI の Grok Build は公式プラグインを相次いで整え、Exa・Tavily・TinyFish といった web 検索／取得プラグインを追加。エージェントにリアルタイムの web 接続を与えるプラグイン経済が形になってきている。

Devin では、Cognition が Kimi K3 を Devin Desktop / CLI に追加した。FrontierCode 1.1 で「テストした中で初めてフロンティア級に迫った OSS モデル」と位置づけ、Devin 内ではバグの再現やコンテキスト管理に強いと報告している。基盤モデルのオープン化議論が業界で騒がしい一週間だったが、プロダクト側では「OSS モデルを実運用のエージェントにどう載せるか」という実装の話として着地した。
