プロダクトウォッチ

2026年9月17日（木） 過去1週間

まとめ

今週の主役は Claude Code の外にあった——Cursor が「Projects」を全ユーザーにベータ公開し、コードを書かない"コーディネーター"が数千のサブエージェントを自前 VM 上に配って回すという、エージェント運用のスケールを一段引き上げる賭けに出た。先週まで各社が固めていた「隔離された作業場でエージェントを走らせる」流れ（Codex の worktree、OpenHands 1.0）の、その先の"束ねて指揮する"層に踏み込んだ格好だ。対する Claude Code の一週間（2.1.269→2.1.274）は派手な新機能より足回りの徹底整備——claude plugin eval でプラグインを再現可能に採点し、auto モードのサブエージェント引き継ぎを安全分類器で検問し、Remote セッションで fast mode を解禁、組織向けに 料金 multiplier と omitClaudeMd を足し、最後は MCP 接続とトランスクリプトの自己修復で長時間運用を堅牢化した。Devin は Review に必ずセキュリティ検査を通すようにして"常駐レビュアー"の性格を強めた。要は、エージェントを「作れる」から「大量に・安全に・組織で回し続ける」段階へ、各社が一斉に配線を引き直した週だった。

Claude Code

`claude plugin eval` 登場——プラグインを"再現可能に採点"できるようになった 2.1.269

2.1.269（9/11）の目玉は claude plugin eval。プラグインの eval スイートを走らせ、スコア付き・再現可能な結果を JSON と HTML レポートで吐く。これまで Skill やサブエージェント、プラグインの"効き"は体感頼みで語られがちだったが、ここにきて「良し悪しを数字で回帰テストする」土台が公式に入った。同版では /output-style [name] で全セッション種別を横断して出力スタイルを一覧・切替できるようになり、Bash がファイルを編集した際に変更差分を表示する挙動、アーティファクトの同時ウォッチ上限を 5→10 に引き上げる更新も入った。Markdown をアーティファクトとして publish するとスタイル付きドキュメントとして描画されるようにもなっている。

刺さりどころは明快で、サブエージェントやスキルを"自作して積む"人ほど、次の課題は「積んだものが本当に良くなっているかを測る」ことだった。エンジニア界隈でも「ルールは Hooks/permissions、文脈知識は Skill、委譲境界は Subagent」と役割を整理する議論が定着しつつあり、plugin eval はその設計を検証可能にする一手。地味だが、エージェント構成を"感覚"から"計測"へ寄せる意味は大きい。

  • Claude Code Changelog（2.1.269：claude plugin eval・/output-style・アーティファクトウォッチ 10 件）

auto モードのサブエージェント引き継ぎを安全分類器で検問——"組織で・リモートで回す"足回りを増強

今週の Claude Code は、エージェントを大量・遠隔・組織で走らせる前提の配線を続けて足している。2.1.269 では auto モードの挙動が締められ、サブエージェントからの引き継ぎ（hand-back）を専用の呼び出し経由にして安全分類器でレビューするようになり、Monitor のウォッチにも必ず期限（最大 30 分、-p 実行では 10 分）が付いた。2.1.271（9/14）では Remote セッション（クラウド・self-hosted runner）でも fast mode が使えるようになり、エージェント定義に omitClaudeMd（ユーザー／プロジェクト／ローカルの CLAUDE.md を読み飛ばす）や、auto モード + サンドボックス下で Bash・PowerShell・Monitor にコマンド単位の allowed_domains を指定する制御が加わった。

組織運用向けも一段進み、マネージド設定の modelPricing に multiplier（1〜10）が入って社内チャージバックにマークアップを乗せられるようになり、2.1.273（9/15）では LLM ゲートウェイに x-claude-code-* のヒントヘッダを送る CLAUDE_CODE_GATEWAY_HINT_HEADERS=1 も追加された。先週が「プロンプトキャッシュの取りこぼし封鎖」なら、今週は「誰が・どこで・どの権限で走らせるか」を締める側の週。派手さはないが、Cursor Projects のような"大量並走"を安全に受け止めるための土台づくりが続いている。

  • Claude Code Changelog（2.1.269：auto モードの安全分類器・Monitor 期限、2.1.271：Remote の fast mode・omitClaudeMd・multiplier）

壊れたトランスクリプトが自己修復——2.1.274 は"長く回す"ための堅牢化

週末の 2.1.274（9/17）は、長時間セッションで効いてくる信頼性修正が並んだ。「unexpected tool_use_id」の 400 でリトライループに陥っていたセッションが解消され、壊れたトランスクリプトが自動で自己修復するようになった。MCP 周りも厚く、http 設定の MCP サーバが 422／4xx で繋がらない不具合、Streamable HTTP のツール呼び出しが 5 分で勝手にタイムアウトする問題、listChanged 宣言なしで prompts／resources が更新されない問題が一斉に直り、初回の非対話ターンで MCP 接続待ちを制御する CLAUDE_CODE_MCP_STARTUP_WAIT_MS が追加された。コンパクト済みセッションを再開すると /goal が失われる不具合や、self-hosted runner がトークン更新後に落ちる問題も修正されている。

メモリ逼迫時に「解放するか安全に再起動するか」を促す警告表示も入った。2.1.269 の git 権限確認の回帰を翌日 2.1.270 で即修正したのも含め、今週はリリース回転の速さと同じ速度でエッジケースを潰し続けた一週間。エージェントを何時間も・多数のツールと回すほど、この手の"取りこぼし修復"がそのまま体験の差になる。

Cursor Projects：コードを書かない"コーディネーター"が数千のサブエージェントを指揮する

機能・移行・アプリ丸ごとを月単位で回す——自前 VM 上の並列サブエージェントとイベント駆動

Cursor が 9/10、全ユーザー向けベータとして Projects を投入した。狙いは、機能追加・大規模移行・アプリ一式のような「一回のセッションに収まらない大きな仕事」を、数週間〜数ヶ月の文脈を保ったまま回すこと。中核がコーディネーターで、これは自分ではコードを書かず、計画を立て、実装を複数のエージェントに委譲し、仕上がりを人間のレビューに戻す——いわばプロジェクトマネージャ役だ。委譲先のサブエージェントはそれぞれ独立した VM 上で、プロジェクトの隔離コピーとクリーンな文脈を持って並列に走る。作業はクラウドで進むのでラップトップを閉じても止まらず、全エージェントは同期された共有コンテキスト（ファイル・調査結果・学習した好み）を参照し、その知識ベースは時間とともに育つ。

さらにコーディネーターは Slack チャンネル・スケジュール・プルリクエストを購読し、イベントを起点に自動で作業を切り出す。ここが今週の注目点で、この夏の各プロダクトが揃って進めてきた「エージェントを隔離した場所で走らせる」（Codex の worktree、OpenHands 1.0、Cursor 自身の self-hosted machines）の一歩先——「隔離した多数のエージェントを、誰が指揮して束ねるか」という指揮層に正面から踏み込んだ。"数千のサブエージェント"という表現は誇張含みに読むべきだが、方向としては明確で、個人が単発タスクを投げる道具から、常時走り続ける小さな開発チームを一人で運用する道具へと重心を移そうとしている。実際の使い勝手（コーディネーターの計画品質、レビューに戻る粒度、コスト）はこれから各所で検証されるが、"エージェントの UI の次"を最初に大きく提示したという意味で、今週いちばん議論を呼んだ動きだ。

Devin：レビューに必ずセキュリティ検査を通す"常駐レビュアー"へ

Devin Review が毎回セキュリティをチェック、Live Voice と 21 個の OAuth MCP で運用面も拡張

Cognition の Devin は 9/16 の更新で、Devin Review が毎レビューにセキュリティ検査を含めるようにした。任意のオプションではなく常に走るようにした点が肝で、エージェントが量産する PR を「マージ前に必ずセキュリティの目を通す」既定動作に格上げした格好。あわせて、ライブ音声モデルを使う Live Voice Mode、composer に入力し始めた時点でセッションが起動する挙動、VM を失ったセッションをサイドバーから再起動する導線などが入った。

連携面は 9/11 に厚く、Dropbox・ClickHouse・Coda など 21 個の OAuth MCP サーバをワンクリック接続できるようになり、PagerDuty 連携でインシデントを automation／oncall responder に紐付けられるようになった。API に冪等キーが入って重複セッション生成を防げるようにもなっている。先週の"複数 PR・複数セッションを捌く UI"に続き、今週は「レビューを厳格化しつつ、運用・インシデント対応の配線を増やす」方向——Claude Code の安全分類器や Cursor のイベント駆動と並べると、各社が揃って「エージェントを本番運用に耐える形に締める」ところへ来ているのが分かる。
