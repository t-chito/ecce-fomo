まとめ

今週の主役は Claude Code の Cloud セッションが research preview を抜けて正式リリースされたこと——ラップトップを閉じても Anthropic のインフラ上で作業が回り続け、CLI・モバイル・デスクトップから起動できるようになった。先週 Cursor が「コーディネーターが多数のエージェントを束ねる」構想を出したのに対し、Claude Code は自前で「常時走るクラウドの手元」を全ユーザーに開いた格好だ。同じ週に Opus 5.5 が Claude Code の既定モデルになり（Pro/Team でも Opus が既定に）、これに合わせて「plan mode を畳んで effort で深さを切り替える」「"よく考えて"は書かない・タスクを丸ごと渡す」という操作モデルの再設計が中の人・個人エンジニアの双方で議論に。足回りでは auto モードのサーバ側分類器化で分類コストが無料化し、AGENTS.md フォールバック対応、176 件の CLI 変更を積んだ 2.1.281 の再開・キャッシュ・MCP 周りの堅牢化が入った。外では Cursor が Rollouts と Security Review、CodeRabbit が Change Stack、Devin が GPT-6 の激安モデルと Microsoft 連携——各社そろって「エージェントが量産する PR を、本番前にどう検証・監視するか」のレビュー／運用層に軸足を移した一週間だった。

Claude Code

Cloud セッションが正式リリース——ラップトップを閉じても走り続ける"クラウドの手元"

9/23、Claude Code の Cloud セッションが research preview を抜けて正式リリースされた。作業は Anthropic ホストのインフラ上で進むため、ラップトップを閉じても止まらない。起動口は幅広く、CLI の claude --cloud、Claude モバイルアプリの Code タブ、デスクトップアプリのいずれからでも開始できる。ローカルで使用量の上限に当たっても、クラウド側に切り替えて続行できるのが実運用上の勘所だ。既存の Pro/Max 加入者にはワンタイムのクレジット（Pro $100・Max $250）が配られ、/claim-credit か告知リンクから申請する（GitHub 連携が必要、申請期限は 10/7）。翌日には「クレジットは任意の一回きり特典で、Cloud セッションはこれを先に消費してから通常プランの使用量に落ちる」と挙動を補足する訂正も出ており、"別課金の新機能"ではなく既存プランの延長線上にある点が強調された。

位置づけは明快で、先週 Cursor が「コードを書かないコーディネーターが多数のサブエージェントを束ねる」という指揮層の構想を出したのに対し、Claude Code は「いつでも走り続けるクラウド常駐の実行環境」を全ユーザーに正式開放した。あわせて週末の 2.1.281 では Cloud セッションに Fast mode の切り替えも追加され、リモートでも速度を選べるようになっている。夏以来の「隔離した場所でエージェントを走らせる」流れが、Claude Code では"手元を離れても続く既定の実行場所"という形で一段実用に寄った。

  • @ClaudeDevs: Cloud sessions are officially available and out of research preview（9/23）
  • @ClaudeDevs: クレジット申請（/claim-credit・GitHub 連携・10/7 期限）
  • @ClaudeDevs: クレジットは先に消費される任意特典という補足（9/24）

Opus 5.5 が既定に——"plan mode を畳んで effort で回す"へ、操作モデルの再設計が始まった

2.1.280（9/22）で Claude Opus 5.5（claude-opus-5-5）が Claude Code の既定 Opus モデルになり、Pro/Team Standard でも既定モデルが Opus に切り替わった。同版では新モデル向けの effort（思考の深さ）レベルの扱いも変更されている。公式の使い方指南（@ClaudeDevs）は今回のモデルの性格をよく表していて、曰く「タスクを丸ごと渡し、"done"の定義とチェックインの頃合いだけ決める」「"よく考えて"は書かない——常に先に考えるから」「長時間走らせた後は"次に進むのに何が要るか"を訊く」。考える量を減らしたいときも、プロンプトで頼むより effort を下げる方が確実に効く、というのが要点だ。

ここに plan mode の見直しが重なった。中の人（@trq212）が「plan mode を廃止し、shift+tab のホットキーで effort レベルを切り替える」案を投げ、「もうモデルに plan mode は要らないと思う」と踏み込んだ（plan mode 愛用者からの反対意見を募る形）。つまり「別モードで計画を立てさせる」から「深さのダイヤルを回して丸ごと任せる」へ、操作の中心が移りつつある。個人エンジニア側の反応も上々で、「Opus 5.5 は感触がかなりいい」「頼むからナーフしないでくれ」といった声や、effort/ハーネス設計を整理する解説（@oikon48）が広がった。モデルの実力が上がったぶん、プロンプトの小技より"どれだけ任せ、どこで戻すか"の設計が使い勝手を決める段階に来ている。

  • @ClaudeDevs: Try these in your first Opus 5.5 session（タスク丸投げ・"think carefully"不要・effort）
  • @trq212: plan mode 廃止と shift+tab での effort 切り替え案
  • Claude Code Changelog（2.1.280：Opus 5.5 を既定に・effort レベルの扱い変更）

分類コスト無料化・AGENTS.md 対応・176 件の 2.1.281——足回りは"安く・堅く"へ

週の足回りは、コストと堅牢性の両面で効く更新が続いた。2.1.278 で auto モードの分類器が既定でサーバ側実行になり、分類のための追加課金が発生しなくなった（/status に "Auto mode server" 行が追加）。先週が「auto モードのハンドバックを安全分類器で検問する」話だったのに対し、今週はその分類コストを利用者から外す方向で、無人・長時間運用のハードルを下げた。2.1.277（9/18）では CLAUDE.md が無い場合のフォールバックとして AGENTS.md を読む対応が入り、他ツールと設定ファイルを共有しやすくなった。2.1.275（9/17）は claude.ai 側の Skill/Plugin をターミナルセッションへ同期する導線を追加している。

週末の 2.1.281（9/23）は 176 件の CLI 変更を積んだ大型リリースで、中身の大半は「長く・遠隔で回す」ための取りこぼし修復だ。セッション再開まわり（過去ターンの再送、巨大セッションで末尾しか復元されない、権限プロンプトでプロンプトキャッシュを失う、ツール実行中に終了する等）と、プロキシ/ゲートウェイ経由でレスポンスが途中で切れて完了扱いになる／再試行がループする系の不具合が一斉に潰された。設定面では "attribution": false でコミット・PR の帰属表記を隠せるようになり、Claude Desktop 連携向けに blockReadsOutsideWorkingDirectories・disableBypassPermissionsMode といった安全側の締め付けも追加された。派手な新機能より、「大量に・遠隔で・組織で回し続ける」ための配線を今週も黙々と引き直した週だった。

  • Auto mode classifier billing（分類器の課金についての解説）

Claude Marketplace 開設——ツール・エージェント・パートナーの発見口

プラグイン/コネクタから"エージェントを買う"まで、Claude の拡張が一か所に

Anthropic は 9/23、Claude Marketplace を開いた。Slack や Notion のようなコネクタ・プラグインの追加に加え、Cursor や CrowdStrike といった企業のエージェント／プロダクトを購入したり、Accenture・Deloitte のようなサービスパートナーで導入をスケールさせたりできる発見口だ。作り手側は自分のツール・エージェント・サービスを出品できる。

Claude Code で Skill やサブエージェント、プラグインを自作して積む文化が広がるなか、次に効いてくるのは「良いものをどこで見つけ、どう配るか」という流通の問題だった。claude plugin eval による"採点"（先週）と合わせて、作る→測る→配るの導線がプラットフォーム側で一本につながり始めている。個人開発の Skill/Plugin を追う層にとっては、今後の配布・発見の起点になり得る動きだ。

  • @claudeai: Claude Marketplace でツール・エージェント・パートナーを発見（9/23）

レビューと本番運用の層が競争軸に——Cursor・CodeRabbit

Cursor が Rollouts と Security Review——デプロイ監視と PR セキュリティ検査を自動化

Cursor は 9/23、Teams/Enterprise 向けに 2 つの自動化ボットを投入した。Rollouts はデプロイ中の PR を監視し、環境をまたいで変更の健全性を追い、テレメトリと突き合わせて回帰を検知——問題を見つけると自動リバートまでトリガーできる。Security Review は PR を対象に SQL/コマンド/テンプレートのインジェクションや認証・認可のバイパスを解析し、深刻度付きの指摘と修正案を返す。チームごとに独自ルールも設定できる。いずれも 10 日間のトライアル用クレジット付きで即日提供。

先週 Devin が「Review に必ずセキュリティ検査を通す」常駐レビュアー化を進めたのに続き、今週は Cursor がセキュリティ検査＋デプロイ監視・自動リバートまで踏み込んだ。エージェントが PR を量産する前提が定着したいま、各社の勝負どころが生成そのものより"マージ前の検証"と"本番に出た後の監視"へと移っているのがはっきり分かる。

  • Cursor Changelog（9/23：Rollouts・Security Review）

CodeRabbit Change Stack——"何をマージしようとしているか"を理解してから承認する

CodeRabbit は Change Stack を発表した。狙いは、エージェントが数分で作る PR を、レビュアーが本当に理解してから承認できるようにすること。PR の目的・振る舞い・依存関係・コードを一つにつないで見せ、「自分が今マージしようとしているものを分かっているか？」を問い直させる。

Cursor の Security Review が「危険を機械が指摘する」側なら、Change Stack は「人が理解して責任を持って承認する」側を補強する。生成の速さがレビューの理解を置き去りにしがちな今の開発現場で、"承認の質"に照準を合わせた動きとして注目された。

  • @coderabbitai: CodeRabbit Change Stack（PR の目的・振る舞い・依存・コードを接続）

Devin：GPT-6 の激安モデルと Microsoft 運用連携

GPT-6 Sol/Luna を採用しコスト激減、Teams ネイティブ対応と M365 連携も

Cognition の Devin は 9/22、GPT-6 Sol と Luna を利用可能にした。同社の FrontierCode 1.1 で GPT-6 Sol は GPT-5.6 Sol と同スコアをタスク単価 61% 減で達成し、GPT-6 Luna は GPT-5.6 Luna を上回るスコアを約 1/4 のコストで出す——1 タスク $0.10 未満と、リーダーボード最安を主張する。エージェントを大量・常時走らせるほど効いてくる、運用コストの実弾だ。

運用連携も 9/23 に強化され、Microsoft Teams のネイティブ対応と、メール・カレンダー・ファイル・チャットにつなぐファーストパーティの Microsoft 365 連携が入った。「自分の PC でも Devin が動く」というローカル寄りの訴求に、企業のコラボ基盤への食い込みを重ねた形。安いモデルと業務連携の両輪で、"チームに常駐するエージェント"としての実運用に寄せている。

  • @cognition: GPT-6 Sol/Luna が Devin で利用可能に（コスト・FrontierCode 1.1）
  • @cognition: Teams ネイティブ対応・Microsoft 365 連携
