まとめ

今週の GitHub 週間トレンドは三つの流れが軸になった。ひとつは 「自律・長時間エージェントの土台」争い。今週最大の伸びは自己改善型コーディングエージェント PrimeIntellect-ai/prime-agent（週間 +12,476★・今週トップ）で、長時間エージェントの状態管理カーネル loopx、エージェントに計算環境を与える Cloudflare の computer が同じ週に並んだ。ふたつめは「スキル」配布への大手の参入で、Google 公式の google/skills（Google Cloud 向け 60+ スキル）と Addy Osmani の agent-skills（累計 8.7万★）が上位に食い込み、先週から続く reverse-skill・book-to-skill も伸び続けた。みっつめは文脈・記憶をグラフで持つ基盤で、説明可能性を掲げる semantica、モノレポ向け知識グラフ RAG の code-graph-rag、先週から続くチーム記憶ハブ TencentDB-Agent-Memory（週間 +5,388★）が並んだ。加えて OCR 不要の Rust 製 PDF 解析 pdf-inspector、ER 図エディタ drawdb、独立ブラウザ ladybird、そして manim・ComfyUI・ChinaTextbook といった定番の大型リポジトリも顔を出した。エージェント「本体」から「土台・スキル・記憶」へ関心が広がる構図が、先週よりさらに鮮明になった一週間だった。

自律・長時間エージェントの「土台」争い

PrimeIntellect-ai/prime-agent — 自己改善型のコーディング／長時間タスクエージェント（今週トップ・週間 +12,476★ / 累計 1.6万★）

今週いちばんスターを伸ばしたリポジトリ。ページ上部の説明は「A self-improving RLM agent for coding workflows and long-running autonomous tasks.」で、コーディングと長時間の自律タスクを自動化するオープンソースエージェント。二つの中核抽象を持つ——文脈を変数として、ツールを関数呼び出しとして扱う Recursive Language Model（RLM）と、再利用可能なプロンプトやスキルを蓄積・改良し続ける Continual Harness だ。

プログラム的にツールを実行する永続的な IPython 環境、並列・バックグラウンド作業のためのサブエージェント生成、切断をまたいでセッションを維持する detach／reattach、ターン・トークン・時間の予算を設定できる自律モード、エージェント同士の直接メッセージングとオーケストレーションなどを備える。ベースプロンプトを書き換えずに補助的なハーネス状態だけを改良できる点も特徴。主体は TypeScript/JavaScript（npm パッケージを含むモノレポ）、ライセンスは MIT。分散学習で知られる Prime Intellect 発の「セッションをまたいで学び続ける」エージェントが、今週の話題をさらった。

  • PrimeIntellect-ai/prime-agent

huangruiteng/loopx — 長時間エージェントのための状態カーネル（週間 +1,967★ / 累計 4.7千★）

複数プラットフォーム（Codex・Claude Code・Cursor）をまたいで長時間の AI エージェントワークフローを統治する、軽量な状態カーネル。ページ上部の説明は「The open, provider-neutral, stateful control plane for long-running agents.」で、目的・ゲート・実行可能タスク・証跡ログ・クォータ管理といった永続的な制御状態を保ちながら、異なるエージェントランタイムに区切られた「作業ターン」を実行させる。

単発の対話では、持続的な文脈・人間の判断ゲート・ピア間の引き継ぎ・支出管理を要する長期プロジェクトを扱えない。loopx は永続的なガバナンス層を実行ランタイムから切り離し、数日がかりのエンジニアリングループやエージェントチームでスコープ・証跡・意思決定履歴を保つことを狙う。曖昧な待機状態の代わりに明示的なユーザーゲートを置き、ピア所有権とリース管理付きの順序化された ToDo、暴走支出を防ぐクォータ対応スケジューリング、ローカルファースト・読み取り専用の制御平面などを備える。主体は Python 3.11+、ライセンスは MIT。prime-agent が「学び続ける本体」なら、こちらは「長時間ループを統治する層」で、同じ長時間エージェント熱の別の側面を押し上げた。

  • huangruiteng/loopx

cloudflare/computer — エージェントに「コンピュータ」を与える仮想ファイルシステム基盤（週間 +3,599★ / 累計 8.0千★）

ページ上部の説明は「Give your agent a computer 👾」。エージェントが複数のランタイム環境でコードを実行できるようにする仮想ファイルシステム基盤で、権威ある状態を Durable Object 内の SQLite に保持し、異なる計算バックエンド向けに差し替え可能な実行面を提供する。

実行バックエンドは三種類——FUSE マウントを伴う Container、Dynamic Worker 上で bash を動かす Isolate shell、ECMAScript モジュールの Isolate JavaScript。workspace.runtime.exec() という統一エントリポイント、SQLite 裏付けの永続ファイルシステム、複数の実行可能サンプル、MCP（Model Context Protocol）連携、ファイルシステム操作のベンチマークツールなどを備える。フル Linux コンテナから軽量な Workers まで、異種の環境でエージェントの負荷を動かす複雑さを、統一ファイルシステムインターフェースの背後に隠す設計。ただし README には Preview/Experimental で API は不安定・本番非対応と明記される。主体は TypeScript/JavaScript、ライセンスは MIT。Cloudflare がエッジ側から「エージェントの実行環境」に参入したことを示す。

  • cloudflare/computer

「スキル」配布に大手が参入

Google 公式の、Google 製品・技術（Google Cloud を含む）向け Agent Skills を集めたリポジトリ。ページ上部の説明は「This repository contains Agent Skills for Google products and technologies, including Google Cloud.」で、エージェントの能力を拡張する再利用可能なモジュールを、ゼロから作らずに使えるようにする。

AI/ML・インフラ・データベース・アナリティクス・セキュリティ・ウェブホスティングにわたる 60 以上のスキルを収め、RAG システムやデータサイエンスのパイプライン、AI エージェントのデプロイといった複合ワークフロー向けの解も含む。GKE・BigQuery・Firebase・Cloud Run などドメイン別に整理され、Claude・Codex・Antigravity CLI といったエージェントハーネスに対応、npx skills add google/skills で導入できる。ライセンスは Apache 2.0。先週まで個人開発者中心だった「スキル配布」の潮流に、プラットフォーマー自身が公式スキル集を出す動きが加わった。

  • google/skills

addyosmani/agent-skills — 「本番品質」のエンジニアリングスキル集（週間 +4,562★ / 累計 8.7万★）

Google Chrome チームの Addy Osmani による、AI コーディングエージェント向けのソフトウェアエンジニアリングのベストプラクティスを詰めたワークフローパッケージ。ページ上部の説明は「Production-grade engineering skills for AI coding agents.」で、要件定義からデプロイまでの開発ライフサイクル全体を、品質ゲート・テスト・セキュリティレビューを課す 24 の相互接続されたスキルで導く。

解こうとするのは「AI エージェントは厳密さより速さに流れ、仕様・テスト・セキュリティレビューを飛ばしがち」という課題。開発フェーズに対応する 8 個のスラッシュコマンド（/spec・/plan・/build・/test・/review・/ship ほか）、define〜ship の 24 スキル、コードレビュアー・テストエンジニア・セキュリティ監査官・ウェブ性能監査官の 4 専門ペルソナ、テスト／セキュリティ／性能／アクセシビリティの 7 チェックリストを備える。Claude Code・Cursor・Copilot・Cline・Codex・Gemini CLI ほか多数に対応。主体は Markdown、ライセンスは MIT。累計 8.7万★の巨大リポジトリが今週も +4,562★ と伸び、「スキルで規律を注入する」路線の代表格になった。

  • addyosmani/agent-skills

文脈・記憶をグラフで持つ

semantica-agi/semantica — 説明可能性を核に据えたグラフネイティブ基盤（週間 +4,073★ / 累計 7.2千★）

ページ上部の説明は「Graph-Native Infrastructure for Context and Accountable AI Systems」。決定の追跡や説明可能性を欠いたまま動く AI システムという課題に対し、LLM とベクトルストアの下に決定論的な基盤層を敷く。とくに、決定が規制当局の審査に耐える必要のある規制産業を意識する。

複数ソースの企業データから照会可能な文脈グラフを構築し、AI の決定を因果系譜つきの第一級オブジェクトとして記録、W3C PROV-O 準拠の来歴（provenance）トレイルを生成する。前向き連鎖・Rete・Datalog・SPARQL によるルールベース推論を LLM なしで実行し、データ競合の検出・解消やエンティティ解決も行う。Databricks（Unity Catalog）や Snowflake のネイティブコネクタ、RDF トリプルストア／ラベル付きプロパティグラフ／ベクトルストアを差し替え可能なポリグロット構成を持つ。topics には ai-governance・explainable-ai・graph-rag・provenance・reasoning などが並ぶ。主体は Python、ライセンスは MIT。「速く答える」より「後から説明・監査できる」ことに軸足を置く AI 基盤が、今週急伸した。

  • semantica-agi/semantica

vitali87/code-graph-rag — モノレポ向けの知識グラフ RAG（週間 +1,628★ / 累計 4.3千★）

ページ上部の説明は「The ultimate RAG for your monorepo. Query, understand, and edit multi-language codebases with the power of AI and knowledge graphs」。Tree-sitter で多言語ソースを解析し、Memgraph 上に知識グラフを構築、自然言語での照会と AI によるコード編集を可能にする RAG システム。混在言語のリポジトリを単一のグラフスキーマの下に統合する。

大規模で多言語なモノレポの探索・理解の難しさに対し、多言語 AST 解析と知識グラフ構築、自然言語クエリのグラフクエリ変換、ast-grep による構造的な検索・置換、代入や関数呼び出しをまたぐデータフロー追跡、AI 駆動のコード最適化とデッドコード検出、Claude Code など向けの MCP サーバー連携を提供する。topics には claude-code・knowledge-graph・mcp・rag・tree-sitter などが並ぶ。主体は Python、ライセンスは MIT。コードベースを「グラフとして持ってエージェントに渡す」アプローチが、記憶・文脈のトレンドと重なって伸びた。

  • vitali87/code-graph-rag

TencentCloud/TencentDB-Agent-Memory — チーム単位の記憶ハブは今週も上位（継続・週間 +5,388★ / 累計 2.2万★）

先週に続き今週も大きく伸びた、AI エージェント向けのチーム単位メモリ管理システム。README では「会話・ドキュメント・コードを、Chat Memory・Skill・LLM-Wiki・Code-Graph という 4 つの再利用可能な記憶資産に変え、ガバナンスのもとでエージェントやフレームワーク横断に共有・装備する」と説明する。

Chat Memory は L0〜L3 の多層で会話を蒸留し、Skill は会話から抽出した実行手順・検証ルール付きの再利用可能ワークフロー、Wiki は LLM 向けのリンクグラフ付き構造化ドキュメント、CodeGraph はシンボル・ファイル・呼び出し関係・影響分析をインデックスする。既存のコードベース・文書・会話履歴を取り込むコールドスタート機能や、チーム管理・資産整理・エージェントのロードアウト設定を行う Memory Hub UI も備える。topics には ai-agent・long-term-memory・vector-search・local-first などが並ぶ。主体は JavaScript/TypeScript、ライセンスは MIT。エージェントの「記憶をどう蓄え・共有するか」という層が、二週続けて支持を集めた。

  • TencentCloud/TencentDB-Agent-Memory

定番ツールと大型リポジトリ

firecrawl/pdf-inspector — OCR 不要の Rust 製 PDF 分類・抽出ライブラリ（週間 +3,251★ / 累計 1.5万★）

ページ上部の説明は「Fast Rust library for PDF classification and text extraction. Detects whether a PDF is text-based or scanned, extracts text with position awareness, and converts to clean Markdown — all without OCR.」。すべての PDF に高価な OCR をかけるのではなく、抽出可能なテキストを既に含む PDF を賢く見分けることで、OCR をスキップするスマートなルーティング判断を可能にする。README によれば約 54% の文書で OCR を省ける。

テキストベース・スキャン・画像・混在の分類（信頼度スコア付き）、フォント情報や座標を含む位置認識つきテキスト抽出、見出し・リスト・コードブロック・表に対応する Markdown 変換、矩形／ヒューリスティックの表検出、CID フォント対応、多段組の読み順検出、ブラウザ処理向けの WebAssembly 対応などを備え、ML モデルや外部依存を持たない軽量設計。主体は Rust（Python・Node.js・WASM バインディング付き）、ライセンスは MIT。Firecrawl 発の「OCR ルーティング」を核にした実務的な PDF ツールが伸びた。

  • firecrawl/pdf-inspector

drawdb-io/drawdb — ログイン不要の ER 図エディタ兼 SQL ジェネレータ（週間 +693★ / 累計 3.9万★）

ページ上部の説明は「Free, simple, and intuitive online database diagram editor and SQL generator.」。ブラウザ上で動く ER 図（ERD）エディタで、アカウント作成なしにデータベーススキーマを視覚的に設計できる。ドラッグ&ドロップでの図の作成、SQL スクリプトのエクスポート／インポート、マイグレーション生成に対応する。

PostgreSQL・MySQL・SQLite・MariaDB・Oracle・SQL Server など複数 DB をサポートし、IndexedDB によるローカル保存、サーバーを立てれば任意のファイル共有も可能。topics には database-schema・diagram-editor・erd・react・sql などが並ぶ。主体は JavaScript（React フロントエンド）、ライセンスは AGPL-3.0。手早くスキーマを描いて SQL に落とせる定番ツールが、今週もランキングに顔を出した。

  • drawdb-io/drawdb

LadybirdBrowser/ladybird — ゼロから作る独立ブラウザ（週間 +775★ / 累計 6.6万★）

ページ上部の説明は「Ladybird is a truly independent web browser, using a novel engine based on web standards.」。既存エンジンをフォーク・拡張するのではなく、ウェブ標準に基づく新しいレンダリングエンジンをゼロから構築する、pre-alpha 段階のブラウザプロジェクト。

UI・WebContent レンダラ・ImageDecoder・RequestServer を分離するマルチプロセス構成、サンドボックス化されたタブプロセス、悪意あるコンテンツへの耐性を高めるプロセス外の画像デコード・ネットワーク接続などを備える。LibWeb（描画）・LibJS（JavaScript エンジン）・LibWasm・LibCrypto/LibTLS・LibGfx といった自前ライブラリ群で構成される。主体は C++、ライセンスは BSD-2-Clause。「本当に独立した」ブラウザという稀少な立ち位置が、今週も継続的な支持を集めている。

  • LadybirdBrowser/ladybird
