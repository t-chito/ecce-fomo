まとめ

先週はエージェント「本体」の新顔ラッシュだったが、今週の主役はエージェントに配る「スキル」そのものに移った。Matt Pocock の skills（週間 +12,147★）を筆頭に、返答を要点先行に矯正する i-have-adhd、発散と枝刈りで発想を広げる adhd、技術書 PDF をスキルに変換する book-to-skill が揃ってランクイン。先週の「デザインをスキルで配る」流れが、集中・思考法・書籍知識まで一気に広がった週になった。もう一つの軸はRust 製ツールの上位独占で、今週の最大の伸びは人間とエージェントが同じ場で協働する自己ホスト基盤 block/buzz（週間 +12,444★・今週トップ）。Web フレームワーク topcoat、オフライン文法チェッカ harper も並んだ。さらに Alibaba 社内発の AI コードレビュー open-code-review、エージェント専用ブラウザ ego-lite、金融時系列の基盤モデル Kronos なども目立ち、先週からの pi・jcode・worldmonitor・OmniRoute も上位を維持した。

「スキル」がエージェント配布の主役に

mattpocock/skills — 実務エンジニア向けのスキル集（週間 +12,147★ / 累計 19.7万★）

Matt Pocock による、Claude Code や Codex などの AI コーディングアシスタント向けに再利用できるエージェントスキル（プロンプトのテンプレートとワークフロー）を束ねたコレクション。「意図と出力のズレ」「冗長さ」「バグ」「アーキテクチャの劣化」といった AI 支援開発で起きがちな失敗に対し、小さく・適応しやすく・組み合わせ可能な実践を、確立された工学原則に基づいて配ることを掲げる。

ユーザーが明示的に呼ぶスキルとして /grill-with-docs・/grill-me・/triage・/to-spec・/implement・/improve-codebase-architecture・/wayfinder を、モデル側が自動で呼ぶスキルとしてテスト駆動開発・デバッグ・コードレビュー・ドメインモデリング・プロトタイピング・リサーチを備える。導入時に課題管理先（GitHub・Linear・ローカルファイル）とトリアージ用ラベルを選ぶ構成で、Claude Code プラグイン（/plugin install mattpocock-skills）または npx skills@latest add mattpocock/skills で入れられる。主体は JavaScript/TypeScript、ライセンスは MIT。今週いちばん存在感を放った「スキルとしての実践の配布」の代表例だ。

  • mattpocock/skills

ayghri/i-have-adhd — 返答を「要点先行」に矯正するスキル（週間 +4,978★ / 累計 1.4万★）

Claude Code・Codex などのコーディングアシスタント向けに、AI の返答をより直接的で行動志向な形に整形するスキル/プラグイン。前置きの冗長さを嫌い、明快さを求める開発者を対象にする。

「まず行動から」始める応答フォーマット、番号付きの複数ステップ、脇道の情報の抑制、不要な締め文の排除を軸に、「次のアクションを先頭に置く」「具体的な次の一手で締める」「リスト項目は 5 個まで」など 10 の構造ルールを課す。README には冗長版から直接版へ変わる before/after の例が載り、「Hope this helps!」のような決まり文句を削る。/i-have-adhd コマンドで呼び出すか、fork してルールを自分好みに調整できる。設定は Markdown と JSON、ライセンスは MIT。「デザインの初期値を矯正する」先週の流れが、今週は「返答の作法を矯正する」方向へ広がった。

  • ayghri/i-have-adhd

UditAkhourii/adhd — 発散と枝刈りで発想を広げるスキル（週間 +791★ / 累計 2.9千★）

同じ「adhd」の名でも狙いは対照的で、こちらは Claude・Codex の Agent SDK 上に構築された「枝刈り付き Tree-of-Thought（思考の木）」の思考フレームワーク。設計判断・曖昧なデバッグ・命名・API 面の設計・戦略づくりといった、決まった正解のない創造的で開かれた問題を対象にする。

核となるのは二段構えの仕組みだ。発散フェーズでは、互いに文脈を共有しない N 本の並列・独立した推論プロセスを、それぞれ別の認知フレームで走らせ、アンカリング（引きずられ）を防ぐ。収束フェーズでは別の批評パスが、新規性・実現性・適合性の軸でアイデアを採点し、魅力的だが破綻したアイデアに理由付きで印を付け、近いものをまとめ、上位候補を深掘りする。「採点し、罠を刈り、生き残りを深める」という枝刈りが要だ。6 つの工学問題での評価で、単発ベースライン比 約2.9倍の新規性・5.2倍の罠検出を示すという。主体は TypeScript/Node.js、ライセンスは MIT。同名でも「要点を絞る」と「発想を広げる」が並び立つのが今週のスキル熱を象徴する。

  • UditAkhourii/adhd

virgiliojr94/book-to-skill — 技術書 PDF をスキルに変換（週間 +4,135★ / 累計 1.4万★）

技術書・文書・研究資料を、コーディングアシスタントで使える構造化されたエージェントスキルへ変換するツール。静的な PDF を、対話的に問い合わせられるリソースへ作り替えることで、知識の定着とアクセス性の問題に取り組む。

PDF・EPUB・DOCX・TXT・Markdown・reStructuredText・AsciiDoc・HTML・RTF・MOBI/AZW/AZW3 と多数の形式を処理し、中核メンタルモデル・章ごとのファイル・用語集・デザインパターン・クイックリファレンスへと整理して出力する。全文を一度に文脈へ流し込むのではなく章を必要時に読み込む設計で、典型的な問い合わせで「本を丸ごと文脈に入れる場合の約24〜51分の1」のトークン量で済むという。GitHub Copilot CLI・Amp・Claude Code など、オープンな Agent Skills 標準に対応する複数プラットフォームで動く。コードは Python、ライセンスは MIT（処理対象の書籍・文書自体には及ばない）。書籍の知識をスキルという形に落とし込む発想が、今週の潮流にもう一つの角度を加えた。

  • virgiliojr94/book-to-skill

Rust 製ツールが上位を占める

block/buzz — 人間とエージェントが同じ場で協働する基盤（今週トップ・週間 +12,444★ / 累計 1.9万★）

今週いちばんスターを集めたリポジトリ。Block, Inc. 発の、人間と AI エージェントが同じワークスペースで一緒に作るための自己ホスト可能なプラットフォームで、「A workspace where humans and agents build together」と位置づける。

Nostr リレーをベースにした統一イベントログを核に、メッセージ・反応・ワークフロー・Git イベントを、すべて署名された同じ種類のイベントとして記録する。エージェントは「ボット」ではなく独自の鍵と監査証跡を持つチームメンバーとして扱われ、会話・パッチ・ワークフロー実行・承認を一箇所から検索・監査できる。デスクトップ（Tauri + React）、モバイル（Flutter）、CLI（buzz-cli）とマルチプラットフォームに対応する。バックエンドは Rust、ライセンスは Apache 2.0。エージェント「本体」の競争が一巡した先で、人間との協働をどう記録・監査するかという土台づくりが今週の首位に立った。

tokio-rs/topcoat — Rust でフルスタック Web を作るフレームワーク（週間 +1,263★ / 累計 4.0千★）

Tokio チームによる、フルスタック Web アプリを作るための「モジュラーで全部入り」の Rust フレームワーク。シンプルさと生産性を重視し、サーバーサイドレンダリングと任意のクライアント対話性で完結したアプリを Rust で組めることを狙う。

Automattic/harper — オフライン・プライバシー重視の文法チェッカ（週間 +2,026★ / 累計 1.4万★）

Automattic による、オフラインでプライバシーファーストな英語文法チェッカ。データをサーバーに送る Grammarly や、メモリを食う LanguageTool の弱点への代替として設計された。

「高速・オープンソース・Rust 製」を掲げ、ミリ秒単位の校正と「LanguageTool の 50 分の 1 未満」というメモリ使用量、完全にプライベートなオフライン動作を売りにする。WebAssembly でブラウザ内でも動くほど小さく、VS Code・Neovim・Helix・Emacs・Zed など複数エディタに対応し、Obsidian プラグインと Language Server Protocol もサポートする。言語は Rust、ライセンスは Apache 2.0。現状は英語のみだが、他言語へ拡張できる設計だとする。Rust 製ツールが上位を占める今週の中で、地味だが実用的な一角を担った。

コードレビューとエージェント基盤

alibaba/open-code-review — Alibaba 社内発の AI コードレビュー（週間 +5,322★ / 累計 1.7万★）

Alibaba グループの社内公式 AI コードレビュー支援ツールを起源とし、数万人規模の開発者で検証したのちオープンソース化されたという、自動コードレビューの CLI ツール。Git の差分を解析し、変更されたファイルをツール利用能力を持つエージェント経由で設定可能な LLM に渡し、行レベルの精度で構造化されたレビューコメントを生成する。ファイル全体をスキャンする監査用途にも使える。

「決定的なパイプライン＋LLM エージェント」のハイブリッド構成、行レベルの正確なコメント、NPE・スレッド安全性・XSS・SQL インジェクションを狙った作り込み済みルールセットを持ち、OpenAI・Anthropic など複数の LLM プロバイダに対応する。Claude Code・Codex・Cursor と連携し、CI/CD にも組み込める。汎用エージェントとのベンチマークで「精度と F1 が大きく高く、トークン消費は約 9 分の 1」だとする。主体は Go（一部 TypeScript/JavaScript）、ライセンスは Apache 2.0。先週トップだったグラフ型の code-review-graph に続き、レビュー領域が今週も強い。

エージェント専用ブラウザ

citrolabs/ego-lite — エージェントとユーザーが同居できるブラウザ（週間 +5,037★ / 累計 6.8千★）

AI エージェントがブラウザ自動化を実行しつつ、ユーザーは同じブラウザで邪魔されずに作業を続けられる、エージェント専用のブラウザアプリ。Claude Code・Codex などのエージェントが Web タスクを自動化する際、ユーザー自身の閲覧とぶつからないよう切り分けることを主眼に置く。

「同じブラウザ・別のワークスペース」という設計で、エージェントは隔離された Spaces（同一ブラウザ内の並列ワークスペース）で並行してマルチタスクをこなす。Chrome のログイン・Cookie・拡張・ブックマークを引き継ぎ、AI が認識するための「市場最強のページ Snapshot」を掲げる。ego-browser スキル経由で任意のエージェント CLI から直接使え、CLI ベースではなくコードベースの手法で複雑なタスクを速く実行し、競合比「最大 2.5 倍速い」とする。言語は JavaScript、ライセンスは MIT。対応は現状 macOS で、Windows・Linux はロードマップ上にある。エージェントが増えるほど、その「手足」となるブラウザ層の需要も立ち上がることを示す。

  • citrolabs/ego-lite

デコーダのみの Transformer 構成を金融市場データで事前学習し、専用トークナイザで OHLCV（始値・高値・安値・終値・出来高）を離散トークンへ量子化してから自己回帰学習する二段フレームワークを取る。パラメータ数 4.1M〜499.2M の mini/small/base/large のモデル群、複数時系列を同時処理するバッチ予測、中国 A 株を例にしたファインチューニング手順、BTC/USDT の 24 時間予測ライブデモを備える。主体は Python、ライセンスは MIT。LLM 以外の基盤モデルもトレンドに食い込む流れが今週も続いた。
