非 LLM「Jev」の衝撃 ― 型付き・校正済み推論というもう一つの道

今週を単独で染めたテーマ。ChatGPT 開発に関わった Diogo Almeida が率いる TypeSafe AI が、LLM とは根本的に違う「System One Models」の第一弾「Jev」を 9 月 15 日に発表した。左から順にトークンを吐く LLM と違い、Jev はスキーマに沿った構造化出力を一度に返す。「文章は生成できない」代わりに、判断と確率を桁違いの速度・低コストで返す――入力は GPT-5.6 Terra 級の性能を約 1/100 のコストで、出力コストは実質ゼロ、ツール呼び出しのエラー率 0%、と謳う。記事群が共通して掴んでいるのは、これが「LLM の置き換え」ではなく「LLM に任せていた高速判断部分の切り出し」だという読みだ。状態取得やテキスト化は従来どおり LLM、次アクションを有限の選択肢から選ぶところを Jev が担う、という協働像で多くが一致している。

  • 構造化出力・確率つき・超高速という三点は多くの書き手が実際に叩いて確認している。mizchi は Jev 同士に五目並べ・MOBA を実時間で対戦させ、watany は「危険操作の分類ゲート」と要件ヒアリングの初期評価（8 問を 677ms・$0.00013 で処理し ADR 化）に組み込んだ。
  • 「プログラマは既存のチャットより構造化されたエージェントの方を好むだろう」という直感が繰り返し出てくる。Jev の値は決定的なガードレールやガバナンスを安価に置ける点にあり、Rust で書いていたような判定層を高速分類器で置き換えられる、という運用目線が強い。
  • 食い違いもはっきりある。懐疑側（nwn）は「LLM の 1 トークン目の logits を選択肢に射影し KV-cache で並列化すれば Gemma3 でも 77 倍速は出せる、Jev 固有の新しさは校正済み確率（Calibrated Probability）にこそある」と切り分け、DeepSeek V4 Flash の ~90ms 低遅延を挙げて「大手が標準 API で追随しうる」と長期の優位を保留する。「覇権を取るかは知らんが、構造化出力特化のモデルは残る」という醒めた見立てが全体のトーンを均している。

フロンティアモデルが「操作して仕事する」段階へ ― できると任せられるの距離

Jev の隣で、フロンティア LLM は「答える」から「PC を操作して仕事を終える」へ踏み込んだ。OpenAI の GPT-6 Astra は ScreenSpot-Pro 92.7%（前世代 76.9%）、ExploitBench 100%、ARC-AGI-3 で最大 99.9%（前世代 7.8%）と、画面操作・抽象推論のベンチを跳ね上げ、Blender で 3D を作り UE5 の空間を歩かせるデモまで見せた。別報では Astra が人間の助けなしにパズル FPS『Portal』をクリア（API コスト約 8 万 9 千円）。会社ごと AI に任せる Pion は、メール・電話・ブラウザ・銀行機能を握って店舗やカフェを実運営する。「できる」の実演は一気に増えた。

  • ただし記事を束ねると、「できる」と「任せられる」の距離がテーマとして残る。Pion の店舗・カフェは「まだ黒字化していない」と明記され、Andon Labs 自身が「実験」と位置づける。OpenAI の「ナビエ・ストークス方程式の難問解決」主張には、他者の成果を流用した疑いが付いた。能力ベンチの上昇と、信頼・経済性・帰属の担保は別軌道で動いている。
  • 周辺のプロダクト化も速い。GPT-Live-1（音声エージェントの話し方を細かく制御）、ChatGPT Work の「ユーザーの文体を学んで再現」、DaVinci Resolve 21.1 が Claude / ChatGPT Codex と連携し映像編集を指示可能に――「操作させる」対象がクリエイティブ用途へ広がっている。

AI コーディングを組織で回す ― プロセス・機構・非決定なハーネス・コスト

「AI に作らせる」を組織で回すためのプロセス・ルール・機構・コストが、今週もまとまって入った。上流では、AI 前提で開発ライフサイクルごと組み直す AI-DLC（人間は What/Why と検証に退き、AI が How を分解、非機能要件が対話の中で自然に立ち上がる）や、フロントの仕様と実装を同じ語彙（Subject×Object×Verb）で書き、YAML と命名から責務を機械抽出して CI の品質ゲートにする提案が、「仕様と実装のズレを人手の目視でなく差分演算で突き合わせる」方向を示す。gherkin×Skills で E2E を自律実行させる試みも同じ流れ。

  • 足元のハーネスは、その理想ほど決定的ではない。パス指定の Claude Code Rules が「黙って発火しない」のは、隠れフラグ CLAUDE_CODE_THRIFTY_SONIC が cat/sed 読みを促し Read ツールに相乗りする発火経路を外すから――しかもセッション単位の A/B で挙動が割れる。ネストした CLAUDE.md は「その配下のファイルを Read した時に初めて」読まれ、以後同一セッションでは再読み込みされない。「機構で守る」前提のツール自体が、まだ観測しづらい非決定性を抱えているという現実が並ぶ。
  • コストと基盤の統制も具体化した。日本トレカセンターは全社 200 名に OpenCode を配り自前の LiteLLM ゲートウェイに通して、モデル選択と週次予算を会社側で握りコストを導入前の 1/10 以下に。Spotify は「大きなファイル読みや定型コード生成を軽量モデルへ委譲」する Portal でClaude 側トークンを平均約 90% 削減（350 行超の Read を機械的にブロックして委譲を強制）。Managed Agents の IaC 管理、使い勝手を増した Claude Code Desktop も同じ「回す道具を整える」棚。

図と可視化を「宣言」で書く ― 何を書き、どう見せるかは機械に

図・可視化・3D を巡って、「何を」だけ簡潔に書き、「どう見せるか」は機械に委ねるという共通形が立ち上がっている。可視化中間言語 Flint は、データの意味（「年月」「利益」）とチャート種別だけ指定すれば、軸・ラベル・余白・配色を意味から推論して Vega-Lite / ECharts / Chart.js の設定を吐く。TALA はホワイトボードの手描きに寄せた直交レイアウトで、対称性・流れ・クラスタリングを美的評価しながらアーキ図を自動配置する。ThoughtDAG は対話をコンテキスト単位で編集できるグラフに、gbdraw は論文の作図スクリプトをブラウザ内 Web アプリに変える。宣言と機構の分業という、前々からの「概念だけ書いて機構に任せる」志向の、表現側への延長だ。

  • ただし「機械に任せる」には再現性のコストが付く。TALA はランダム性を含むためノード 1 個の追加で図が大きく組み変わる――DAG 主体や大規模図には不向き、と作者自身が但し書きを添える。「毎回同じ絵が出る」ことと「良い絵が出る」ことは両立しない領域がある。
  • 3D は毛色の違う外れ値。「Astra に Blender を MCP で操作させる」よりコードで直接モデリングさせる方（Swift の Realitizer ライブラリ）がアプリ組み込みまで一貫する、という週末実験。面白いことに、3D 品質は Astra と Claude Opus 5 が拮抗する一方、ゲームのロジック設計は Opus 5 が上回った――モデルごとの得意分野が割れる観察が付く。

設計とデータの基礎を持ち直す ― 境界・構造・効き方

AI が実装を書く時代でも、境界・構造・データの効き方は人が判断軸を持つという基礎の棚が今週も厚い。モノリス分割では『ドメイン駆動トランスフォーメーション』の 6 つの指標（完了成果物の受け渡し、一方向の手渡し、担当部門の違い、用語の意味のズレ、扱う主題の差、リズムとトリガー）で、病院の予約〜処方の物語から受付→予診→診察→会計の境界を切り出す――「同じ"診断"でも事務と医師で意味が違う」ことが境界の合図になる。細かく割りすぎず大きめに切って運用で研ぐ、という勘所も共通する。

  • データ層の落とし穴を数値で確かめる姿勢も続く。JOIN のデカルト積問題を実測すると、兄弟テーブルを一度に結合しただけで結果 10 万行が 64 万行へ膨れ、ピークメモリは 69MB→417MB と約 6 倍に。対策はクエリ分割かページング、という当たり前を数字が裏打ちする。
  • 再利用可能な構造の語彙も拾い直す。GoF は 23 個を網羅せず、Strategy・Adapter・Facade・Observer・Factory Method といった実務で効く一群に絞るのが実践的、という整理。REST や 3 層アーキテクチャの入門、SendGrid→SES のコスト移行、グラフエンジニアリングの初手も同じ「土台を言葉にして持つ」棚に入る。

「ユーザー」に AI エージェントを含めて設計し直す

デザインの側から、「ユーザー」に AI エージェントを含めて設計し直す視点が二本立てで入った。NN/g 系の「AI エージェントもデジタルインタフェースの利用者だ」は、視覚（スクショ解析＝高コスト・脆い）・アクセシビリティツリー（HTML 構造＝効率的で堅い）・API 直叩きの三経路を並べ、アクセシビリティのために整えた意味的マークアップが、そのままエージェントにも読みやすいと説く。「コンテキストアーキテクチャ」は、プロンプト単体の工夫を超えて情報アーキテクチャの原則を AI システムへ適用する構えで、命名・語彙・記憶設計が出力を左右する（"reset-password" と名付ける方が "credential-recovery workflow" より効く、という具体）。WebMCP で自社 CMS のデザインエディタをエージェント操作可能にする実験は、その実装側の裏返しだ。

  • ただし「エージェント対応」には正当な抵抗理由もある、と 49 は明記する――広告モデルの保護、規制対応に必要な摩擦、独自データによる競争。全面的にエージェントへ開くのが常に善ではないという留保が、単純な「アクセシビリティは万能」論を締める。
  • 人間向けの UX 工芸も並走する。ダッシュボードは「誰の何の判断を助ける画面か」を決めてから作る（重要 KPI は左上、ビューは 2〜3 に絞る）、UX ライティングの実務 Q&A、Figma の同時編集を支える CRDT 同期設計――こちらは今週やや影が薄く、関心の重心がエージェント向けの再定義へ寄ったことがそのまま出ている。
