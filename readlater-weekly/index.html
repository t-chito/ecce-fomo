続報Jev が実装・ツール・競合を伴うエコシステムになった

前号で登場した Jev をめぐり、半月で周辺が一気に揃った。公式 SDK と互換のオープンウェイト実装 OpenJev は、トークンを生成せず、閉じた候補集合を 1 回の forward で採点するという性質が Jev の特徴（高速・スキーマ準拠・確率つき）をそのまま生むことを示し、Qwen2.5-7B で 1 問 74ms・64 問同時なら 7.9ms/問を実測した。難易度でモデルを振り分ける Jev Router、ローカル実行を支える Ollama 対応、そして Clef・d1・Jeff・Kev まで含む競合の登場で、「速い型付き判断」を機構として置ける土台が出揃った。

  • 周辺ツールが実用段階に入った。jev-lint はコードの命名やコメントが実装と食い違わないかを自然文ルールで採点し、約 9,800 行・23 ルールを 7.7 秒・約 8 円で検査する。jany は自然文を正しい CLI コマンドへ直し、曖昧な語だけを Jev に役割選択させる。Ollama v0.35 は Nimble などのローカル実行に対応した。
  • 競合は構造で割れる。プロプライエタリ API 型（Jev・d1）、27B ベースに LoRA や全微調整を乗せる型（Clef・Kev）、小型オープン型、非自己回帰の encoder 型（Laya）。d1 は HuggingFace の Decision Index で Jev 超えを謳い、多言語とプロンプトインジェクション耐性を強みに挙げる。
  • ただし横並び比較は難しい。比較記事は、出自の違うレイテンシ（Cloudflare は Jev を 524.1ms と測り公称 500ms 上限を超えた）は比較できないと指摘し、オープン実装も校正済み確率までは再現していないと釘を刺す。呼び出し側とモデルの間にルーティング層を挟み、ロックインを避ける設計を勧める。

続報Jev は最終判断でなく下流を止めるゲートで活きる

実地検証がまとまって入り、Jev の居場所がはっきりしてきた。RAG では、再ランクよりも「対象外の質問を門前払いする」「回答不能を検出して LLM 呼び出しをブロックする」といった下流抑止の位置で 7〜75 倍速・最大 75 倍安を出す。問い合わせ振り分けや LLM ジャッジでも、誤答スクリーニングや一次仕分けに効く。共通するのは、答えの根拠が入力の中にあり、有限の選択肢から選ぶ判断に限って安く速く確実、という線だ。逆に入力外の知識や先読み・記憶が要るタスク（株価予測、チェス、部分的な誤りの検出）では精度が落ちる。

  • 「できる」の派手な実演にも但し書きが付く。Jev はポケモン赤を 37 時間 40 分・約 260 円で殿堂入りさせたが、RAM から状態を抜く自作プログラム・移動の A* 探索・攻略ガイドという足場が前提で、個々のボタンを直接選ばせた初期構成ではマサラタウンから出られなかった。高水準の行動抽象がないと自律は成立しない。
  • 「任せられる」は確信度ゲートで作る。LLM ジャッジ比較では Jev は正答を誤判定せず 72 件中 64 件を的中させたが、「大部分正しいが一部だけ誤り」を 8 件見逃した。確率 0.2〜0.8 の不確実な判断だけ LLM へエスカレすれば、LLM 呼び出しを 12〜18% に抑えつつ精度 100% を保てる、という併用設計が繰り返し出てくる。
  • 批判側は冷静だ。ゲームでは日本からの約 260ms のレイテンシでリアルタイム制御が全滅し、DeepSeek の判断を LightGBM に蒸留すれば推論 0.249ms で全クリアできる――自然言語入力でない用途なら古典手法や蒸留で置換できると突く。別の一本は「生成しない＝革新的」を BERT・NLI と突き合わせて分解し、ラベル付きデータが既にあり分類が安定なら Jev へ置換する理由を無理に作るな、と締める。

新モデルの使い分けと Claude Code の作り込みが進む

Claude 側は新モデルと作り込みの両面で動いた。Sonnet 5.5 は前世代比 30% 高速・30% 安価で、知識労働や図表理解では GPT-6 Sol を上回り、エージェント系ベンチでは Opus 5.5 並みに達した（ただし推論 Max ではトークンを食い、Opus の検討が勧められる）。実務の使い分けでは、Opus 5.5 は手を止めて聞く回数が減り、取込済みの前例を自分で調べて「同じやり方でいいか」と前例つきで確認するように変わった――問いが「どうしますか」から「これでいいですか」へ、人の仕事が立案から承認へ寄ったという観察が印象的だ。

  • 作り込みの基盤は Claude Code Mods（Function Hooks）。TypeScript 関数をエンジンに直接ロードし、on("tool.call", {tool:"Bash"}) で rm -rf / を拒否したり、await next() の後に API キーを [REDACTED] へマスクしたりできる。/diff やテレメトリなど標準機能自体が Mod として実装され、prepend→user→append→builtin→core の 5 層で組織が両端を押さえる権限モデルを持つ。

AI 出力の信頼は検証の作り替えで担保する

AI が大量に書く前提で、テスト・レビュー・評価を作り替える記事が厚い。テストは「E2E かユニットか」の優劣でなくどの不具合を検出できるかで役割分担し、速くて原因を示せるテスト（型・lint・ユニット・PBT）が AI の反復フィードバックを担い、最大の投資はそもそも誤ったコードを書けなくする型設計（値オブジェクト＋判別可能 union で網羅を有限化）に置く、という整理が中心だ。テスト要求仕様（TRS）を設計書の前に挟めば、受け入れ基準 81 本からテストケース 360 件を生成でき、人は「書く」から「レビュー」へ回る。

  • レビューも観点を機構で分ける。敵対的レビューの実測では、85 件の差分への 99 回で確定した重大指摘 138 件のうち半数超の 72 件は単一レーンだけが検出しており、観点分離に意味があると示す。ただしコストは標準 code-review の約 9 倍で、適用は行数でなく「何に触るか（データ更新・計算ロジック・認可）」で切り分けよと結ぶ。
  • 評価そのものが不安定だという計測も出た。LLM-as-a-Judge では同一入力 3 回の一貫性が 50〜75%、生成側も同一プロンプト 9 回で成功率 0〜100% とブレる。対策は違反検出（LLM）と達成検証（決定論的な正規表現）を分離し、入力を凍結して 9 回再生成し ±30 点を超えた変化だけ本物とみなす、という設計だった。
  • 文章の質も機構で正す方向だ。AI-Slop 対策を禁止語リストでなく統語構造の病理（非生物主語＋身体性動詞、サ変名詞の過剰圧縮、架空の敵との否定対比）として捉える yomiyasu は、160 本のコーパスで単純正規表現の誤検出 95.8% を lookaround で 0% に抑え、減点式 Linter まで同梱する。「ユニットテスト不要論」への反論や「回答の前提を問う」技法も、同じ検証できる形にする関心に連なる。

設計とデータの基礎を数字と型で持ち直す

AI が実装を書く時代でも、基礎を数字と型で持ち直す棚が続く。B+ツリーが速いのはアルゴリズムの優秀さでなく、ノード 1 個をディスク I/O 単位（8kB ページ）に合わせて I/O 回数を減らす形だから、という一本は、1000 万件で二分木なら高さ 24 段・点検索で 24 ページ読むのに対し B+ツリーは高さ 3 段・計 4 回で済むことを、pgbench で高さ 3 段・shared hit=2／read=2 まで実測して見せる。型の責務を C#／Go／Rust／TS 横断で比べ、拡張メソッド・レシーバー・トレイトは「アクセス手段と用語が違うだけで実態は同じ」と整理する一本も、感覚でなく仕組みで設計を語る姿勢だ。

  • ボトルネックの捉え方も式になる。期日に爆発する爆弾でなく「放置すると改修速度がじわじわ落ちる構造」とみなし、事業の到達状態から逆算すれば候補が一度に 10 個ほど挙がる。最大流量グラフでは、劇的に 1 箇所を解消するより全辺を 1 ずつ上げ続ける方が時間積分した価値が大きい、という結論が面白い。
  • 思考と用語の土台も拾う。「具体と抽象」勉強会の参加記は、AI に任せられるかを自分で判断する力として具体⇄抽象の往復を据える（議論が目先に寄ってコアドメインやユビキタス言語を見落とした、という反省つき）。OIDC と SAML を IdP／SP・認証／認可・「SSO は仕組みであってプロトコルではない」まで解きほぐす初学者向け整理も同じ棚にある。

AI は業務フローの側から要件を立てて組み込む

AI の能力からでなく業務の側から組み込む、という要件定義の記事が揃った。サービスデザイン発想の 5 ステップ（As-Is フロー可視化→課題抽出→AI を一選択肢として役割を「代替」と「支援」に分ける→To-Be シナリオ→要件化）は、個別タスクの自動化より業務全体をどう変えるかに主眼を置く。非エンジニアが社内エンジニアと作ったニュースレター自動化（60 分→15 分）の当事者記録も、境界条件の明示と非機能要件（SLA・バリデーション・例外処理）の学びという同じ所に落ちる。

  • データ接続は「権限を継承したまま」が要点。Microsoft Work IQ は別途 RAG 基盤を建てずに M365 のメール・文書・会議へアクセスするが、アプリ専用権限でなくユーザー委任アクセスで動き、本人が直接触れない情報は Work IQ 経由でも取れない。REST API は取得専用で、作成・更新は MCP 系ツールが要る。
  • 分析の型もスキルに畳む。データサイエンス向けには「この手法ならこの図・値を必ず出す」という diagnostics を、5 つのルーターに束ねて 2 段のルーティングでコンテキスト肥大を避ける設計が示された。生成 AI へ送る前に正規表現で個人情報をマスクする雛形も、完全な匿名化でなく境界防御と割り切る。
