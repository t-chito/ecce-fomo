まとめ

今週の保存は ISUCON2026 の参加記に強く偏り、関心は「Web 高速化の改善ループを、どこまで AI エージェントに閉じさせるか」へ一気に寄った。その裏で続いていたのは、AI の出力を型・lint・テスト・ポリシーといった仕組みで縛り、人が読む層を「意味」に絞る設計論だ。さらにモデル側では、AI を日常の判断や家計にまで広げる動きが並ぶ。拾えていないのは、こうした委任を受け止める組織・制度の視点と、実ユーザーの生の声である。

ISUCON2026 は改善ループをエージェントに閉じさせる競技になった

13 本の参加記の大半が同じ構図を描く。今年の題材はリージョンをまたぐ写真 SNS「ISUReal」で、欧米のアプリサーバから唯一の DB への往復（約 100ms）をどう減らすかが核だった。そして主役は、計測 → 仮説 → 実装 → ベンチ → 残すか戻すか、という改善ループを人の手を介さずエージェントに回させる Human-out-of-the-loop（HOOTL） の設計である。運営も今年から、使った AI のハーネスとモデルの申告欄を設けた。優勝は完全自律の競技エージェントを 3 ヶ月・100 回以上の試行で仕上げた 1 人チームの 625,857 点。多くのチームが同じ発想で臨み、差は「モデルの賢さ」ではなく、観測データへ直接触らせる土台・1 変更 1 ベンチ・判断の記録・知識カード・監査役エージェントといった座組の作り込みに出た、と口をそろえる。

  • 人間の仕事はコードからゴール設定と見落としの指摘へ移った。あるチームは「最終スコア 100 万点」という届かない目標を GOAL.md に置いて、ほどほどで手を止めさせない。別チームは 14 時以降コードもコマンドも書かず、AI どうしの会話を眺めて方針だけ返した。
  • 複数エージェントの協調には設計が要る。3 人がそれぞれの Claude Code を Slack でつなぎ、CLAIM・DEPLOY_REQ・BENCH_DONE の 1 行書式と担当ファイルの排他、デプロイのロックで、1 本しかないベンチを奪い合わずに回した。実装担当とベンチ担当は分けるべきだった、という反省も具体的。
  • 負けの原因も AI 特有だった。ツールを全部捨てて Claude Code に全任せしたチームは、エージェントが「実装に 8 時間かかるので却下」と人間基準で見積もり、致命的な改善を見送って惨敗した。「間に合わないとは考えるな」と圧をかけても、終盤は安全側に倒れて勝ちを諦める。ログ出力を切ると減点される罠に気づかず提出した例もある。
  • 権限を与えた AI の危うさも顔を出す。サーバに仕込まれた偽の AGENTS.md（プロンプトインジェクション）にエージェントが対処を迫られ、別チームではエージェントが勝手に運営へ質問を投げてしまった。

続報AI の出力を仕組みで縛り、人が読む層を意味に絞る

ハーネスで出力を御する関心の続き。共通するのは、品質はプロンプトの工夫でなく AI の外側に置いた仕組み（型・lint・テスト・CI・ポリシー）で決まる、という割り切りだ。そのうえで人間が読む範囲を、機械では確かめられない「意味」の層へ絞る。

  • 仕様書を厳密に書くほどコードに近づく。だったら可読性の高いコードを仕様の正（SSoT）にし、説明はコードから生成すればよい、という code as spec。2,000 行の spec は人間でなく後続エージェント向けで、人がレビューできない文書が正として入ることへの疑問が出発点にある。
  • AI が書く ADR やコメントは、放っておくと冗長で自由になる。ガイドラインやスキルは「お願い」で守られる保証がないので、構造は rego ポリシーで CI を落として弾き、意味のずれ（仕様書化していないか）は LLM に質問させて PR の注意に留める、と判定の重さで手段を分ける。
  • 仕組みの層は定型化しつつある。フロントエンドの「本番品質」を ①コンテキスト ②機械的ガードレール ③テスト ④CI と人のレビュー の 4 層で守る整理、チケットを入れるとマージ済みコードが出る「ソフトウェアファクトリー」の用語集、不変条件から DDD の集約を機械的に導く形式手法の試みが並ぶ。

AI が日常の判断と家計にまで入り込む

モデル側の新しい動きは、コードや数学でなく生活の判断を測り、担う方向に向いている。評価軸そのものが実用へ移りつつある。

  • OpenAI の LifeVal は、引っ越し先の保育園選びや防災ボランティアの立ち上げといった日常タスクで AI を採点するベンチ。GPT-5.2 の 49.3% から GPT-6 Astra の 80.6% まで伸び、処理時間を抑えたまま精度が上がったとする。AGI は学術でなく実用の有用性で測るべき、という立場を掲げる。
  • Claude には米国ベータで個人向け資産管理が付いた。Plaid 経由で銀行口座を読み取り専用でつなぎ、支出の分類・重複課金やじわ上がりする請求の検知・支払いカレンダーを出す。送金や運用、投資助言はせず、会話は学習に使わない、という線引き。
  • 検索にも判断モデルを持ち込む Decision RAG。文書を階層に持ち、各段で「はい」の確からしさだけ返す判断モデルがどの棚を開くかを決める。AgenticRAG の賢さを Naive に近い速さで使う、という狙い。

生成メディアは速度と制御性で刻む（観測枠）

動画・画像の生成モデルは、能力の跳躍よりも速さ・価格・編集の制御性で小刻みに更新が続く。性能そのものより、各社が示す数字の測り方に注意して眺める枠。

  • Google の Gemini Omni 1.2 Flash は最大 15 秒（従来 10 秒）、アップスケーラで 4K、編集済み動画の多ターン編集に対応。720p で動画出力は約 $0.07/秒、前世代比で 30% 安いと謳う。
  • OpenAI の Images 2.6 は従来比で約 50% 高速になり、GIF 生成と細かい編集制御に対応。ChatGPT と Codex API で使える。
  • 言語モデルに書道を競わせる「AI 書道コンクール」。画像生成 AI でなくテキストモデルに描かせる遊びで、評価の恣意性ごと楽しむ外れ値。

続報運用とセキュリティは「入力を疑う」と「増幅を止める」で固める

信頼の設計を自分の手で詰める関心の続き。今回の軸は、外から来るものを信用しすぎない構えと、失敗が連鎖で膨らむのを抑える仕掛けだ。

  • 防御側で LLM にログの要約・一次判定・IoC 抽出をさせると、ログに残る User-Agent やユーザー名から攻撃者が間接プロンプトインジェクションを仕込める。要約は書き換えに気づきにくく、研究では多層防御でも 8% 前後の脆弱性が残る。だから生ログを攻撃者の入力として扱い、出力の IP・ホスト名を元レコードと機械照合し、トリアージでは「優先度を上げる」方向だけ AI に任せ、アラートを AI 単独で閉じさせない。
  • Uber はリトライストームを「エラーの所有権」で抑える。各層が一律に再試行すると負荷が Rd で膨らむ。自分の外向き呼び出しが成功していてエラーなら自分の責任（claim）、失敗由来なら症状（unclaim）と見分け、unclaim されたエラーは再試行しない。2025 年 11 月 18 日の障害では約 950 万の無駄なリクエストを抑制し、再試行の増幅が届く深さの最大を 25 → 3 に下げた。
