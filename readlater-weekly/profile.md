# 関心プロフィール

このファイルは「あとで読む」に保存した記事から読み取れる、現時点の関心と知識領域の地図である。時系列の記録ではなく、関心の構造を一枚で見渡すために随時書き換える。

## 中心にある関心: AI に「どこまで・どう任せるか」の設計

関心の芯は一貫して、委任を可能にするのは能力でなく**検証・権限・介入の設計**だ、という一点にある。今回この芯は、ISUCON2026 の参加記が大量に流れ込んだことで、**「改善のループをエージェントに閉じさせ、人はループの外に出る」**という具体像を一気に得た。

- **ループを閉じる座組が差を生む**。計測 → 仮説 → 実装 → ベンチ → 残すか戻すか、を人の手を介さず回させる Human-out-of-the-loop（HOOTL）に強く引き込まれている。多数の参加記が口をそろえるのは、差はモデルの賢さでなく、観測データへ直接触らせる土台・1 変更 1 ベンチ・判断の記録・知識カード・監査役エージェントといった**環境側の作り込み**だという点。前号までの「ハーネスで出力を縛る」「信頼するのは成果物」の軸が、競技という閉じた土俵で裸で確かめられた格好。
- **人の仕事はゴール設定と見落としの指摘へ**。届かない目標（「最終スコア 100 万点」）を置いて手を止めさせない、コードもコマンドも書かず AI どうしの会話を眺めて方針だけ返す、という「手放し方」に惹かれている。同時に、エージェントが人間基準の時間見積もりで致命的な改善を見送った敗因が、**任せる側が外すべき前提**を具体的に教えてくれた。
- **複数エージェントの協調は設計対象**。会話履歴を共有しないエージェントを Slack の 1 行書式と担当ファイルの排他、デプロイのロックで協調させる運用に関心。実装担当とベンチ担当を分けるべきだった、という反省まで含めて、エージェント群のオーケストレーションが新しい設計領域として立ち上がった。

## 続く関心: AI の出力を仕組みで縛り、人が読む層を「意味」に絞る

中心と地続きで、今号も厚い。品質はプロンプトの工夫でなく **AI の外側に置いた仕組み**（型・lint・テスト・CI・ポリシー）で決まる、という割り切りが共通する。そのうえで人が読む範囲を、機械で確かめられない層へ絞る方向が鋭くなった。

- **仕様を厳密に書くとコードになる → code as spec**。可読性の高いコードを仕様の正（SSoT）にし、説明はコードから生成する。人がレビューできない 2,000 行の spec への疑問が出発点で、「人間が全部読む前提を外す」という前号からの線の、設計ドキュメント版。
- **お願いでなくポリシーで縛る**。AI が書く ADR やコメントの劣化を、構造は rego で CI を落として弾き、意味のずれは LLM に質問させて PR の注意に留める、と**判定の重さで手段を分ける**発想に納得している。ガイドライン／スキルは守られる保証がない、という割り切りが効いている。
- **仕組みの層が定型化する**。フロントの「本番品質」を 4 層（コンテキスト・ガードレール・テスト・CI と人のレビュー）で守る整理、チケットを入れるとマージ済みコードが出る「ソフトウェアファクトリー」の用語集、不変条件から DDD の集約を機械的に導く形式手法。前号の「仕様書を AI への入力データとして設計する」が、ここに吸収されつつある。

## 新しく立ち上がった関心: AI が日常の判断と家計にまで入り込む

前号で太くなった「AI の判断そのものをどう信じるか」は、今号では**信頼・帰属の問いから、AI が担う対象そのものの移動**へ比重を移した。評価軸と機能が、コードや数学から生活へ下りてくる。

- **評価軸が生活へ**。OpenAI の LifeVal は保育園選びや防災ボランティアの立ち上げといった日常タスクで AI を採点する（GPT-5.2 の 49.3% → GPT-6 Astra の 80.6%）。AGI を学術でなく実用の有用性で測る、という立場に注目している。
- **読み取り専用の委任**。Claude の個人向け資産管理が、Plaid 経由で口座を読み取り専用につなぎ、送金・運用はせず会話も学習に使わない、と権限と帰属の線を引く。中心の「権限境界の設計」が、個人の金という生々しい対象で試されている。
- **判断モデルを検索に差す**。文章を書かず確からしさだけ返す判断モデルで、RAG の各段の棚を選ぶ Decision RAG。前号の「ジャッジの当たり外れを測る」線が、判断モデルを部品として使う方向へ分岐した。

## 続く関心: 運用とセキュリティを自分の手で固める

AI に任せきらず運用とセキュリティを手で確かめる関心は今号も残る。軸は**「外から来るものを疑う」と「失敗の増幅を止める」**。

- **入力を攻撃者のものとして扱う**。防御側で LLM にログを要約・一次判定させると、ログに残る文字列から間接プロンプトインジェクションが刺さる。多層防御でも 8% 前後残るので、生ログを攻撃者入力として扱い、出力を元レコードと機械照合し、アラートを AI 単独で閉じさせない。前号の「`.zshrc` を AI が読んで漏らす」と同じ、委任の拡大が攻撃面を広げるという軸。
- **増幅を所有権で止める**。Uber がリトライストームを「エラーの所有権」で抑える設計（claim / unclaim、増幅の届く深さを 25 → 3 に）。一律の再試行が R^d で膨らむのを、原因の切り分けで御する。

## 続く関心: 役割の再定義と、価値が返る場所

「人間は設計者・監督者へ回る」線は、ISUCON を通してさらに具体化した。優勝が「1 人会社で CTO 機能を提供する個人」だった事実が、作る量と成果は別で、止まる場所が上流（目標・戦況判断・見落としの発見）へ移るという前号からの観測を補強する。ゴールだけ渡して回し続ける、という運用そのものが、人の新しい持ち場の輪郭になっている。

## 休止・以前の関心

- **テストと CI の重心が「手元」と「網羅」へ**。前号で太かったこの線は、今号は AI 生成の Playwright テストを `waitForTimeout` 禁止などのルールで矯正する一本が小さく残った程度。関心自体は中心の「仕組みで縛る」に吸収されつつある。
- **設計とデータを数字と型で持ち直す／設計観の言語化**。前号の軸は、今号は code as spec と形式手法に形を変えて「仕様の言語化」として続いた。
- **表現を「宣言」で書く**、**設計対象としての"ユーザー"再定義**は今号も気配が薄く、休止気味。

## 周縁・外れ値

毛色の違うものを拾う雑食は健在。AI の周りで手を動かす小ネタ——自宅 GPU 1 枚の Kaggle に Slurm を持ち込む、Figma の同期を Node.js + WebSocket の最小構成で作る・Figma Motion を CSS で再現する、Claude Code でグラレコ風の AWS 構成マップを作る。AI 時代の文章術（読者とゴールを先に決めて削る）は、以前の「日本語 AI 臭さ・読みやすさ」の関心の名残。AI から離れて、歩くほど遅いランニングの認知機能への効果（筑波大ほか）、PdM の視界を開発の外へ広げる「コックピット」。

## まだ拾えていない視点

委任が「ループを閉じる」ところまで具体化した一方で、それを受け止める**組織・制度・帰属責任の設計論**は依然として宿題。エージェント群を人がどう束ね、失敗の責任をどこに置くかは、ISUCON の座組論の延長線上に見えているのに、制度側の一次情報が拾えていない。加えて、前号から持ち越しの**実ユーザーの生の声（インタビュー・行動データ）を一次で扱う視点**も、product cockpit が「情報を集める器」に触れたに留まり、まだ埋まっていない。
