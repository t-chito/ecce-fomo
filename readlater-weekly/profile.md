# 関心プロフィール

このファイルは「あとで読む」に保存した記事から読み取れる、現時点の関心と知識領域の地図である。時系列の記録ではなく、関心の構造を一枚で見渡すために随時書き換える。

## 中心にある関心: AIエージェントの運用設計 ―「回す人」を仕組みに置き換える

最も比重が大きい領域。かつては「エージェントに作らせる」ことが前提化し、関心は生成の前後の設計にあった。それが一段上がって**ループエンジニアリング**——人間が毎回プロンプトを打つ役から降り、エージェントを動かし続けるシステム全体を設計すること——が中心になった。そしていま、この中心は賛美から**批判と再定義のフェーズ**へ移りつつある。「ゴールまで自走するのは2023年からある発想で、新しいのはむしろ外側の運用ループ（Software Factory）だ」という問い直し、Anthropic のターン型／ゴール型／タイマー型／プロアクティブ型という4分類の受容、そして次の主戦場を「意図の獲得」に置く Inquiry Engineering の提案を選んで拾っている。ループを回すこと自体より、その手前（意図の引き出し）と後ろ（知見の恒久化）に力点が移った。

この中心は次のように枝分かれしている。

- **完了の定義と外部検証**。「自己申告で完了にさせない」が繰り返し現れる急所。受け入れ基準を最初に固定し、外部シグナルでのみ達成を判定する。今週はこれが「何を守るかを人の記憶の外に置く」形へ具体化した——仕様書と保証台帳をフェーズで交代させる GDD（保証駆動開発）、約100項目のチェックリスト＋AI スキャンで PII 送信まで検出するリリースハーネス（estie）、インシデントの外部品質を KPI として可視化し現場と経営をつなぐ EM の試み。台帳・ハーネス・KPI という「1枚のドキュメントや仕組み」で完了と品質を保証する方向。
- **手順と知識の注入、自己増殖・自動最適化、そして"どこに記憶を持つか"**。プロジェクト固有の流儀をスキルや SOP、hook に切り出し、CLAUDE.md は肥大化させない。育てたスキルを「測る」段階（skill-creator／darwin-skill／SkillOpt）を経て、今週は**記憶と状態をどこに置くか**という土台へ降りた。会話履歴をコンテキストに詰め込むと破綻する、を起点にした永続メモリの5パターン、RAG でなく取り込み時にページを作る LLM Wiki、そして MCP 2026-07-28 仕様がセッション ID を捨てて「状態＝サーバー発行のハンドルを持ち回る」ステートレス設計へ移ったこと。三つとも「状態をどこに持つか」で束ねられる。
- **単体の限界と、複数モデル・ハーネスでの補完、そしてその過信への警戒**。1体・1コンテキストは失速すると捉え、役割ごとにモデルを割り当てる Agent Team に関心がある一方、Fable 5 を再現しても「API で使えるなら単発のほうがバランスが良い」という醒めた実測やデバイアス Skill を選ぶ。複数化＝銀の弾丸ではなく、コストに見合うかを毎回測る対象という姿勢。
- **方法論と役割の再定義**。「人間は設計者・監督者に回る」が名前のついた方法論へ結晶した。AI に粗い初期実装を落とさせ人間が観測・分解・修正するメテオフォール開発、Prompt→Context→SDD→Agentic の4段階整理、そして Agentic UX の「意図の設計／環境の設計」という2境界。とくに前者は先週の Inquiry Engineering＝意図の獲得の直系で、人間の仕事を「作る」から「意図を与え・監督し・修正する」へ移す線が太くなっている。

トークン経済・コンテキスト効率（need-to-know で絞る、md2idx、サブエージェントへの委譲）は背景として維持。今週の「記憶・状態・プロトコル」はこの線の土台側への深掘りにあたる。

## 隣接する関心: AIの出力を「信頼可能」にする検証系

エージェント運用の「外部検証」が、コードレビューとテストの側で厚くなった領域。「AI が大量に書いたものを人間がどう保証するか」が一貫した問い。

- **レビュー**。汎用ツールが知らない「自社の方言」を規約化する道と、人手より安く確実な「決定的な審判」を機械に置く道（形式証明器、Salesforce の6サイクル収束）に加え、今週は**レビューを回し続ける運用経済**が入った。PR が4倍（月3,100本超）に増える中、AI レビュー基盤の1実行2〜4ドルという従量課金が「実行をためらう構造」を生むため、実行を開発者の定額サブスクへ載せ替える（dinii）、Claude Code Routines のサブスク枠でリポジトリ内レビュースキルを回す、といったコスト設計。あわせて GitHub 公式のスタック型 PR（gh-stack）で巨大 PR を分割し「レビューできる粒度」を保つ、という粒度設計も。検証を止めないための経済と分割。
- **量産される出力を捌く（新規で太い）**。「モデルが1回に出す量は増えるが読む側は変わらない」を前提に、AI の出力を圧縮・可視化・削減する関心が今週明確に立ち上がった。長いコメントは AI 自身の読解にも効いていなかったという実測（削れない理由まで解剖）、認知負荷研究を土台に成果物レビューの往復を助ける RHW、設計レビューを図つき HTML で返す improve-codebase-architecture、口癖をフックで置換する試み。これまでの「圧縮率・性能を鵜呑みにしない」態度を、出力の読みやすさの側へ延ばしたもの。
- **テスト**。「振る舞いの仕様としてのテスト」→「肥大化とどう向き合うか」（不安と実行時間をコンパスに、ミューテーションテスト、回帰・システムテストを設計された規律として）。量でなく設計の厳密さで測る、で一貫。今週は前面には出なかったが背景として維持。

## 基礎を固める関心: 設計原則と「構造で守る」実装

古典的な設計原則は「知っておくべき教養」ではなく**AIの大量出力を評価する物差し**として拾う姿勢が続く。ズレを規約でなく構造や型で機械的に防ぐ実装（仕様とコードのドリフトを ID＋ハッシュで検出、業務規約を言語の制約に格上げする JVM 言語、bulletproof-react ×オニオン）への関心を経て、今週は**アーキテクチャの前提を言葉にできること**へ向いた。『ソフトウェアアーキテクチャの基礎』を二人が別々に薦め、アーキテクチャを技術選定でなく**制約と品質特性の調整・トレードオフ**として捉え直す。フロントでは Feature-Sliced Design（Layers／Slices／Segments、依存ルールを ESLint で強制、段階導入）で責務の置き場所をレイヤーの制約に落とす。設計を感覚から卒業させ、判断軸を人ごとにブレさせない**共有可能な構造**へ、で束ねられる。

## 開発を経営・組織で捉える関心: 速度から統制へ、そして業務の再設計へ

先週はじめて入ったプロダクト・ビジネスの視点が、今週は**AI-BPR（AI 前提での業務そのものの再設計）**へ具体化して定着した。「AI を既存業務に差し込むだけでは足りない、役割分担ごと組み直す」を軸に、Observe→Shift→Simulate→Forecast の方法論、「強み起点」で心理的安全性を重視する従来 BPR との対比、人手不足を論拠に AI-BPR を組織生存の必須要件と位置づける覚悟までを拾う。統制と価値の断絶（74%が期待、実現は20%）、AI 推進の組織アンチパターン、規制産業（Jefferies）での統制と自律の両立といった、作り手の技術に閉じない論点への関心が定着しつつある。

## 育ってきた関心: AIと社会を「データ」で疑い、「制度・規範」で問う

作り手でも組織でもなく、AI が社会や既存の定説をどう動かすかを疑うマクロな視点。先々週の「ボットが web トラフィックの過半（58%）」「米英欧の労働統計に自動化ショック不在」「表形式 LLM が XGBoost を$2で上回る」という**データで通説を疑う**入口から、今週は**制度・規範**の側へ一歩進んだ。雇用では Anthropic 自身のデータが自社 CEO の「1〜5年で職の半数消滅」発言と真逆＝大量失業は起きていない、と先週の反証を継続。加えて AI ヌード化禁止法（xAI が定義の粗さ＝水着や政治風刺まで巻き込む点で反対・提訴）、GCC の「15行超の AI 生成コードは受け入れ拒否」ポリシーと、規制と受け入れ規範の設計そのものへ関心が伸びた。「みんなが信じる前提を測って疑う」態度が、制度の議論にまで開いてきた。

## テストへの関心（再掲・上の検証系に統合）

「正しさの確認」ではなく「品質を構造として設計し、人間にもAIにも渡す生きた仕様書」にする発想は健在。詳細は「AIの出力を信頼可能にする検証系」に統合した。

## フロントエンドと表現への関心: 制約を先に設計し、計測で確かめる

モダンCSS・レンダリング経路・コンポーネント設計を「人間が制約を先に設計する」軸で追う関心は続く。直近では useActionState でユーザー操作を妨げない UX を宣言的に作る、TypeScript 7.0（Go 製 tsgo）の型チェック速度を自前で実測する（公式の10倍は出ず約8倍）、Claude Code Desktop の Browser pane を Playwright と実機比較するなど、**自分で測って確かめる**基礎固めが中心だった。今週の Feature-Sliced Design は「構造で守る」側へ寄せて上に統合した。ツールの公称値を鵜呑みにしない慎重さは一貫している。

## 質への関心: 量より検証

AIで量を増やすこと自体には価値を置かず、人間が判断・検証できる形まで質を高めることに価値を置く。バージョン固定・実機/ソース照合・決定的チェック・別プロバイダでの相互評価といった、根拠の明示を伴うかで質を見分ける。この「量より検証」は、エージェント運用の外部検証、レビュー・テストの検証系、そしてマクロを疑う姿勢まで、いま複数の領域を貫く共通の根になっている。

## 周縁の関心

点在しつつ続く領域。Web・基盤の基礎とパフォーマンス（今週は N+1 を Valkey の GEO／ソート済み集合で約90倍に）、資格・学習法を仕組みに落とす線が今週は**学習の心理**へ深まった——「好きは生まれつきでなく成功体験の積み重ねで後天的に作れる」を自己効力感・自己決定理論で裏づけ、AI で「分かった」の回数を増やす戦略に落とす一本に反応。Anthropic Academy の Claude 101 受講記、リーダーの時間をタイムボクシングで守る実践も同じ働き方・学習の棚。ものづくりと公開の手軽さ（単一 HTML で動く Bento/Slides、SEO 自動化で11サイト一人運営、Lyria 3.5）は継続。神経科学（脳が訓練で処理経路を再配線し"真のマルチタスク"へ）のような毛色の違う外れ値も拾う雑食性は変わらない。

## まだ拾えていない視点

作り手偏重は、経営・統制、社会・マクロ、そして今週の規制・受け入れ規範（AI 規制訴訟・OSS の AI コードポリシー）でさらに和らいだ。規制・ガバナンスは「まだ届いていない」から「入口が開いた」へ進んだが、制度の設計論として深掘りするのはこれから。依然として手薄なのは、ユーザーリサーチやマーケティングといった**顧客解像度**の側（Agentic UX の「意図の設計」で片鱗は出たが、実ユーザーの声を扱う記事は少ない）と、AI 活用の**コスト構造・経済性**そのものを主題にした論考（レビュー代のサブスク相乗りで運用コストには触れ始めたが、単価・投資対効果の分析は薄い）。
