# 関心プロフィール

このファイルは「あとで読む」に保存した記事から読み取れる、現時点の関心と知識領域の地図である。時系列の記録ではなく、関心の構造を一枚で見渡すために随時書き換える。

## 中心にある関心: AIエージェントの運用設計 ―「回す人」を仕組みに置き換える

最も比重が大きい領域。かつては「エージェントに作らせる」ことが前提化し、関心は生成の前後の設計にあった。それが**ループエンジニアリング**（人間がプロンプトを打つ役から降り、動かし続けるシステム全体を設計する）へ上がり、賛美から批判と再定義のフェーズを経て、**「どこまで任せ、人間は何を握るか」という境界の設計**へ重心が移った。実装・探索・一次調査は AI に委ね、人間は判断・方向づけ・知識の構造化に退く、という線が一貫して太い。

この境界の議論に、今回は**「できる」と「任せられる」の距離**という新しい亀裂が加わった。GPT-6 Astra が PC 操作・抽象推論のベンチを跳ね上げ（ScreenSpot-Pro 92.7%、ARC-AGI-3 99.9%）、人間の助けなしに『Portal』をクリアし、会社ごと AI に運営させる Pion まで出た――能力の実演は一気に増えた。だが Pion の実店舗・カフェは「まだ黒字化していない」と明記され、Astra 由来の数学的難問解決の主張には流用疑惑が付く。**能力ベンチの上昇と、信頼・経済性・帰属の担保は別軌道で動いている**という醒めた読みが、境界設計の前提として立ち上がっている。任せられる範囲は「できるか」ではなく「外部から検証・統制できるか」で決まる、という以前からの姿勢の延長線上にある。

この中心は次のように枝分かれしている。

- **完了の定義と外部検証、"何を守るかを人の記憶の外に置く"**。「自己申告で完了にさせない」が繰り返し現れる急所。受け入れ基準を先に固定し外部シグナルで判定する。仕様書と保証台帳をフェーズで交代させる GDD、約100項目のチェックリスト＋AI スキャンでリリースを守るハーネス、インシデントを KPI 化する EM の試みといった「1枚のドキュメントや仕組み」で完了・品質を保証する方向へ具体化してきた。台帳・ハーネス・KPI の系譜。
- **知識と状態をどこに置くか、"構造化した知識"の実測優位**。プロジェクト固有の流儀をスキルや SOP、hook に切り出し CLAUDE.md は肥大化させない、を土台に、記憶と状態の置き場所（永続メモリのパターン、取り込み時にページを作る LLM Wiki、MCP のステートレス化）へ降りた。「社内知識を Skills に構造化すると都度検索を定量で上回る」という実測が象徴。AI Agent を「未オンボーディングの新入社員」と捉える比喩が続く。ここには今回、**情報アーキテクチャの原則を AI システムへ適用する「コンテキストアーキテクチャ」**（命名・語彙・記憶設計が出力を左右する。"reset-password" と名付ける方が効く）という、知識の置き場所論をさらに設計論へ引き上げる視点が加わった。
- **単体の限界と複数化への醒めた計測**。役割ごとにモデルを割り当てる Agent Team に関心がある一方、「API で使えるなら単発のほうがバランスが良い」という実測を選ぶ。複数化＝銀の弾丸ではなくコストに見合うかを毎回測る対象、という姿勢。Google ADK でエージェント品質を評価する実装のように、「効果を数えられる形にする」評価系への関心もここに連なる。
- **方法論と役割の再定義**。「人間は設計者・監督者に回る」が名前のついた方法論へ結晶してきた。今回の AI-DLC（AI 前提で開発ライフサイクルごと組み直し、人間は What/Why と検証に退き、AI が How を分解、非機能要件が対話中に立ち上がる）は、この直系。任せる範囲と渡す知識の形の設計へ、さらに進んだ。

トークン経済・コンテキスト効率（need-to-know で絞る、サブエージェントへの委譲）は背景として維持。

## 新しく立ち上がった関心: AIの「出力形式」を問う ― 型付き・校正済み推論という別の道

今回いちばん明確に立ち上がった一群で、日本語圏の一次検証記事が単独で群がった。TypeSafe AI の非 LLM モデル「Jev（System One Models）」――文章を吐かず、スキーマに沿った構造化出力を確率つきで一度に返す――を、多くの書き手が実際に叩いて検証している。関心の芯は「速い・安い」そのものより、**LLM に任せていた高速判断部分を切り出して機構に置ける**という運用像にある。状態取得やテキスト化は従来どおり LLM、次アクションを有限の選択肢から選ぶところを Jev が担う、という協働の見立てで多くが一致する。危険操作の分類ゲートや要件ヒアリングの初期評価（8 問を 677ms・$0.00013）に差す具体例が、その「決定的なガードレールを安価に置く」志向をよく表す。

同時に、この関心は**熱狂と距離を取る検証癖**とセットで動いている。懐疑側は「LLM の 1 トークン目の logits を選択肢へ射影し KV-cache で並列化すれば近い速度は出る、Jev 固有の新しさは校正済み確率（Calibrated Probability）にこそある」と切り分け、大手が標準 API で追随しうると長期優位を保留する。「覇権を取るかは知らんが構造化出力特化は残る」という見立てが全体のトーンを均す。これは後述の「質への関心（量より検証）」の直系で、**出力の形式そのものを設計変数として扱い、謳い文句を実測で校正する**という態度が、新しい対象（型付き・校正済み推論）に向いたもの。

## 隣接する関心: AIの出力を「信頼可能」にする検証系と、機構で整える運用

エージェント運用の「外部検証」が、コードレビュー・テスト・出力矯正の側で厚くなった領域。「AI が大量に書いたものを人間がどう保証するか」が一貫した問い。

- **レビューと仕様の機械照合**。汎用ツールが知らない自社の方言を規約化する道、機械に決定的な審判を置く道（形式証明器・収束するレビュー）に加え、今回は**仕様と実装を同じ語彙で書いて差分演算で突き合わせる**提案（フロントの責務を Subject×Object×Verb で書き、YAML と命名から機械抽出して CI の品質ゲートにする）が入った。目視レビューを決定的な照合へ寄せる方向。
- **量産される出力を機構で整える**。「モデルの判断に毎回頼らず機構でフィードバックを返す」線。hook で block を差し戻す、デザインシステムを Skill＋Lint で機械的に固める、AI 生成 MD/HTML を非破壊で直す、といった実装群に、今回は**「AI 臭さ」を抜く試行錯誤**（冗長さ・特定語の多用・過剰な強調をパターン化して禁止則に落とす）が加わり、出力の矯正が文体の質にまで及んだ。
- **テスト**。「振る舞いの仕様としてのテスト」→「肥大化とどう向き合うか」に、今回は**見積もりの式化**が加わった。テストケース数を「テストオブジェクト×テスト観点」の掛け算に分解し、勘を根拠のある式に変える。gherkin×Skills で E2E を自律実行させる試みと合わせ、テストを「数えられる／回せる」形にする関心。

## 基礎を固める関心: 設計原則と「概念・構造で守る」実装

古典的な設計原則を**AIの大量出力を評価する物差し**として拾う姿勢が続く。ズレを規約でなく構造や型で機械的に防ぐ実装への関心を経て、概念の切り方（注文と履行を別概念に切ると危ういクエリが消える、等）まで遡ってきた。今回は**境界とデータの効き方**の側で具体化した。モノリス分割を『ドメイン駆動トランスフォーメーション』の 6 指標（完了成果物の受け渡し、一方向の手渡し、担当部門の違い、用語の意味のズレ、扱う主題の差、リズムとトリガー）で切り出す手順、JOIN のデカルト積問題をメモリ実測（ピーク 69MB→417MB、約 6 倍）で突きつける一本、GoF を実務で効く一群（Strategy・Adapter・Facade・Observer・Factory Method）に絞る整理、REST や 3 層アーキの入門――「設計を感覚から卒業させ、判断軸を人ごとにブレさせない共有可能な構造（概念境界・型同期・依存方向・語彙）」で束ねられる系譜が続いている。

## 育ってきた関心: 「ユーザー」に AI エージェントを含めて設計し直す

前回芽生えた「プロダクトの芯・顧客解像度」の関心が、今回は**設計対象としての"ユーザー"の再定義**へ枝を伸ばした。AI エージェントもデジタルインタフェースの利用者だ、という視点（視覚解析・アクセシビリティツリー・API 直叩きの三経路。アクセシビリティのために整えた意味的マークアップが、そのままエージェントにも読みやすい）と、GUI ツールを WebMCP でエージェント操作可能にする実装が、UX とエージェント運用を橋渡しする。ここには**「全面的にエージェントへ開くのが常に善ではない」**という留保（広告モデルの保護、規制に必要な摩擦、独自データによる競争）も同時に入っており、単純なアクセシビリティ万能論には振れていない。人間向けの UX 工芸（ダッシュボードは「誰の何の判断を助ける画面か」から、UX ライティング、Figma の CRDT 同期）も並走するが、今回は影が薄く、重心がエージェント向けの再定義へ寄ったことがそのまま出た。作り手偏重だった関心が、顧客・そして"非人間の利用者"の側へ開いていく途上にある。

## 表現を「宣言」で書く関心: 何を書き、どう見せるかは機械に

図・可視化・3D を巡って、**宣言と機構の分業**という共通形が今回はっきり出た。可視化中間言語 Flint（データの意味とチャート種別だけ書けば軸・配色・余白はコンパイラが埋める）、アーキ図をホワイトボード風に自動配置する TALA、対話を編集可能なグラフに変える ThoughtDAG、コードで直接 3D をモデリングする試み。「概念だけ書いて機構に任せる」という設計側の志向が、表現の生成側へ延びたもの。ただし**「機械に任せる」には再現性のコストが付く**（TALA はノード 1 個追加で図が組み変わる。3D は Blender 操作 vs コード直接生成でトレードオフ、モデルごとに造形とゲーム設計の得意が割れる）という但し書きも同時に拾っており、「良い出力」と「毎回同じ出力」が両立しない領域への目配りがある。まだ周縁だが、上の検証系・基礎設計と地続きの、育ちつつある棚。

## 開発を経営・組織で捉える関心: 速度から統制へ、そしてコストの実務へ

プロダクト・ビジネスの視点は **AI-BPR（AI 前提での業務そのものの再設計）**として定着していた。「AI を既存業務に差し込むだけでは足りない、役割分担ごと組み直す」を軸に、統制と価値の断絶、規制産業での統制と自律の両立まで拾ってきた。今回はこの系が**運用コストの統制**という具体へ降りた。全社 200 名に AI エージェントを配り自前のゲートウェイ（LiteLLM）に通してモデル選択と週次予算を会社側で握りコストを 1/10 以下に落とす構成、大きなファイル読みや定型コード生成を軽量モデルへ委譲して主モデルのトークンを約 90% 削る手法。長らく「まだ拾えていない視点」に置いていた**コスト構造・経済性**が、ここで初めて主題として入ってきた。

## 質への関心: 量より検証

AIで量を増やすこと自体には価値を置かず、人間が判断・検証できる形まで質を高めることに価値を置く。バージョン固定・実機/ソース照合・決定的チェック・別プロバイダでの相互評価・自前の計測といった、根拠の明示を伴うかで質を見分ける。この「量より検証」は、エージェント運用の境界設計・知識の実測優位、レビュー/テストの検証系、基礎の概念設計、そして今回の**新モデル（Jev）の謳い文句を校正済み確率まで詰めて切り分ける態度**まで、いま複数の領域を貫く共通の根になっている。「できる」と「任せられる」を分けて測る姿勢もここから来ている。

## いったん休止した関心: AIと社会を「データ・制度」で問うマクロ視点

過去には雇用（Anthropic 自身のデータ vs 大量失業予言）・AI 規制・OSS の受け入れ規範と、制度・規範の側へ踏み込んでいた。今回もこの社会・マクロの記事はほぼ拾えていない。ただし「認知負債」を"仕組みを人が理解せぬまま動くコード"と定義し生成速度が理解速度を超えたことを危機とする一本、「AI に仕事を奪われない」と考える理由を語る一本が、**労働と理解の問い**という形で周縁に現れた。制度の設計論としての深掘りは引き続き宿題。

## 周縁の関心

点在しつつ続く領域。見積もり・キャリアの実務メモ（工数見積もりの本質、テスト観点の掛け算）、Claude Code の使いこなし（Desktop の機能、ネストした CLAUDE.md の読まれ方、Rules を黙って壊す隠れフラグ CLAUDE_CODE_THRIFTY_SONIC の特定）は道具の細部を試す関心として継続。加えて、**ハーネス自身が抱える非決定性**（機構で守る前提のツールが、セッション単位の A/B で挙動を割る）に一次で気づく目が育っている。音楽生成 AI（YuE2）、単一ファイルでアプリを持ち運ぶツール、画風プロンプト、AI ネイティブなデータ分析基盤、zip 不要になった GitHub Actions Artifact といった毛色の違う外れ値を拾う雑食性は変わらない。

## まだ拾えていない視点

作り手偏重は、顧客解像度・そして"AI をユーザーに含める"再定義でかなり和らいだ。今回はさらにコスト構造・経済性（ゲートウェイでの統制、トークン削減の実測）が主題として入り、長年の空白の一つが埋まり始めた。依然として薄いのは、実ユーザーの生の声（ユーザーインタビュー・行動データ）を一次で扱う視点と、前々から休止している**規制・ガバナンスの制度設計論**。また、フロンティアモデルの能力上昇に対する「信頼・帰属・安全」の制度的な担保（今回は流用疑惑・黒字化前という但し書きで気配だけ触れた）も、次に深掘りしたい空白として立ち上がってきた。
