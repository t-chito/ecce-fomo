# 関心プロフィール

このファイルは「あとで読む」に保存した記事から読み取れる、現時点の関心と知識領域の地図である。時系列の記録ではなく、関心の構造を一枚で見渡すために随時書き換える。

## 中心にある関心: AIエージェントの運用設計 ―「回す人」を仕組みに置き換える

最も比重が大きい領域。かつては「エージェントに作らせる」ことが前提化し、関心は生成の前後の設計にあった。それが**ループエンジニアリング**（人間がプロンプトを打つ役から降り、動かし続けるシステム全体を設計する）へ上がり、いまは賛美から**批判と再定義のフェーズ**を経て、**「どこまで任せ、人間は何を握るか」という境界の設計**へ重心が移っている。実装・探索・一次調査は AI に委ね、人間は判断・方向づけ・知識の構造化に退く——本番障害のトリアージを AI が13分で自動化し人間は最終決定を一文で下すだけ、という一次事例や、Anthropic の開発者5アーキタイプ（人間が計画判断の70%、AI が実装判断の80%）を「能力ポートフォリオの診断軸」として読む視点に、その線がはっきり出ている。

この中心は次のように枝分かれしている。

- **完了の定義と外部検証、そして"何を守るかを人の記憶の外に置く"**。「自己申告で完了にさせない」が繰り返し現れる急所。受け入れ基準を先に固定し外部シグナルで判定する。これは仕様書と保証台帳をフェーズで交代させる GDD、約100項目のチェックリスト＋AI スキャンで PII 送信まで検出するリリースハーネス（estie）、インシデントを KPI 化する EM の試みといった「1枚のドキュメントや仕組み」で完了・品質を保証する方向へ具体化してきた。台帳・ハーネス・KPI の系譜。
- **知識と状態をどこに置くか、そして"構造化した知識"の実測優位**。プロジェクト固有の流儀をスキルや SOP、hook に切り出し CLAUDE.md は肥大化させない、を土台に、記憶と状態の置き場所（永続メモリの5パターン、RAG でなく取り込み時にページを作る LLM Wiki、MCP 2026-07-28 のステートレス化＝状態＝ハンドル持ち回り）へ降りた。ここに「社内知識を Skills に構造化すると Notion 都度検索を定量で上回る」（松尾研: 正解率 33%→87.3%→96%、致命誤り 100%→42.2%→15.6%、トークン78%減）という実測が加わり、"都度検索の不確実性 vs 事前構造化"という軸が明確になった。AI Agent を「未オンボーディングの新入社員」と捉える比喩が象徴。
- **単体の限界と複数化への醒めた計測**。1体・1コンテキストは失速すると捉え役割ごとにモデルを割り当てる Agent Team に関心がある一方、「API で使えるなら単発のほうがバランスが良い」という実測やデバイアス Skill を選ぶ。複数化＝銀の弾丸ではなくコストに見合うかを毎回測る対象、という姿勢。
- **方法論と役割の再定義**。「人間は設計者・監督者に回る」が名前のついた方法論（AI に粗い初期実装を落とさせ人間が観測・分解・修正するメテオフォール開発、Prompt→Context→SDD→Agentic の4段階、Agentic UX の意図の設計／環境の設計）へ結晶した。今回の「境界の引き方」「5アーキタイプ＝能力ポートフォリオ」は、この人間の役割再定義の直系で、任せる範囲と渡す知識の形の設計へ進んだ。

トークン経済・コンテキスト効率（need-to-know で絞る、md2idx、サブエージェントへの委譲）は背景として維持。

## 隣接する関心: AIの出力を「信頼可能」にする検証系

エージェント運用の「外部検証」が、コードレビューとテストの側で厚くなった領域。「AI が大量に書いたものを人間がどう保証するか」が一貫した問い。今回は**観点の言語化と機構化**として深まった。

- **レビュー**。汎用ツールが知らない自社の方言を規約化する道、機械に決定的な審判を置く道（形式証明器・収束するレビュー）、レビューを回し続ける運用経済（1実行2〜4ドルをサブスクへ載せ替え、gh-stack で分割）に加え、今回は**レビューの観点そのものを定量分析**する一本が入った。ベテランの PR レビュー187件を分類するとバグ指摘は20%（5件に1件）に過ぎず、最多は「一貫性」と「契約の保存」で計33%が"今は壊れていないが将来の劣化を防ぐ"型、コメントの69%は差分外のファイル由来。レビューの価値がバグ検出より劣化防止にあることを数字で突きつける。
- **量産される出力を機構で整える**。「モデルの判断に毎回頼らず機構でフィードバックを返す」線が実装群として厚くなった。hook で block を差し戻す meiseki（textlint 決定論層のみ hook 化＋安全弁3つ）、デザインシステムを Skill＋Storybook MCP＋カスタム Lint（Biome/GritQL）で機械的に固める MOSH、AI 生成 MD/HTML を非破壊で直す WYSIWYG エディタ Velq、Playwright＋LLM のガイドを spec 再実行で乖離検知。これまでの「圧縮率・性能を鵜呑みにしない／規約より機構で当たる」を、出力の矯正・追従の側へ延ばしたもの。
- **テスト**。「振る舞いの仕様としてのテスト」→「肥大化とどう向き合うか」に、今回は**手段の使い分けと機構化**が加わった。AI 直接自動化は動的画面で行き詰まり「1ケースを最後まで通す／画面別に手段を分ける」へ転換、AI の価値は全自動化でなく失敗後の原因整理と保守サイクル短縮にある、という実測。VRT を撮影と比較の2関心に分け追加インフラ無しで baseline を GitHub artifact に置く設計判断も同じ棚。

## 基礎を固める関心: 設計原則と「概念・構造で守る」実装

古典的な設計原則を**AIの大量出力を評価する物差し**として拾う姿勢が続く。ズレを規約でなく構造や型で機械的に防ぐ実装への関心を経て、今回は**概念の切り方**まで遡った。注文 Order と履行 Fulfillment を別概念に切ると配送破損も分割発送もモデルを変えず表せ危ういクエリが消える、という「概念設計が未来の仕様を先取りする」具体例が核。あわせて、その概念を古くさせない機構（TypeScript の型からドメインモデル図／オブジェクト図を描く domain.storybook）、境界と依存方向で固める ERP 設計（D1 でなく Postgres＋Hyperdrive、必要な所だけ advisory lock、EVM 計算の一元化、契約 package の依存方向を CI 検査）、そしてトレードオフの語彙（『ソフトウェアアーキテクチャの基礎』の知識のピラミッド、幅＞深さ、0→1 は人間）、Strategy パターンでの開閉原則遵守。設計を感覚から卒業させ、判断軸を人ごとにブレさせない**共有可能な構造（概念境界・型同期・依存方向・語彙）**へ、で束ねられる。

## 新しく厚くなった関心: 基盤を「自分で測って」理解する

今回いちばん明確に立ち上がった一群。基盤の内部を公称値や通説でなく**数値・実演・試算で確かめる**。DB インデックスの比較回数（1000倍のデータでも約10回増）と効かない条件、Cloudflare 1.1.1.1 のキャッシュを1件953→420バイト・全体100TB 削るデータ構造最適化、OpenTelemetry を3層に立て Baggage の session.id を横断させる自動計装の実践、HTTP QUERY（RFC 10008）を FastAPI で実際に試すと分かる落とし穴、EC2 で「3年前払い＜スポット」を実証して"スポット最安"の通説を覆す試算。「ツールの公称値を鵜呑みにしない／自分で測って確かめる」という一貫した態度が、今回は応用や方法論でなく**基盤（DB・DNS・トレース・HTTP・クラウドコスト）の深掘り**として現れた。周縁で続いてきた Web・基盤のパフォーマンス関心（N+1 を Valkey で解く等）が、中心近くまで太くなったと見てよい。

## 育ってきた関心: プロダクトの芯と顧客解像度 ―「作れる時代」に残る人間の仕事

これまで手薄だった**ユーザー解像度・プロダクトの芯**が、今回まとまって入った。生成 AI にプロトタイプを頼むとありふれた一般解しか出ず、「5歳の子を持つ母親」という背景から本質ニーズ（子の将来につながる体験）を掘って初めて方向が定まった、という Goodpatch の具体例が象徴。プロトタイプは検証ツールから探索ツールへ変わったが**ユーザー理解の時間はむしろ増やすべき**、という主張。あわせて NN/g の2本（MVP を"構造化された実験"と定義しバリュー/ソリューション仮説を検証する、情報提供型マイクロコピーを明確さ→簡潔さ→個性の3C で評価する）と、AIっぽさの正体（完璧さと矛盾の同居・文脈の希薄さ・学習パターンの認知）を突く一本。共通するのは「AI で量産できるからこそ、何を検証するか・誰の本質ニーズか・どう人間味を残すかという価値の芯は人間が握る」。作り手偏重の関心が顧客・プロダクトの側へ開いた、育ちつつある芽。

## 開発を経営・組織で捉える関心: 速度から統制へ、そして業務の再設計へ

プロダクト・ビジネスの視点は **AI-BPR（AI 前提での業務そのものの再設計）**として定着していた。「AI を既存業務に差し込むだけでは足りない、役割分担ごと組み直す」を軸に、Observe→Shift→Simulate→Forecast、従来 BPR との対比、人手不足を論拠にした組織生存要件化、統制と価値の断絶（74%が期待・実現は20%）、規制産業での統制と自律の両立まで拾った。今回は前面には出なかったが、上の「顧客解像度」の芽と、下の「社会・制度」の休止とあわせて、作り手に閉じない視野は維持されている。

## いったん休止した関心: AIと社会を「データ・制度」で問うマクロ視点

前回は雇用（Anthropic 自身のデータ vs CEO の大量失業予言）・AI 規制（xAI のヌード化禁止法提訴）・OSS の受け入れ規範（GCC の15行ルール）と、**制度・規範**の側へ一歩進んでいた。今回はこの社会・マクロの記事をほぼ拾えていない。関心が消えたのではなく、今回の保存が基盤・検証・プロダクトへ偏った結果とみられる。「みんなが信じる前提を測って疑う」態度自体は、基盤の"通説を実測で覆す"（スポット最安の否定）や検証の"バグは5件に1件"に形を変えて生きている。制度の設計論としての深掘りは引き続き宿題。

## 質への関心: 量より検証

AIで量を増やすこと自体には価値を置かず、人間が判断・検証できる形まで質を高めることに価値を置く。バージョン固定・実機/ソース照合・決定的チェック・別プロバイダでの相互評価・自前の計測といった、根拠の明示を伴うかで質を見分ける。この「量より検証」は、エージェント運用の境界設計・知識の実測優位、レビュー/テストの検証系、基盤の自分で測る姿勢、そしてプロダクトの芯（検証すべき仮説）まで、いま複数の領域を貫く共通の根になっている。

## 周縁の関心

点在しつつ続く領域。資格・学習法を仕組みに落とす線は今回、工数見積もりの本質（変更箇所でなく"安全に完了させる作業全体"を見積もる）や、面接で退職理由を取り繕わず「どう考え行動したか」を示す、といったキャリアの実務メモへ広がった。学習の身体側では「睡眠不足時の20分運動が90分昼寝と同等の記憶効果」という研究。Claude Code の使いこなし（/watch-video の3処理深度、Concise 出力、VS Code の Hybrid Markdown）は道具の細部を試す関心として継続。金融 ML（Kaggle 予測コンペを"失敗の系譜"として設計者視点で読み解き、adaptive overfitting の理論まで辿る）や、音楽生成 AI・推論高速化・太陽物理・画像フォーマットのハックといった毛色の違う外れ値を拾う雑食性は変わらない。

## まだ拾えていない視点

作り手偏重は、経営・統制、社会・マクロ、そして今回の顧客解像度（本質ニーズ・MVP・マイクロコピー）でかなり和らいだ。顧客・プロダクトの側は「入口が開いた」段階で、実ユーザーの生の声（ユーザーインタビュー・行動データ）を一次で扱う記事はまだ少ない。依然として薄いのは、AI 活用の**コスト構造・経済性**を主題にした論考（レビュー代のサブスク相乗りや EC2 試算で運用コストには触れ始めたが、単価・投資対効果の体系的分析は薄い）と、前回開いた**規制・ガバナンスの制度設計論**（今回は休止）。この2つが次に埋めたい空白。
