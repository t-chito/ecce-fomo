# 関心プロフィール

このファイルは「あとで読む」に保存した記事から読み取れる、現時点の関心と知識領域の地図である。時系列の記録ではなく、関心の構造を一枚で見渡すために随時書き換える。

## 中心にある関心: AIエージェントの運用設計 ―「回す人」を仕組みに置き換える

最も比重が大きい領域。かつては「エージェントに作らせる」ことが前提化し、関心は生成の前後の設計にあった。それが一段上がって**ループエンジニアリング**——人間が毎回プロンプトを打つ役から降り、エージェントを動かし続けるシステム全体を設計すること——が中心になった。そしていま、この中心は賛美から**批判と再定義のフェーズ**へ移りつつある。「ゴールまで自走するのは2023年からある発想で、新しいのはむしろ外側の運用ループ（Software Factory）だ」という問い直し、Anthropic のターン型／ゴール型／タイマー型／プロアクティブ型という4分類の受容、そして次の主戦場を「意図の獲得」に置く Inquiry Engineering の提案を選んで拾っている。ループを回すこと自体より、その手前（意図の引き出し）と後ろ（知見の恒久化）に力点が移った。

この中心は次のように枝分かれしている。

- **完了の定義と外部検証**。「自己申告で完了にさせない」が繰り返し現れる急所。受け入れ基準を最初に固定し、test/lint/build の exit code や形式証明器のような外部シグナルでのみ達成を判定する。これは今週さらにコード品質の側（レビュー・テスト）へ降りてきている。
- **手順と知識の注入、そして自己増殖・自動最適化**。プロジェクト固有の流儀をスキルや SOP、hook に切り出し、CLAUDE.md は肥大化させない。さらに手順を書く作業自体をエージェントにやらせる自己増殖に踏み込み、いまは**育てたスキルを「測る」**段階に進んだ。skill-creator（平均±標準偏差での比較）、darwin-skill（ルーブリック採点＋hill-climbing）、SkillOpt（文書をNNの重みのように扱う）を並べ、「自動最適化の中身はほぼ深層学習の訓練ループ」という見立てに強く反応する。公式ベストプラクティスが「ドキュメントより先に評価を作れ」と訓練ループの順番を規定している、という読み替えに共感。
- **単体の限界と、複数モデル・ハーネスでの補完、そしてその過信への警戒**。1体・1コンテキストは失速する（Lead に情報が集中して取りこぼす）と捉え、役割ごとにモデルを割り当てる Agent Team に関心がある。一方で、Opus/Sonnet のハーネスで Fable 5 を再現しても「API で使えるなら単発のほうがバランスが良い」という醒めた実測や、結論を隠して上位モデルにセカンドオピニオンを求めるデバイアス Skill を選ぶ。複数化＝銀の弾丸ではなく、オーケストレーションのコストに見合うかを毎回測る対象、という姿勢。

トークン経済・コンテキスト効率（need-to-know で絞る、md2idx、サブエージェントへの委譲）は先週深掘りした線で、今週は前面には出なかったが背景として維持されている。

## 隣接する関心: AIの出力を「信頼可能」にする検証系

エージェント運用の「外部検証」が、コードレビューとテストの側で今週いちばん厚くなった領域。「AI が大量に書いたものを人間がどう保証するか」が一貫した問い。

- **レビュー**。方向は二つ。汎用ツールが知らない「自社の方言」を規約化する道（7年分の PR レビュー履歴を規約に変換。疑問形3割・55文字という暗黙知の可視化）と、人手より安く確実な「決定的な審判」を機械に置く道（形式証明器で人手の20〜40分の1のコスト、Salesforce の PR フィードバックが6サイクルで自己終了＝コミュニティ標準へ収束）。diff 上で AI と人間がコメントを書き合う hunk のような協業インターフェースも拾う。
- **テスト**。先週の「振る舞いの仕様としてのテスト」が「肥大化とどう向き合うか」に具体化。「不安」と「実行時間」をコンパスにする、粒度のトレードオフを実測する、ミューテーションテストで偽陰性を炙り出す（カバレッジ数値目標の空洞化への対抗、Meta の実践）、回帰テスト・システムテストを「対象外」を明示した設計された規律として捉え直す。量でなく設計の厳密さで測る、で一貫。

## 基礎を固める関心: 設計原則と「構造で守る」実装

古典的な設計原則は「知っておくべき教養」ではなく**AIの大量出力を評価する物差し**として拾う姿勢が続く。今週はさらに、ズレを規約でなく**構造や型で機械的に防ぐ**実装に寄った。仕様とコードのドリフトを ID＋ハッシュ＋Stop Hook で決定的に検出する（LLM に頼らない）、業務上の規約を言語の制約に格上げする JVM 言語、要件定義の整理手法（イベントストーミング／RDRA／ICONIX）、検索画面のUIをインデックス設計の観点からバックエンドが早期に口出しする、bulletproof-react にオニオンアーキテクチャを重ねて責務の置き場所を決める——いずれも「規約にとどまると毎回同じ判断が要る」問題への構造的な解として束ねて読める。

## 開発を経営・組織で捉える関心: 速度から統制へ、そして業務の再設計へ

先週はじめて入ったプロダクト・ビジネスの視点が、今週は**AI-BPR（AI 前提での業務そのものの再設計）**へ具体化して定着した。「AI を既存業務に差し込むだけでは足りない、役割分担ごと組み直す」を軸に、Observe→Shift→Simulate→Forecast の方法論、「強み起点」で心理的安全性を重視する従来 BPR との対比、人手不足を論拠に AI-BPR を組織生存の必須要件と位置づける覚悟までを拾う。統制と価値の断絶（74%が期待、実現は20%）、AI 推進の組織アンチパターン、規制産業（Jefferies）での統制と自律の両立といった、作り手の技術に閉じない論点への関心が定着しつつある。

## 新しく入ってきた関心: AIと社会のマクロを「データで疑う」

今週明確に立ち上がった角度。作り手でも組織でもなく、AI が社会や既存の定説をどう動かすかを**実データで疑う**マクロな視点。ボットが web トラフィックの過半（58%）を超え「デッドインターネット理論」が裏づけられつつあるという見立てと、米英欧の労働統計に「自動化ショックは現れていない」という反証が、AI の影響見積もりを真逆に振らせる。表形式 LLM が XGBoost を$2で再現可能に上回るという技術的定説の崩れも同じ棚に入れ、「みんなが信じる前提を測って疑う」という、作り手時代からの「量より検証」の態度のまま社会へ開いた点が新しい。

## テストへの関心（再掲・上の検証系に統合）

「正しさの確認」ではなく「品質を構造として設計し、人間にもAIにも渡す生きた仕様書」にする発想は健在。詳細は「AIの出力を信頼可能にする検証系」に統合した。

## フロントエンドと表現への関心: 制約を先に設計し、計測で確かめる

モダンCSS・レンダリング経路・コンポーネント設計を「人間が制約を先に設計する」軸で追う関心は続く。今週は useActionState でユーザー操作を妨げない UX を宣言的に作る、TypeScript 7.0（Go 製 tsgo）の型チェック速度を自前で実測する（公式の10倍は出ず約8倍、メモリは内部値と Max RSS を分けて読む）、Claude Code Desktop の Browser pane を Playwright と実機比較するなど、**自分で測って確かめる**基礎固めが中心。ツールの公称値を鵜呑みにしない慎重さが、圧縮率や性能一般への態度と一貫している。

## 質への関心: 量より検証

AIで量を増やすこと自体には価値を置かず、人間が判断・検証できる形まで質を高めることに価値を置く。バージョン固定・実機/ソース照合・決定的チェック・別プロバイダでの相互評価といった、根拠の明示を伴うかで質を見分ける。この「量より検証」は、エージェント運用の外部検証、レビュー・テストの検証系、そしてマクロを疑う姿勢まで、いま複数の領域を貫く共通の根になっている。

## 周縁の関心

点在しつつ続く領域。Web・基盤の基礎（CSRF、TCP/IP、AWS ネットワーク、SQL/NoSQL）、資格・学習法を仕組みに落とす（基本情報の学習法、忘却曲線で回す面接ドリル Skill）、ものづくりと公開の手軽さ（測定できるグラフRAG、P2P＋EOS でサーバ代0円、Cloudflare Drop、自然言語で作る WordPress、Castle Map）。そして「テックブログの高齢化」——採用・広報の整った記事ばかりで初心者の“気づき”を書く場が減る、という、AIが答えるから不要論への静かな反論に反応した点は、伝達と多様性への関心の表れ。

## まだ拾えていない視点

作り手偏重は、経営・統制、そして社会・マクロの視点が入ったことでかなり和らいだ。一方でユーザーリサーチやマーケティングといった顧客解像度の側、AI活用の倫理・規制・コスト構造そのものを主題にした論考は依然として手薄。マクロは「労働・トラフィック」という入口が開いたばかりで、規制やガバナンスの制度設計まではまだ届いていない。
