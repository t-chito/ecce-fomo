# 関心プロフィール

このファイルは「あとで読む」に保存した記事から読み取れる、現時点の関心と知識領域の地図である。時系列の記録ではなく、関心の構造を一枚で見渡すために随時書き換える。

## 中心にある関心: AI に「どこまで・どう任せるか」の設計

関心の芯は一貫して、委任を可能にするのは能力でなく**検証・権限・介入の設計**だ、という一点にある。ISUCON2026 を土台に得た「改善のループをエージェントに閉じさせ、人はループの外に出る」という具体像は、競技の外の日常開発へ広がり、**個人ハーネスと全社基盤の設計論**として立ち上がった。

- **ハーネスは「削る」方向に効く**。ISUCON の優勝者も感想戦の参加者も、作り込んだ full より素の bare が伸び、規約・手順・スキルを消すほどスコアが上がったと報告する。1 変更 1 ベンチ・フェーズ分割・探索記録といった人間向けの手順はトークンを食い、大きな書き直しを選ばせない。残す価値があったのは、目標を毎ターン入れ直す Stop フックと、頭打ちで観点を返す監査役だけ。前号までの「ハーネスで出力を縛る」から、「最低限だけ残して、あとはモデルに任せる」へ重心が移った。
- **差を生むのは環境側、とりわけ評価環境**。優勝者が最も手をかけたのは競技エージェントでなく、構成を同じ基準で比べる評価環境だった。評価環境のバグがエージェントの判断を誤らせる例まで出て、「測って比べないと分からない／その物差し自体が正しいかも疑う」という評価の難しさが前面に出た。
- **人の仕事はゴール設定と「どこを見るか」**。回数や手順を縛る指示は行動を変えず、「全てを疑って」「勝手に上限を決めるな」「マニュアルを読み直せ」といった視点を外から揺らす一言がスコアを跳ねさせた。同時に、エージェントは大胆なアーキテクチャ変更に保守的で、人間基準の工数見積もりで致命的な改善を却下する。任せる側が外すべき前提が具体的に見えてきた。
- **「プロンプトより構造」**。個人ハーネスは、規約の正本・タスク単位の記録・置き場・lint を外側に用意し、訂正の行き先を種類ごとに決める。別セッションのエージェントが決定の原文の行まで辿って矛盾を指摘できる。CLAUDE.md は「守られる保証のないコンテキスト」なので、確実に残すものは hook と lint に寄せる。人が止まってよいのは破壊的操作・外部送信・範囲変更・価値判断の4つだけに絞る。
- **全社基盤は「安全を by design で」作ることが性能に効く**。サンドボックスにクレデンシャルを置かず egress をプロキシで絞り、情報区分ごとのサービスアカウントで権限の抜け道を塞ぐ。安全側に倒しすぎると役に立たないエージェントになるので、できる限り多くのコンテキストを渡せるよう作り込む。pstack の思想（証拠がなければ完了と認めない・書いた本人に採点させない・足す前に引く）が、実運用のベースに入り始めた。

## 続く関心: AI の出力を検証の仕組みで縛り、人が読む層を「意味」に絞る

中心と地続きで今号も厚い。品質はプロンプトでなく **AI の外側に置いた仕組み**（型・lint・テスト・ポリシー）で決まる、という割り切りが共通する。そのうえで人が読む範囲を機械で確かめられない層へ絞る。

- **「実行させるな、コンパイルさせろ」**。AI に毎回やらせている判断を一度プログラムへ変える。演習データから全 E2E を生成するメタテスト、grep で悪いテストを検出、Stryker のミューテーションでテストの穴を測る。一度コンパイルすればトークンゼロで同じ結果が出る。
- **通ること・カバレッジは正しさを保証しない**。常に 500 を返すバグに 500 を期待するような無価値なテストが混じる。モックの制限や private を直接テストしないといったトレードオフの判断は人が担う。「AI は回り道をしない、回り道を選ぶのは人間」という定式が刺さった。
- **AI は「絞り込んだ候補の判定役」に落ち着く**。QA の事例は、プログラムで候補を絞ってから判断だけ任せ、AI が出した数字は検算する、毎回同じ答えが要る照合には AI を使わない、に収束した。
- **ルール自体も検査対象**。Turtle + lint で must/mustNot の矛盾や例外の抜けを CI で止める。コードを読まずにマージする no-look-merge は、品質確認だけでなく「見逃しの責任を組織が引き受ける」合意がないと成立しない、と論点が帰属責任へ伸びた。

## 続く関心: 判断モデルと、先回りする個人エージェント

前号の「判断モデルを検索に差す（Decision RAG）」が、実力検証と新しい使い手の両方で深まった。

- **Decision Model は速く安いが、得意・不得意がはっきり出る**。Jev・Decisions・Clef は、はっきりした欠陥検出や検索の事後フィルターでは最上位の生成 LLM と同程度で、応答 0.16 秒・費用は生成 LLM の 3〜25 分の 1。ただし条件を 1 つ削った微妙な情報不足は 8 割以上を見逃し、閾値は手元データで決め直す必要がある。判断モデルは万能でなく、使う段を選ぶ部品。
- **判断を前処理・検証に差し込む**。Gemini Decisions は動画を直接入力して道具や状態を判定、Jev×scikit-learn は問い合わせを確率特徴量に変えて分類器へ。文章を生成させず確率だけ取り出す使い方が広がる。
- **評価軸と機能が生活へ下りる／先回り型エージェント**。Meta の Muse は、承認を Sentinel が握り本物の認証情報を見せない権限設計の proactive エージェント。利用者が複数の個人 AI を役割分担させ、AI 同士をファイル越しに議論させる試みまで現れた。中心の「権限境界の設計」が、個人の生活という生々しい対象で試されている。

## 続く関心: 運用とセキュリティを自分の手で固める

任せる範囲が広がるほど攻撃面も広がる、という軸は今号も残る。重心は**「使い捨ての隔離環境」と「攻撃を自分のアプリに仕掛けさせる」**。

- **AI に自分のアプリを攻撃させる**。AI ペンテストの Shannon を、開発環境ごと EC2 に閉じ込め使い捨てで回す。実測は Rails アプリで約 2 時間・$110、攻撃の検証が費用の半分。ペンテストが定期健康診断になりつつある。
- **手元の仕組みで防御も固める**。おとり（Canarytokens）で不審アクセスを検知、コミット前フックで TruffleHog を走らせシークレット入りコミットを終了コード 2 で止める、自宅サーバーは Cloudflare Tunnel + Access でポートを開けず認証も肩代わりさせ、AI にはサービストークンと許可リストで絞った権限だけ渡す。委任の拡大が攻撃面を広げるという前号からの軸が、具体的な手当てに落ちてきた。

## 続く関心: 役割の再定義と、価値が返る場所

「人間は設計者・監督者へ回る」線は、工場のメタファーで具体化した。機能のデリバリーをラインと捉え、性能・品質を落とさず人間というボトルネックを取り除いて設備総合効率を上げるのが持ち場、という見立て。優勝が「評価の仕組みに最も手をかけた個人」だった事実や、個人が週 100 コミットを「意思決定だけ」で積む事例が、止まる場所が上流（目標・戦況判断・見落としの発見・帰属責任）へ移るという観測を補強する。「人間に残るのは意思決定とその源泉であるエゴ」という言い方も現れた。

## 基盤モデルと周辺プロダクトの動き（観測枠）

評価軸と機能が、学術やコードから生活・業務の実作業へ下りてくる。関心は性能そのものより、各社が出す数字の測り方と、何を自分の基盤に載せるかに向く。

- Anthropic: Claude Sheets / Whiteboards / Data で表計算・ボード・データ分析を Claude 内に取り込み。メモリは「Dreaming」で整理され、高性能モデルほどメモリで伸び、記録対象はモデルに選ばせた方がよい。
- AWS Emulator: 人間がコードに関与せず、数百の AI エージェント群が週末で構築。4 ゲートを通った修正だけマージする体制は、ISUCON の座組論と地続き。
- 観測の道具: 組織の Claude Code 利用を OpenTelemetry で自動収集（user.email・cost_usd 付き）。生成メディアは Suno の Visuals のように速さ・編集で小刻みに更新。

## 周縁・外れ値

雑食は健在。AI の外側の設計・デザイン論——デザインも制約・情報・評価・修正の 4 層の「ハーネス」で自社基準に収束させる、生産性を「速くやる」でなく「やらなかったことをやる＝提供価値の増幅」と捉える。設計の学び直し（最適化プロダクトの待ち時間 UX、DDD+CQRS+イベント駆動、クリーンアーキテクチャ）は「AI に任せる前に境目を人が決める」線と地続き。手元の道具として、oxlint で lint を 50 倍速くする、Slack の Markdown 対応、自己ホスト推論の KV キャッシュを ElastiCache で共有して TTFT を短縮、Claude Code を会議に参加させる、といった小ネタ。

## 休止・以前の関心

- **テストと CI の重心が「手元」と「網羅」へ**、**設計とデータを数字と型で持ち直す**は、今号は「検証で縛る」「AI に任せる前に境目を人が決める」に吸収された。
- **AI が家計にまで入り込む**（読み取り専用の個人向け資産管理）は、今号は Muse など個人エージェント一般の権限設計へ形を変えた。
- **表現を「宣言」で書く**、**設計対象としての"ユーザー"再定義**は今号も気配が薄く、休止気味。

## まだ拾えていない視点

委任が「ループを閉じる」ところまで具体化し、no-look-merge で**帰属責任を組織がどう引き受けるか**が明確な論点に上がった。それでも、エージェント群を人がどう束ね、失敗の責任をどこに置くかという**組織・制度・帰属責任の設計論**の一次情報は依然として拾えていない。加えて、**実ユーザーの生の声（インタビュー・行動データ）を一次で扱う視点**も、デザインハーネスが「一次情報の取得に時間を移す」と触れたに留まり、まだ埋まっていない。
