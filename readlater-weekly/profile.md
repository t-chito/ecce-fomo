# 関心プロフィール

このファイルは「あとで読む」に保存した記事から読み取れる、現時点の関心と知識領域の地図である。時系列の記録ではなく、関心の構造を一枚で見渡すために随時書き換える。

## 中心にある関心: 型付き判断モデル（Jev / System One）を機構のどこに差すか

前回「新しく立ち上がった関心」として芽生えた Jev が、今回いちばんの比重を占める中心へ育った。関心は「これは何か」という驚きから、**どこに効き、どこで失敗するか**の見極めへ完全に移っている。Jev＝文章を吐かず、スキーマに沿った構造化出力を校正済み確率つきで一度に返す「System One Model」という理解を土台に、今回は三つの方向へ同時に枝を伸ばした。

- **エコシステム化**。公式 SDK と互換のオープンウェイト実装（OpenJev）、コードの命名・コメントの嘘を採点する jev-lint、自然文を CLI コマンドへ直す jany、難易度でモデルを振り分ける Jev Router、ローカル実行の Ollama 対応、そして Clef・d1・Jeff・Kev という競合まで、半月で周辺が出揃った。関心の芯は「速い型付き判断を機構として安価に置ける土台が実用段階に入った」点にある。競合は構造で割れる（プロプライエタリ API／27B＋LoRA／小型オープン／非自己回帰 encoder）という分類と、出自の違うレイテンシ数値は比較できない（Cloudflare は Jev を 524.1ms と測り公称 500ms を超えた）という冷静な切り分けも拾っている。
- **実地検証による線引き**。Jev が真価を出す位置は「最終判断」ではなく「下流を止めるゲート」――対象外の質問の門前払い、回答不能の検出による LLM 呼び出しブロック、誤答の一次スクリーニングで 7〜75 倍速・大幅コスト減。逆に入力外の知識・先読み・記憶が要るタスク（株価予測、チェス、部分的な誤りの検出）では落ちる。答えの根拠が入力（state）の中にあり、有限の選択肢から選ぶ判断に限って安く速く確実、という境界を、RAG・LLM ジャッジ・問い合わせ振り分け・RSS スコアリングの自前検証が繰り返し確かめた。
- **「できる」と「任せられる」の距離（継続）**。前回の亀裂がここでも効く。Jev はポケモン赤を 37 時間 40 分・約 260 円で殿堂入りさせたが、RAM から状態を抜く補助プログラム・A* 経路探索・攻略ガイドという足場が前提で、ボタンを直接選ばせた初期構成ではマサラタウンから出られなかった。高水準の行動抽象がなければ自律は成立しない。「任せられる」は確信度ゲート（確率 0.2〜0.8 だけ LLM へエスカレ）で作る、という併用設計がテーマとして定着した。

熱狂と距離を取る検証癖はさらに鋭くなった。ゲームでは日本からの約 260ms のレイテンシでリアルタイム制御が全滅し、DeepSeek の判断を LightGBM に蒸留すれば推論 0.249ms で全クリアできる――自然言語入力でないなら古典手法や蒸留で置換できる、という批判。「生成しない＝革新的」を BERT・NLI と突き合わせて分解し、ラベル付きデータが既にあり分類が安定なら Jev へ置換する理由を無理に作るな、という釘刺し。これらは後述の「質への関心（量より検証）」の直系である。

## 隣接する中心: AIエージェントの運用設計 ―「回す人」を仕組みに置き換える

長らく最大の比重だった領域で、今も太い。**ループエンジニアリング**（人間がプロンプトを打つ役から降り、動かし続けるシステム全体を設計する）から、**「どこまで任せ、人間は何を握るか」という境界の設計**へ重心が移り、いまは上の Jev の「機構のどこに差すか」と地続きになっている。実装・探索・一次調査は AI に委ね、人間は判断・方向づけ・知識の構造化に退く線が一貫して太い。

- **ハーネスを自分で作り込む**。今回は Claude Code Mods（Function Hooks）が入った。TypeScript 関数をエンジンに直接ロードし、`on("tool.call")` で危険操作を拒否したり、`await next()` 後に API キーをマスクしたりできる。標準機能自体が Mod として実装され、prepend→user→append→builtin→core の 5 層で組織が両端を押さえる権限モデルを持つ。「機構でフィードバックを返す／守る」志向が、ついにハーネスそのものの改造に届いた。Mods の `$.model.classify` や Jev で既存サブスク内にモデルルーターを作れるが、モデル切替でキャッシュが失効するため処理難度で分ける「エフォートルーター」へ落ち着く、という落とし穴も一次で踏んでいる。
- **方法論と役割の再定義（継続）**。「人間は設計者・監督者に回る」が AI-DLC などの方法論へ結晶してきた線。今回は Opus 5.5 の挙動変化という現場観察で具体化した――手を止めて聞く回数が減り、取込済みの前例を自分で調べて「同じやり方でいいか」と前例つきで確認する。問いが「どうしますか」から「これでいいですか」へ、人の仕事が立案から承認へ寄った。
- **知識をスキルに構造化（継続）**。プロジェクト固有の流儀を Skill に切り出す関心は、登壇資料ノウハウの 3 スキル化（数値基準＋PDF 書き出し時の自動検査つき）や、データサイエンスの手法別 diagnostics を 2 段ルーターで肥大化させず畳む設計へ延びた。「暗黙知を数値基準と自動検査を備えた再現可能なスキルにする」点で一貫する。

モデルの使い分けと経済性も背景として維持。Sonnet 5.5 は前世代比 30% 高速・30% 安価で知識労働・図表理解は GPT-6 Sol 超え、エージェント系は Opus 5.5 並み（ただし推論 Max はトークンを食う）。トークナイザ刷新でベンダー跨ぎのトークン数比較は目安にとどまる、という注意も拾っている。

## 質への関心: 量より検証 ― AI出力を「信頼可能」にする検証系

AI で量を増やすこと自体に価値を置かず、人間が判断・検証できる形まで質を高めることに価値を置く。この「量より検証」は中心の Jev 検証から基礎設計まで複数領域を貫く根で、今回はテスト・レビュー・評価・文章の矯正として厚く具体化した。

- **テスト**。「E2E かユニットか」の優劣論を退け、**どの不具合を検出できるか**で役割分担する整理が中心。速くて原因を示せるテスト（型・lint・ユニット・PBT）が AI の反復フィードバックを担い、最大の投資は「そもそも誤ったコードを書けなくする型設計」（値オブジェクト＋判別可能 union で網羅を有限化）に置く。テスト要求仕様（TRS）を設計書の前に挟めば受け入れ基準 81 本からテストケース 360 件を生成でき、人は「書く」から「レビュー」へ回る。「ユニットテスト不要論」への反論（エラー率と件数を区別せよ、テストは委譲の土台）もここ。
- **レビュー**。観点を機構で分ける。敵対的レビューの実測では確定した重大指摘の半数超が単一レーンだけの検出で、観点分離に意味がある（ただしコストは標準 code-review の約 9 倍、適用は行数でなく「何に触るか」で切り分け）。
- **評価そのものの不安定性**。LLM-as-a-Judge は同一入力 3 回で一貫性 50〜75%、生成側も同一プロンプト 9 回で成功率 0〜100% とブレる。違反検出（LLM）と達成検証（決定論的な正規表現）を分離し、入力を凍結して 9 回再生成し ±30 点超だけ本物とみなす、という設計へ。評価器の生スコア単独は改善検出に使えない、と実証された。
- **文章の矯正**。前回の「AI 臭さを抜く試行錯誤」が、yomiyasu という形で統語構造のレベルへ降りた。禁止語リストでなく言語学的病理（非生物主語＋身体性動詞、サ変名詞の過剰圧縮、架空の敵との否定対比）として捉え、160 本のコーパスで単純正規表現の誤検出 95.8% を lookaround で 0% に抑え、減点式 Linter を同梱する。「回答の前提を問う」プロンプト技法も、根拠を露出させて検証する同じ態度。

## 基礎を固める関心: 設計とデータを数字と型で持ち直す

古典的な設計原則を**AIの大量出力を評価する物差し**として拾う姿勢が続く。今回は数値と型での裏打ちが濃い。B+ツリーが速いのはアルゴリズムでなく「ノード 1 個をディスク I/O 単位（8kB ページ）に合わせて I/O 回数を減らす」形だから、を pgbench の実測（高さ 3 段・shared hit=2／read=2）で示す一本。型が振る舞いを持つかを C/C++/C#/Java/Go/Rust/TS 横断で比べ、拡張メソッド・レシーバー・トレイトは「実態は同じで用語が違うだけ」と単相化挙動まで整理する一本。ボトルネックを「期日に爆発する爆弾」でなく「じわじわ改修速度を落とす構造」とみなし、事業の到達状態からの逆算と最大流量グラフで捉え直す実務論。OIDC/SAML を認証・認可・SSO の混同まで解く初学者向け整理、「具体と抽象」の往復をAI時代の判断力として据える勉強会参加記も同じ棚。「設計を感覚から卒業させ、判断軸を共有可能な構造にする」系譜が続く。

## 開発を経営・組織で捉える関心: 速度から統制、そして業務設計へ

**AI-BPR（AI 前提での業務再設計）**として定着し、前回はコスト統制（ゲートウェイでの予算管理、トークン削減）へ降りた線。今回は要件定義の側へ移った。サービスデザイン発想の 5 ステップ（As-Is フロー可視化→課題抽出→AI を一選択肢として「代替／支援」に分ける→To-Be シナリオ→要件化）が、個別タスクの自動化でなく「業務全体をどう変えるか」を主眼に据える。非エンジニアが社内エンジニアと作った業務ツール（60 分→15 分）の当事者記録も、境界条件の明示と非機能要件の学びという同じ所に落ちる。データ接続では Microsoft Work IQ が、別途 RAG を建てず M365 へ**ユーザー委任アクセス（権限を継承したまま）**で届く設計を示した。作り手偏重から、業務とユーザーの側へ開いていく途上。

## 育ってきた関心: 「ユーザー」に AI エージェントを含めて設計し直す

前々回芽生え前回枝を伸ばした、設計対象としての"ユーザー"再定義（AI エージェントもインタフェースの利用者だ、アクセシビリティがそのままエージェント可読性になる）の関心。今回はこのテーマの新規保存がほぼ無く、いったん静かになっている。並走していた人間向け UX 工芸は、今回は「効果を示すためのベースライン設定」（変更前に測らないと後の数値を解釈できない。完了率 48%→67% の 19 ポイントは 48% があって初めて意味を持つ）という計測の習慣として現れた。測って示す、という点では上の検証系と地続き。

## 表現を「宣言」で書く関心: 何を書き、どう見せるかは機械に

前回はっきり出た「宣言と機構の分業」（可視化中間言語 Flint、自動レイアウト TALA、コードファースト 3D など）。今回は該当する新規保存が無く休止気味だが、Opus 5.5 のワンショットで 470 行の単一 HTML にピクセルアニメ（ボイド群泳・ベイヤーディザ・固定シード地形）を外部依存ゼロで作る検証が、「概念を渡して機構に描かせる」志向の生成側の延長として残った。

## いったん休止した関心: AIと社会を「データ・制度」で問うマクロ視点

雇用・規制・OSS の受け入れ規範といった制度・規範の側は、今回もほぼ拾えていない。前回は「認知負債」「AI に仕事を奪われない理由」という労働と理解の問いが周縁に現れたが、今回はそれも薄く、代わりに Disney+ の全プラン広告化（実質「広告なし」階層の消滅）という配信ビジネスの規約変更が外れ値として入った程度。制度の設計論としての深掘りは引き続き宿題。

## 周縁の関心

点在しつつ続く領域。フロントの技術選定（Next.js vs TanStack Start を 10 観点で実コード比較）、並列エージェント開発の実務課題（VS Code と Cursor の違いはモデル性能でなく「状態が分離されず他の変更で脱線する」ツール側の問題）、生成 AI 送信前の個人情報マスキング（正規表現の雛形と、完全な匿名化でなく境界防御という割り切り）、わざと AWS 障害を注入して復旧する個人ラボ（総額約 35 円）。毛色の違う外れ値を拾う雑食性は健在で、今回は特に**AI から離れた科学**（超新星カタログ Pantheon+ の再分析がダークエネルギーの根拠に異議）が久しぶりに顔を出した。画像モデル Qwen-Image-2.1、話者分離つきリアルタイム文字起こし Nemotron 3 Diarization、YouTube の新機能群もここ。

## まだ拾えていない視点

作り手偏重は、業務・ユーザー・コスト構造の側へかなり開いてきた。依然として薄いのは、実ユーザーの生の声（ユーザーインタビュー・行動データ）を一次で扱う視点と、前々から休止している**規制・ガバナンスの制度設計論**。加えて、Jev をはじめ能力の実演が増えるほど立つ「信頼・帰属・安全」をどう制度で担保するか（今回は Jev で詐欺が安価に大量化するという脅威モデルの指摘で気配だけ触れた）が、次に深掘りしたい空白として残る。
